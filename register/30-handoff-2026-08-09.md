## Conventions that will bite you if skipped (each bit someone this weekend)

- **`./gen.sh` after ANY new file** — a `-only-testing` run on a class the generated project
  doesn't know reports `TEST SUCCEEDED` with **zero tests executed**. Verify via the xcresult's
  test COUNT, never the exit code alone. (Bitten three times this weekend.)
- **Fix loops**: RED watched first, fix, flip via `register/scripts/flip-claim.py` citing the
  fix commit, claims restated, `27-generate-state.py` regenerated. `PENDING` placeholder hashes
  must be repointed — check `grep -rn PENDING register/` before merging.
- **No-ff merges to main**, so register-cited hashes survive.
- **START-HERE's generated block conflicts**: regenerate over the union
  (`27-generate-state.py`), never merge textually — and check the NARRATIVE half didn't get
  clobbered by `--theirs` (it did once; the sitting notes had to be restored by hand).
- **Peer sessions**: `ui-changes` works the PRIMARY clone (`~/src/Maugham`); this is the
  experiments clone. Never fetch their unpushed work into a branch that will be pushed — their
  merges are gated on Denver's smoke word. Notify them after any push that touches shared
  surfaces (they reconcile at their own commit boundaries).
- **Method findings for ruling sittings**: present the live example and the MECHANICS before
  the options; recommended option first; capture Denver's choice verbatim into `basis` — and
  recommendations are *usually but not always* accepted (P1 was the first decline; both P3/P4
  were answered with questions until the mechanics were on the table).
- **Cross-session xcodebuild contention is real**: a hung gate mid-suite with flat CPU is the
  starvation confounder — check `ps ax | grep xcodebuild` before blaming the branch, and
  prefer `./scripts/test.sh` (it queues on the machine lock).
