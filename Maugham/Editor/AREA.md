# Editor — area guide

The NSTextView-backed editing surface and the SwiftUI bridge that exposes it as a binding: text storage, tokenizing and styling, cursor and scroll management, smart typography, find-match and annotation navigation, focus dimming, image paste, wiki-link and checkbox hit-testing, screenplay Tab-cycling, the review render and the translation-review badges. It is the most fragile area in the codebase: every cursor race the project has had lived here. The one rule from CLAUDE.md: **the `EditorHost` binding is fragile (tripwires 2, 3, 6, 7).** The area also carries tripwires 1, 4, 5, 33 and 54. The narrative and history behind the rules below are in `docs/history/editor.md`.

## Rules

### The binding contract
```
EditorHost: Binding(get: { doc.displayText }, set: { doc.setFullText($0) })
   ↓
Document.setFullText: parse → diff → record paragraph changes → write displayText ONCE at end
   ↓
debounced burst flush → op log + autosave → eventual disk write → Document.lastDiskEcho updates inside the coordinated-write block
```
**If you change the shape here, every cursor race you've heard about returns.**
- **`displayText` is written exactly once per `setFullText` call**: that closes the binding-loop race (tripwire 6). `EditorIntegrationHarnessTests.test_endOfFileTyping_doesNotFireApplyExternalText` is the canonical assertion; extend it whenever you touch the binding shape.
- **No parallel observable state on `EditorHost`, and no parallel onChange that reads back into the binding**: the old `$documentText` triad drove three cursor races in 24 hours (tripwire 6, `EditorIntegrationHarnessTests`). A new external-text path needs a regression test asserting `applyExternalText` does not fire during normal typing (`EditorIntegrationHarness.assertNoApplyExternalText`, via `applyExternalTextCallCount`).
- **`EditorSurface.applyExternalText` is for cloud-conflict resolution only**, never typing or op-log re-renders. Its one production call is in `EditorSurface.swift`; a second is a binding race (tripwire 7, `TripwireGrepTests.test_applyExternalTextHasExactlyOneProductionCallSite`).
- **No heavy work inside a synchronous SwiftUI binding setter** (tripwire 3, `EditorIntegrationHarnessTests`). It caused a trailing-space autosave that moved the cursor, an async restore racing key events, and a binding loop reading stale text. Debounce, and isolate the write side from the read side.
- **No SwiftUI ↔ AppKit two-way sync guarded by flags**: `.onChange` fires after the synchronous flag-clear, so the guard leaks (tripwire 2, prose only).
- **The echo guard for our own writes lives on `Document`** (`lastDiskEcho: EchoState`). The editor never sees it, so don't add "last text" state in the editor layer.
- **The binding setter's side effects are part of the contract**: `recordEditorTextWrite` → `recordWordCount`/`recordSessionActivity` (`EditorBindingSideEffectsTests`).
- **`EditorCoordinator` records the cursor into `Document.recordCursorAt(_:)` on selection change**: `Document.setFullText` reads it as `preEditCursor` to align a cut-and-paste of anchored task lines between paragraphs.
- **No `NSTextStorage` subclass fronting several files** (tripwire 1, prose only): AppKit's layout, undo and selection caches cannot be steered from a subclass, and multi-file screenplay is dead.
- **The Fountain extension is spelled in `DocumentFormat` only; ask it, never a `"fountain"` literal** (tripwire 54, `TripwireGrepTests.test_theFountainExtensionIsSpelledInDocumentFormatOnly`).

### TextKit, caret and paste
- **The editor is pinned to TextKit 1**: `EditorSurface.makeNSView` touches `textView.layoutManager` once, which downgrades the view for good, so `MaughamTextView.drawInsertionPoint` can clamp the empty-line caret to glyph height (`CaretHeightTests`). **That `_ = textView.layoutManager` line looks unused; it is load-bearing — don't remove it.**
- **A surface with an `imagePasteHandler` owns pasteboard images**: `MaughamTextView.paste(_:)` never falls through to `super` for an image. `readablePasteboardTypes` advertises images, so `super` would insert an attachment character (`U+FFFC`) into the op log. A nil from the handler means *handled, nothing to insert here*, never *not mine* (`StatementImageIngestTests.test_pastingAPictureLeavesNoAttachmentCharacterBehind`, which catches the defect only with no statement created up front).

### Restyle, scroll and typewriter
- **A whole-document `setAttributes` snaps a long scrolled document toward the top**: it invalidates all layout, which AppKit re-lays out from the top. Each path below either avoids it (a local window) or re-asserts caret and scroll itself.
- **Don't add work inside `applyTypography`** on either path. It takes a `restyleWindow`, and window ≡ whole document is pinned by `WindowedTypographyEquivalenceTests`.
- **The typing path is mode-gated on `WritingMode.defersRestyleWhileTyping`.** Both branches restyle only the changed blank-line blocks found by a character diff (`TypingRestyleWindow.changedBlockWindow`), never a token diff: plain prose has no tokens, so a token window falls back to whole-document and snaps scroll. A local `setAttributes` does not move scroll, so AppKit's caret-following autoscroll is left alone.
  - Prose defers the repaint to the burst's trailing edge (`scheduleDeferredRestyle` → `performDeferredRestyle`, `restyleSettleDelayMs` = 300 ms), diffing against `burstBaselineText`, snapshotted in `shouldChangeTextIn`. Deferral is what stops emphasis flicker. The whole-document branch survives only as a no-baseline fallback.
  - Screenplay paints live and windowed on the keystroke (`paintLiveWindowed`, diffed against `liveRestyleBaseline`), because a styling lag on element-heavy text reads as sluggishness. The cursor restore in `textDidChange` covers its jostle.
  - **Don't re-introduce a per-keystroke origin restore, a whole-document settle or live paint, or a token diff** (`DeferredRestyleTests.test_settleRestyleIsWindowedNotWholeDocument`, `test_screenplayRestylesLiveWhileTyping`, `test_screenplayLiveRestyleIsWindowedNotWholeDocument`).
- **Non-typing callers paint whole-document and re-assert caret and scroll themselves** (attach, `applyExternalText`, theme, typography, focus): `applyExternalText` clamps, and attach defers a `scrollRangeToVisible`.
- **Typewriter mode needs half a viewport of headroom**: `refreshTypewriterInset` sets `textContainerInset.height` to half the clip height (24 when off) and re-runs on resize from `MaughamTextView.updateColumnInset`. `scrollSelectionToVerticalCenter` adds `textContainerInset.height` to the line's container-space `midY`; **don't drop that correction**. Centring runs per keystroke in `textDidChange` (a scroll, not a paint).
- **`applyFocusDim` is called from three paths intentionally** — selection change, focus change and an explicit theme update — and again after each restyle repaints over it. Don't dedupe the calls.
- **The prose tokenizer's budget is a scaling ratio, never a wall clock**: it runs over the whole document on every keystroke, so quadrupling a report-element corpus must stay under 8x the time (`TypingLatencyProbeTests.test_proseTokenizeOfAReportCorpusScalesLinearly`). A new pass must not compare every token with every other; the block-widening of the restyle window is capped.
- **The screenplay parser is one pass over `LineRecord`**, the seam a future incremental tokenizer re-derives from; don't inline it away. A grammar change updates both `FountainTokenizer` and the frozen `FountainTokenizerReference` oracle in MaughamCoreTests. `retokenizeAndStyle` parses once and threads the script to both tokens and typography, so no consumer re-parses.
- **Metrics come from the keystroke's own parse**: `EditorCoordinator.onMetricsChanged`, debounced with the script post.
- **The Mac editor renders screenplay text as typed.** Display-time uppercase was tried and rejected: rendering uppercase over lowercase source desynced the caret. `ScreenplayUppercase` (MaughamCore) is a display contract that only the phone reader consumes. If the Mac ever uppercases, it consumes that and solves cursor positioning first.
- **Task anchors are painted, never deleted from storage**: `Token.Kind.taskBody` paints the checkbox body distinctly, and `Token.Kind.invisibleAnchor` paints the `<!--t-XXXXXX-->` span `NSColor.clear`, so it stays in storage for `RenderFilter`'s round-trip. Both tokenizers emit them, and `ScreenplayMode` adds the invisible-anchor attributes after its full-storage `setAttributes`.

### Appearance, teardown and the control plane
- **An OS light/dark change is a direct per-view call, not a broadcast**: `MaughamTextView.viewDidChangeEffectiveAppearance` calls `coordinator?.effectiveAppearanceDidChange()`. That no-ops when the appearance name is unchanged since the last handled one (baseline seeded in `attach`). AppKit also fires it on first mount, so a broadcast restyled every live coordinator (`EditorAppearanceChangeTests`). The no-op guard lives there, not in `applyAppearance`, which theme and typography changes share.
- **`detach()` runs on every teardown and is idempotent** (`guard !isDetached`). It runs from `EditorSurface.dismantleNSView` on an in-window teardown, and from `MaughamTextView.viewWillMove(toWindow: nil)` on window close, where `dismantleNSView` never runs. It releases the text-view graph, cancels the async tasks, drops the observer tokens and clears the native undo stack before the text view goes (stale actions are the `⌘Z EXC_BAD_ACCESS` class). It also flips `isDetached`, so a coordinator SwiftUI has not yet released does no restyle work and `receiverContext` drops its deliveries. The guard exists because a piece flip fires both hooks.
- **The coordinator has no internal ARC cycle**: every back-reference (delegate, `textView`, overlay and gutter `coordinator`, observers, tasks) is weak or `[weak self]`. SwiftUI's scene retention after a window closes is neutralised by `detach()` and the `.onDisappear` scorch in `ProjectWindow`/`EditorHost` (`WindowTeardownScorchTests`).
- **Control state flows through `EditorControl`, observed with `withObservationTracking`** (ADR 0017). It does not ride `updateNSView`, which is text, frame, gutter and provider wiring only, and it gets no new notification.
  - D1: `EditorControl` holds only control state, never text- or cursor-derived values, or observation fires on the typing hot path.
  - **A version counter that moves at a settle edge, never per keystroke, may live here when its values stay behind a provider**: `referenceIndexVersion` says the cached `ReferenceIndex` changed, re-read through `referenceIndex`; `figureCardVersion` does the same for the figure cards (`figureCardModel`) and the figure-line checks (`figureLineStatus`). A repaint it drives stays in the visible range, on temporary attributes, or on the figure lines whose room moved, never a whole-document restyle.
  - D2: `applyControl` stays no-op-guarded per sub-area.
  - **`armControlObservation` runs `applyControl` outside the tracking closure, and the closure reads only `control.*` properties.** `applyControl` reads through `Document` and `UserPreferences` in review posture, and a tracked read re-fired the whole-document restyle in every review window. Keep the tracked set equal to the consumed set (`EditorControlBridgeTests.test_reviewObservation_ignoresSharedPreferencesMutation`, `test_reviewObservation_stillFiresOnControlPropertyChange`, via `applyControlCount`).
  - The ⌘⌥⇧R `maughamToggleReviewMode` observer is kept deliberately (Bug B): it flips the review membrane synchronously, where a `control.*` mirror would land a frame later.
- **A control flag that swaps which buffer the editor shows flips the membrane synchronously, before the buffer-swap decision.** `EditorSurface.reconcileTextBuffer` calls `coordinator.setTranslationReview(...)` first, then compares `textView.string` to decide a replace. A swap across a translation render always drops the native undo stack (ADR 0023's D1 corruption class; `EditorUndoStackClearTests`).
- **The script post is project-scoped** (ADR 0021): `postScriptDidUpdate` posts `.maughamScriptDidUpdate` to `.project(id: scriptOriginProjectId)`, and receivers adopt it through `.onProjectEvent` only when the id is their own. It is not a key-window guard: a background window's own re-parse must still reach its navigator. A nil origin skips only the post; the debounce bookkeeping stays unconditional (`ScriptUpdateScopingTests`). `scriptOriginProjectId` is wired by `EditorSurface` from `EditorHost` (`ProjectIdentifier.id(for: store.url)`).

### The membrane reads the posture
- **What the editor refuses is decided in `shouldChangeTextIn` alone**, by `EditorEditPolicy.allowsTextMutation`. The editor stays selectable, scrollable and copyable, and `isEditable` is never touched.
- **`lockEditing` has exactly two inputs**, composed once in `EditorControlMirror.membrane(posture:manualReview:shareIsReadOnly:)`:
  - the posture, `!posture.allows(.writeText)`, asked of the window's one door (`DocumentStore.posture(forDocId:)`). A reviewer, an author outside her own pieces, the root yielding on somebody else's piece until **Edit Anyway**, and `Posture.settling` all lock;
  - a read-only iCloud share, `ProjectWindow.shareIsReadOnly(_:)`, an OS-level lock that claims no role.
- **Neither input unlocks what the other locks, and the manual ⌘⌥⇧R (`isReviewMode`) flips the review render but never the lock.**
- **The lock and the `Document`'s own writes flip together**: a trust change bumps the door's epoch, and the `Document`'s stamp is re-stamped in the same main-actor turn (`DocumentStorePostureTests.test_theRestampAndTheBumpAreOneTurn`). The lock trails the change until the refresh lands. A burst typed in that window under a withdrawn permit is signed and set aside in her name, kept in History, not lost (ADR 0032).
- **The checkbox click writes text, so `MaughamTextView.mouseDown` asks `coordinator?.allowsCheckboxToggle` before `checkboxToggleHandler`.** No test may synthesise the click (tripwire 33), so `TripwireGrepTests.test_theEditorsCheckboxClickAsksTheMembraneFirst` reads the source.
- **The statement editor asks the same door** for `.editStatement` (`StatementEditorHost.locksEditing`). The line that says why the editor is locked is `Maugham/Views/PostureStandingLine.swift`. `PostureMembraneTests` (in `ReviewModeMembraneTests.swift`) and `PostureStandingLineTests` pin both directions.

### Two editors in one window
A statement pane in the right column holds a second `EditorSurface` while the manuscript editor holds the centre (`StatementEditorMountTests` hosts the pair in one window). Both fixes below hang off `EditorSurfaceConfiguration.isSecondEditorInItsWindow`, default false (census: `TripwireGrepTests.test_everyEditorSurfaceMountIsAccountedFor`, over `editorSurfaceMountSites`).
- **The window's `UndoManager` is shared, and `detach()` clears it**: `MaughamTextView.usesPrivateUndoManager`, set in `makeNSView` before anything registers, gives the second editor its own manager. Do NOT instead make `detach()`'s clear conditional: popping a native action after its text view has gone is the `⌘Z EXC_BAD_ACCESS` class.
- **Both coordinators answer the window's commands**: every observer `EditorCoordinator`'s `init` registers is key-window scoped through `receiverContext(.keyWindow)`, and `EditorCoordinator.respondsToWindowCommands` gates them at that one funnel. **Count the `MaughamEvent.observe` calls in that init rather than any sentence about them.**
- **A third surface asks the same question**: if it can be on screen at the same time as another editor, it is a second editor.

### Commands that write text
- **A command writes through `applyCommandEdit`** (Route A): one `replaceCharacters` behind the membrane, one ⌘Z step, typing undo kept. Never Route B (`setParagraph` wipes typing undo, ADR 0023 D1).
- **An insert acts on a manuscript only**: the Insert menu is disabled, and the membrane refuses on its own, where the centre is not the bare editor, the posture forbids writing text, the document is a screenplay, or review or translation review is on (`InsertMenuGate`, `InsertCommandTests`).
- **A table re-aligns (`TableText.formatted()`, through `applyCommandEdit`) only on Tab, Shift-Tab, Return or leaving it, never mid-keystroke** (Denver's ruling). The leave-tidy runs on the next runloop, never inside the selection callback, and an undo's selection change or an IME composition schedules none (`TableEditingTests`).
- **A command closes its own undo group outside an event** (`applyCommandEdit`, with `groupsByEvent` off for the bracket): a figure lands in a Task, a table tidy on the next runloop, and an implicit group left open would take the writer's next typing.
- **An edit that lands after its event lands `.deferred`** (`CommandLanding`): it never takes the focus, keeps a writer who has moved on where they are (selection shifted through the edit, no scroll), and waits out `hasMarkedText()` a bounded number of times, then gives up and says so (`FigureCommandTests`).
- **Nothing places an offset against `lastTokens` between a character edit and its retokenize**: AppKit posts a selection change inside `replaceCharacters`. `tokensDescribeAnEarlierText` marks the gap, the table anchors ride every storage edit (`TableTidyState.noteEdit`), and `textDidChange` re-reads the caret's table once the tokens are fresh (`TableEditingTests`).
- **Insert commands go to the focused editor**: with another text input focused (a statement, a research note, a field), the manuscript ignores them (`insertCommandContext`, `InsertCommandTests`).
- **A mixed drop (pictures and other files) and a paste carrying text keep today's behaviour on purpose**: a picture beside text is the text's rendering (Word, Pages), and half a drag is no answer (`FigureIngest.dropDecision`, `carriesText`).
- **A figure a command made whose line cannot be written goes to the Trash, and the writer is told** (Insert ▸ Table, R7b-6; `InsertCommandTests`). Convert writes over its table only if the table's text is exactly what it read, keeping its `tbl:` label (`ConvertTableCommandTests`).
- **A figure line's `![`, `](path)` and `{#…}` are painted faint** (`syntaxPunctuation` blended toward the background, never an alpha, so the focus dim cannot brighten it), and the caret's line is shown again by a layout-manager temporary `.foregroundColor` (`refreshFigureSyntaxUnfade`: no storage edit, no re-layout, no scroll; at most two lines). It is a second temporary foreground beside the translation dimming, so translation review shows none and its full-range clear stays exact (`CaptionBarTests`).
- **A figure line always keeps its own paragraph**: `shouldChangeTextIn` applies `FigureLineSeparation` (MaughamCore) last, making a gluing edit with the blank line inside it (one ⌘Z) or refusing a Backspace or Delete over the one blank line; prose only, never in a command's edit, an undo or redo, or a composition. A line that arrives glued gets `ManuscriptChecks`' warning (`FigureLineParagraphTests`).
- **The Figure… panel runs from the coordinator**, an exception to the window-command recipe: its result must land at this editor's remembered caret.
- **A figure drop or paste never reaches `super`** (`MaughamTextView.performDragOperation`, `paste`): `super` would write the file's path or a `U+FFFC` into the op log. The membrane is asked before anything is copied; the line lands after the async copy at the point carried through any typing (`FigureIngest.Anchor`), never in a document the editor has left (`FigureCommandTests`).
- **Only `EditorHost` sets `answersInsertCommands`**: a research note answers window commands and shares `ProseMode`, so without it the note takes a table (`InsertCommandTests`). The menu's enabled state is `InsertMenuGate` (`Maugham/Views/EditorControlMirror.swift`).

### Overlays and in-editor UI
- **No `NSPopover` for in-editor UI or autocomplete** (tripwire 5, prose only): sizing is unreliable, it blocks input and it fights text-view focus. Use inline ghost text, a sheet, a plain `NSView` overlay or a pane.
- **The completion list is the one in-editor picker** (`CompletionListView`, a scroll-view subview above every overlay). Its keys come first in `doCommandBy`, before the table arms, only while it is open; `complete:` is swallowed in prose. It opens only on a typed character (recorded in `shouldChangeTextIn`: one character, never in `applyCommandEdit`, a paste or drop, an undo or a composition) on a manuscript surface outside code, closed or still being typed, accepts through `applyCommandEdit`, and closes on scroll, resize, focus loss, the caret leaving the trigger, `applyExternalText`, a refusing membrane, Esc and detach (`CompletionListTests`). A new picker is a `CompletionSource` (its `CompletionTrigger` may run past the caret through a key), never a second list.
- **Overlays and gutters draw only the visible range, from cached data** (tripwire 4). The coordinator resolves each `Annotation` to UTF-16 (`ResolvedReviewMark`) in `recomputeReviewMarks()` on an annotation-set change (pushed one-way from `EditorHost` off `Document.annotationsVersion`) or a text change, never per draw. Overlays self-observe scroll and text through `NotificationCenter` and are re-framed from `MaughamTextView.updateColumnInset`; the review overlays show only when `coordinator.isReviewMode`.
- **A figure's thumbnail is a decoration, never an attachment** (tripwires 1, 26). Its room is the figure line's `paragraphSpacing` (`ProseMode.reservesFigureThumbnails`, set only by `EditorHost` with the resolver), put on the whole line by both paints through one function of the written path and line start, `figureRoom(forLinePath:at:)` (`WindowedTypographyEquivalenceTests`): a table figure's card height from the window's `FigureCardCache` (`FigureCardMetrics.room`, the one place card metrics come from typography), today's fixed height for an image, a labelled card or a cache miss. It reads memory only, never the disk or the op log; a fill lands as `EditorControl.figureCardVersion`. Decodes run off the main thread through ImageIO thumbnailing, cached by resolved path and modification date; a landed decode repaints only the overlay. A figure on the last line gets its room from `MaughamTextView`'s height instead (TextKit 1 lays out no spacing after a final unterminated paragraph).
- **Nothing here makes a figure card a character**: `TripwireGrepTests.test_theEditorsFigureCardsAreDecorationsNeverAttachments` keeps `NSTextAttachment` and `U+FFFC` out of this folder and adds to `paragraphSpacing` only in `ProseMode.figureLineStyle`.
- **A card version re-lays out only the figure lines whose room moved** (`refreshFigureRooms`: one `addAttribute` of `.paragraphStyle` per line), after the settle paint when a burst is in flight (`FigureRoomRefreshTests`).
- **An expanded grid's room is keyed by its figure line's start, not the path** (R7c-4), and the grid is the one hit-taking subview in a card's room: every other overlay is click-through. The start rides every storage edit; a whole-buffer replace is followed by a line diff, so a relabelled line keeps the grid and a removed one folds it, never hopping lines. Expand and fold re-lay out that paragraph only, and the grid is re-framed after every paint or room change. Insert ▸ Table expands only for a writer who has not moved on; a deferred landing stays a card (`FigureGridExpandTests`). No key sent to the grid or its panel passes up to the text it sits in: one the grid has no meaning for beeps, never `super.keyDown` (`FigureGridFinalWaveTests`).
- **The text taking the focus folds an expanded grid**: `MaughamTextView.becomeFirstResponder` (so every `makeFirstResponder(textView)`), a click in the text, a navigation (a task, scene or annotation jump, a find match, a caret moved off the line), detach and window close, which fold first. The open edit is committed (Esc discards it) and the caller's selection kept; Esc and Done put the caret at the end of the line. A formula that will not read keeps the grid only against a click or focus in the text, which is refused for one turn (keys in that turn go to the window); where the grid cannot stay (a navigation, the line gone, a teardown) a notice carries the typed text (R7c-8, `FigureGridFocusTests`).
- **The grid asks `FigureGridGate`, fed by the figure's drawn posture (`.allows(.editFigure)`), never the text's lock** (R7c-5, R7c-6): translation review never expands; parked, a closed host, a refusing posture, a read-only share or the window's explicit review mode (never the review the text's posture forces) open read-only (select and scroll; bars disabled; typing answered with the reason line). The caption follows the text's membrane on its own. It is asked again at expand, at mount, whenever the figure's drawn posture changes (card or no card), at each `figureCardVersion` edge, on a mode flip and after a write the host refused (`FigureGridReadOnlyTests`).
- **An expanded grid has its own undo stack; the fold collapses the visit into one window step**. Grid writes register on `gridUndo`, and the grid view and panel answer `undo:`/`redo:` (titled there), so ⌘Z never reaches the window's stack. Open typing is cancelled (R7d-4); read-only refuses (R7d-11). `closeFigureGrid` registers the step at once, so text typed after it sits above; a teardown or a send to Research registers none (`FigureGridUndoTests`).
- **Format ▸ Table posts `maughamFigureTableCommand` to the key window; the coordinator hands it to the expanded grid's controller, which asks its menu state first** (R7c-10). The coordinator alone sets `FigureGridPresence`, at expand, fold and a change of what the commands may do; while a grid is expanded the Insert menu is disabled. ⌘⌥↑↓←→ are the menu items' alone (`FigureGridMenuTests`).
- **A trailing figure's room is asked of the text** (`FigureThumbnailLayout.trailingFigurePath`, its room the line's own), never the marks: AppKit resizes mid-edit, before the retokenize. The frame is re-asserted after every retokenize, since `sizeToFit` skips an unchanged size. The decode cache key carries the column's pixel bucket, so a wider column decodes again.
- **Project-wide references come from one cached index, never a walk** (`ReferenceIndex`, cached by `ReferenceIndexHost`) over `ProjectStoreASTSource.publishablePieces(in:)`: the closed pieces' op-log tokens (one `.maugham/ops` listing per rebuild) and the parse run off the main thread, only a moved piece's derive on it; before the first build a label-minting command walks instead; rebuilt on a research, binder or op-log change and on the open document's metrics edge, never per keystroke. The coordinator reads it through `referenceIndex` and repaints on `EditorControl.referenceIndexVersion`. Its figure and table numbers are the default book's (`ReferenceIndexTests`).
- **Labels and problem underlines are display-only, on a manuscript only** (`showsReferenceMarks`): the label overlay never changes layout, repaints on an edit or scroll only with a marker or figure line, and on a caret move only entering or leaving a waiting label; the checks run at the settle, a whole-document paint or a new version (D1), never per keystroke (`ReferenceLabelOverlayTests`). Underlines are temporaries on `.underlineStyle` and `.underlineColor` only, never `.foregroundColor` (the dimming's and the un-fade's); severity and words are publishing's (`PublishProblem`).
- **No uncached per-row computation in SwiftUI list rows that show editor-adjacent metadata** (tripwire 4, prose only): per-row Fountain re-parses made a binder click O(N²). Cache, or read the script the coordinator already parsed.
- **The Translator's note is a window command, not an editor write**: ⌘⌥C and the toolbar's fourth button post `.maughamTranslatorsNote`. `ProjectWindow` reads the paragraph (`Document.paragraphId(at:)`) and opens `TranslatorsNoteSheet` (`Maugham/Views/TranslatorsNote.swift`), which writes a directive through `RulingPerformer.rule`. The editor knows nothing about statements (`TranslatorsNoteTests`).

## Recipes

### Add a control-plane input
1. `EditorControl.swift` — add the property. It must be control state, never derived from text or the cursor (D1).
2. `EditorCoordinator.swift` — read it in `armControlObservation`'s tracking closure, and apply it in `applyControl` behind a no-op guard (D2). The two lists stay equal.
3. Write it one-way from every host that owns an `EditorControl` (`grep 'EditorControl()' Maugham/Views`): `Maugham/Views/EditorControlMirror.swift` (`EditorControlMirrorModifier`, which `ProjectWindow` applies), `Maugham/Views/ResearchNoteEditor.swift` and `Maugham/Views/StatementEditorHost.swift`. Decide per host whether it applies. The coordinator never writes back.
4. If it changes which buffer is shown, flip the membrane before the buffer decision in `EditorSurface.reconcileTextBuffer`.
5. Tests: `EditorControlBridgeTests` (a property change re-applies; an unrelated `UserPreferences` mutation does not).

### Add a window command the editor answers
1. Name the event in `Maugham/Models/MaughamNotifications.swift`, and post it through `MaughamEvent` with a declared scope (tripwire 21), usually `.keyWindow` from `Maugham/MaughamApp.swift`.
2. `EditorCoordinator.swift` — observe it in `init` with `context: { [weak self] in self?.receiverContext(.keyWindow) }` and hold the token in a property, so the second-editor gate covers it.
3. Add the token to `detach()`'s removal list.
4. If the command opens UI, the window handles it (`Maugham/Views/ProjectWindow.swift`); the editor posts or moves the caret and owns nothing else.

### Mount another `EditorSurface`
1. Decide whether it can be on screen beside another editor; if so, set `isSecondEditorInItsWindow: true` in its `EditorSurfaceConfiguration`.
2. Add its file to `TripwireGrepTests.editorSurfaceMountSites`, saying which it is.
3. Bind it with a single `Binding(get:set:)` onto its owning model's text that writes once per set, the shape in *The binding contract*; don't mount `EditorHost`, which is the manuscript editor's.
4. Test the pair in one window, as `StatementEditorMountTests` does.
