# OpLog — area guide

The manuscript op log, Mac side: the `Document` that appends paragraph-level ops to a per-device, chained, sealed JSONL stream under `.maugham/ops/`; the derivation of text and order from it; the clean `.md` render; checkpoints, rewind and partial restore; the cross-Mac merge; task anchors; and the load seam where the signed op log's register, permits and posture meet the editor. The one rule from CLAUDE.md: **the op log is the source of truth, and every manuscript load goes through `Document.load`.** The storage, chain, trust and permit layers live in MaughamCore; this guide owns their rules because this area is where they bind. The area carries tripwires 17, 20, 23, 24, 35–53 and 56. The why behind every rule below, and the history of each, is in `docs/history/oplog.md`.

## Map

## Rules

### Source of truth and the clean render
- **The op log is the source of truth; the `.md`/`.fountain` on disk is a clean derived render** with no `¶id`/`t-` anchors (ADR 0019). Anchors live only in the op log and memory. Walk by `sequence`, never raw `paragraphs`. Never introduce state that lives only in the `.md`. Claude reads through MCP and the op log (ADR 0018).
- **No manuscript file read as truth** (tripwire 20): open document → the live `Document`; closed → `DerivedManuscript` (`DerivedManuscriptCache` in hot loops). The only raw reads here are in `Document+Load.swift`, and none is truth: the import-bootstrap mint read, the echo seed (`EchoState.initialLoad`), the divergence-snapshot reference. Every file read in production carries `// adr-0018-ok: <reason>` (`TripwireGrepTests.test_noManuscriptFileReadsOutsideReconciler`, phone twin in `TripwirePhoneGrepTest`).
- **External `.md` edits are discarded, never ingested**; there is no reconciler. `Document.handleExternalDiskChange` (live) and the `Document.load` divergence check (edited while closed) snapshot the outside bytes under `.maugham/conflicts/` (kinds `discarded`, `diverged`) and re-materialise the op-log truth. The load compares `stripAnchors` display forms and dedupes against the newest backup. Sync flows through the op-log merge (ADR 0012).
- **Conflict backups** (`Document+ExternalChange.swift`) root via `resolveProjectURL` (a Collection piece's land under the project root), are named `<stem>-<docId>-<kind>-<stamp>.<ext>` so same-stem pieces never cross-prune, and keep the newest 20 per docId.
- **Ping-pong damping counts EVERY discard per session, a byte-identical repeat included**, and after `Document.discardDampThreshold` (3) stops auto-rewriting (still snapshotting) until a local edit re-arms it. Do not go back to counting distinct bytes, and do not skip the rewrite for a repeat (`ExternalDiscardDampingTests`).
- **Every manuscript load goes through `Document.load`**, which runs `Bootstrap.run` to mint the `¶id` anchors the op log joins on; never construct a `Document` any other way (`BootstrapWiringTests`). In a narrowed book the load mints only where `LocalWritePermit.mayMintOpening` says, and otherwise refuses with `DocumentLoadError.waitingForPiece` (see The load seam).
- **The load contract is op-log-domain**: the bootstrap signal is op-log emptiness (`!logExists`), never the `.md`'s anchors; content and order come from `Deriver.deriveWithSequenceFallback`; `reconcile(derived:)` only drops orphans (a paragraph in the map but not in `sequence`).
- **The derived `.md` follows the op log's own changes**: `handleExternalLogChange` schedules the ordinary autosave past its echo guard, and the load schedules one when the disk diverged. Neither is a second writer: `performAutosave`'s guards (closed, husked, `rendersToDisk`) decide.
- **A document holding lines renders nothing on its own account** (`Document.rendersOnItsOwnAccount`, `provenance.hasPendingHistory != true`), at load or re-read; a keystroke still writes, and the admission or *Theirs* that lets them in re-reads and renders (`DerivedRenderFollowsReReadTests`).
- **The op log is append-only**: no mutation, no deletion. Checkpoints capture state and never truncate; sealing a segment changes storage layout, never the logical log.
- **`Bootstrap.run` is idempotent**, and its id minting is not to be changed casually: new ids in an existing document orphan every prior op record.
- **Paragraph ids are four characters from `0123456789abcdefghjkmnpqrstvwxyz`**; task anchors six, as `<!--t-XXXXXX-->` only. In-memory APIs accept any string, so a test that crosses the `.md` boundary (Bootstrap, `RenderFilter` against parsed comments) must use alphabet ids or `ParagraphID.mint()`/`TaskAnchorID.mint()`, or it silently tests half the round trip (tripwire 8). Production mints with `mintUnique(excluding:)` (tripwire 23). Censuses: `TripwireGrepTests.test_paragraphIdLiteralsInTestsUseValidAlphabet`, `TripwireGrepTests.test_noBareParagraphIDMintInProduction`.

### Merge / derive resolution contract
- **Two devices with identical logs derive identical text, whatever the load order.** `OpLogStore.mergeSortedDedup` sorts on the total order `(opId, canonicalEncoding)` and keeps the first per opId, so directory enumeration order cannot change the survivor; `load` and `loadSyncMerged` both use it.
- **`Deriver.derive` and `deriveWithSequenceFallback` sort by the same order themselves**; no "caller must sort" precondition. `derive(ops:upTo:)` is the exception and must NOT re-sort: a cursor state is a timeline prefix.
- **A same-opId pair with divergent payloads is a corruption signal.** The merge picks a deterministic survivor; surfacing it needs a `projectURL` the pure function lacks, so don't entangle the two.
- **`Op.at` is display-only.** Resolution is by opId; never put a wall-clock comparison in merge or derive.
- **`sequence: nil` on a typing burst means "ordering unchanged"**: `flushBurstNow` attaches `sequence` only when ordering changed, at the keyframe floor (`Document.sequenceKeyframeInterval`, 50) or on the first burst after load, and the deriver carries the last explicit one forward (`SequenceKeyframingTests`).
- **First bootstrap wins**: the Deriver honours only the first `.bootstrap` op's sequence (ULID order) and keeps a later one's changes, so an iCloud partial-sync re-mint is inert once the real log merges.
- Accepted limits, stated: a clock-lagged re-mint can sort first; same-paragraph concurrent edits resolve by sequence LWW with no conflict surfacing (single editor by ethos; `CrossDeviceIntegrationTests` case 4 is `XCTSkip`-marked).

### Typing, the pending file and close
- **Don't bypass `PendingBuffer`**. The pending file carries the live `sequence`, so crash recovery is op-log-domain.
- **A sequence-only burst is gated on `_orderingChangedSinceLoad`, never `_orderingDirty`** (which starts true): otherwise every transient load (MCP read, search, rename sweep) appends a junk op whose sequence can revert a peer's delete.
- **A clean `close()` leaves no pending file; a failed flush keeps it** (it is the recovery source). Quit never runs `close()`, so a quit leaves a basis-stamped file by design. On load an empty-changes pending file folds only when its `sequence` differs from the derived one AND its `basis` is the log's newest opId.
- **`close()` husks the instance only after flush, trailing autosave, `pending.clear` and seal.** `isClosed` is set first and gates every mutation entry (`setFullText`, `setParagraph`, `insert`, `delete`, `reorder` → no-op and log); `performAutosave` bails (data-safety-critical); `handleExternal*` bail. A `Document` is abandoned after `close()` (`DocumentDoubleCloseTests`).
- **The echo guard is `Document.lastDiskEcho: EchoState`**; don't add a parallel "last text" string, and build it only through its factories (ADR 0010).
- **The orphan sweep is gated on `_pendingSweep: SweepReason?`** (never a bool) and archives only annotations on `reason.removed`, never "anything missing from sequence". It reports through `_sweptSinceLastReport`, spent as one sentence at the burst boundary.
- **The read-only recovery door writes nothing** — no op, checkpoint, seal or quarantine record. `Document.load(recovery: .readOnlyPartial)` is reached only after the strict load refused; `DocumentRecoveryError` is its own refusal. Every `Document*.swift` function reaching `opStore.append(`/`pending.recordChange(` consults the writability choke point (`rejectMutationIfNotWritable`/`requireWritable` or their recovery siblings) first (`ReadOnlyRecoveryTests.test_everyOpLogWriterConsultsTheWritabilityChokePoint`). Such a `Document` is never handed to `documentStore.register` (`ReadOnlyRecoveryTests.test_editorHostRefusalWiring_census`).
- **Quarantine-and-continue** (`OpLogQuarantine`, tripwire 14's typed mover for this case): the `QuarantineRecord` sidecar is written FIRST, the bytes are moved byte-identically and never opened, a dataless stub is refused (`QuarantineError.datalessStub`). `attemptReturn` reads strictly, loads the current log first, never overwrites an existing destination, and treats `.returned` as terminal. `RecoveredHistory.report`'s `mergeHappened` is the caller's fact, not a guess; a sweep says one thing through `RecoveredHistoryReport.aggregate`, and nothing at a surface hand-builds a report (`RecoveredHistoryTests`, `HistoryPaneQuarantineNoticeTests`).

### Checkpoints
- **Checkpoints restore partially** — this document, not everything.
- **A checkpoint never carries a non-document where a document goes.** `CheckpointCapture.documentSubject(of:in:)` is the one answer to "is this a manuscript document?"; its `nil` means no `.checkpoint` breadcrumb, no label parenthetical, no `activeDoc`, no `PartialRestorePicker` seed. The label and the record are one decision (`CheckpointSubjectRecordTests.test_theLabelAndTheRecordCannotDisagree`). A recorded `activeDoc` is re-checked on read and always written (`""` for nil) for older builds. A figure stream gets a pointer, never a breadcrumb.
- **Don't collapse `OpLogStore`/`CheckpointStore` into bare `JSONLAppendStore<T>` calls**: the wrappers keep the hot-path and cold-path concurrency profiles explicit. New shared persistence semantics go into `JSONLAppendStore`. Both partition per device (tripwire 17); checkpoints are not chained. Tripwire 17's census: `OpLogStoreSegmentTests.test_legacyFile_neverSealed`.
- A checkpoint the subject's posture forbids throws `CheckpointRefusal` before writing; ⌘S swallows exactly that and still flashes.

### Task anchors
- **Anchors are for any manuscript-derived item whose lifecycle must survive restructuring** (ADR 0011); tasks are the second instance after paragraphs.
- **`Document.rebuildTasksCache` injects `TaskDeriver.derive`'s `mintedAnchors` into `paragraphs`** so autosave writes them back; re-entrancy is guarded by `_isRebuildingTasks`.
- **`Document.archiveTask(id:)` does two things**: appends `.taskArchive` and splices the manuscript text. Deleting a task line by hand auto-archives from `setFullText`'s alignment; `setFullText`'s optional `preEditCursor`/`postEditCursor` drive the cross-paragraph pass, and nil keeps per-paragraph alignment.

### The writer-facing channels
- **The Document's one writer-facing channel** is `Document.notifyWriter(_:)`, which posts a project-scoped `.maughamDocumentNotice` that `RewindModifier` renders. Its occasions are the rewind undo's drift decline, the annotation undos' declines and the sweep's summary — count the call sites, not this list. Post through `MaughamEvent.postNotice`, never by hand (tripwire 21).
- **The coalescing rule: the toast slot holds ONE sentence, so anything that can happen N times per writer action arrives as one sentence carrying N.** Annotation undos go through `Document.declineUndo(_:)`, never `notifyWriter` directly; it counts per `UndoDecline` verb and speaks a main-actor hop after the batch. A verb's singular and plural sentences sit on adjacent lines in `UndoDecline` (`DocumentNoticeTests`).
- **The second channel, `announceAnnotationsChanged()`**, posts `.maughamAnnotationsChanged` for surfaces that cannot hold the document. It is called from the append sites, never from `invalidateAnnotationsCache` (the burst flush calls that, and every receiver walks the project), and from `handleExternalLogChange` only when foreign annotation ops arrived (`AnnotationChangeEventTests.test_everyAppendSiteInTheFileAnnounces`).

### Op kinds and synthesis
- **`OpKind` is closed and its switches carry no `default:`**; adding a case is a schema decision (bump `ProjectManifest.currentSchemaVersion`, per the type's SCHEMA CONTRACT note). See the recipe.
- **`SynthesisSource` is a typed enum: read the enum, not a list in prose** (tripwire 12). Adding a case bumps `ProjectManifest.currentSchemaVersion`.
- **A reject that beat a spliced accept is repaired by a `claudeReject` carrying the inverse**, which is why `Deriver.appliesToManuscript` admits `.claudeReject` (`AnnotationConvergenceTests`; `formal/AnnotationRace.tla`).

### Chain, identity and seals
- **Verification never refuses to open a book.** A load classifies every line and applies what it can account for; provenance, never a lock.
- **`JSONLAppendStore` is chained when it holds a `ChainPolicy` and plain when it does not**: the op log and inbox pass one; publications and checkpoints do not. Project-scope task ops are `Op`s appended through `OpLogStore` into `__project__.jsonl`, so they are chained.
- **The chain's `prev` is inserted textually as the first key** by `OpLogChain.chainedLine(elementJSON:prev:)`, never a field on `Op` or `InboxEntry`. The line hash is SHA-256 of the bytes without the newline; `OpLogChain.genesis` is accepted only where nothing precedes it; legacy (no `prev`) is a prefix, never a suffix.
- **A seal line is recognised in `OpLogChain` only**: `isSealLine` is the one door and `JSONLAppendStore.parse` its one caller, so a seal never reaches an element decoder (tripwire 37). Census: `TripwireGrepTests.test_sealLinesAreRecognisedInOpLogChainOnly`.
- **Identity is the key's fingerprint, never the host name, and no device id is built by hand** (tripwire 35): `DeviceIdentity.author.deviceId`, or `LocalIdentities.current[<actor>].deviceId`. A slug comes only from `DeviceSlug.make(from:)`, and filename builders take a `DeviceSlug` (tripwire 24). Censuses: `TripwireGrepTests.test_noHostnameIdentity`, `test_noHandBuiltDeviceIdOutsideDeviceIdentity` (phone twins in `TripwirePhoneGrepTest`); tripwire 24 is the compiler plus `OpLogFilenameContractTests` and `OpLogStoreSegmentTests`.
- **No software private key in production** (tripwire 36): the device key is the enclave's, persisted as a blob that is useless off the machine. The exceptions are `DeviceIdentity+Testing.swift` and `PersonKey.swift`, by name in `TripwireGrepTests.softwarePrivateKeyAllowed`. Census: `TripwireGrepTests.test_noSoftwarePrivateKeyInProduction`.
- **Naming an actor is the writer's act, so it mints that actor's key; enumerating never mints.** `LocalIdentities.current` is computed lazily over `DeviceIdentity.identity(for:)`; `fingerprints` and `existingActors` only enumerate. `identity(forDeviceId:)` matches the whole id. The phone is the author alone and reaches `DeviceIdentity.author` directly. The device key never uses the keychain.
- **Unsigned is a state, not a failure**: with no enclave the device writes chained lines nothing seals and reports nothing wrong. A pre-signing file (host-name slug, `phone:<uuid>`) is another device's: read as unsigned history, never appended to, never sealed.
- **The remembered head is written BEFORE the line**, and the whole chained append (read tail, verify, set aside, rewrite, chain, remember, write) runs inside ONE coordinated write, never a nested one.
- **`OpLogChain.resolveAbsentHead` is the one decider of what a missing head means**, for `classifyTail`, the chained append and the verified read. It adopts only on the crash window; anything else quarantines after the last trusted seal. A keyless device's file is left as walked.
- **The state file (op-log-state.json) belongs to one identity** and starts empty under another; heads are keyed by project-root path, so a moved project forgets (the safe direction).
- **A device chains only its own files, and it has four writers.** `OpLogStore.append` asks `LocalIdentities.identity(forDeviceId:)` which actor wrote the op — matched on the whole id, never a prefix — and signs with that actor's key; an id naming no local actor takes the plain append. Reads judge by all four local fingerprints.
- **An annotation op's actor follows its author's source kind**: `Document.addAnnotation` stamps `deviceFor(author:)`, so a non-human author's note is the assistant's even through the writer's open document (`ActorLoadTests.test_anAIAuthoredNoteIsTheAssistantsEvenThroughTheWritersOwnDocument`). `session` is not redirected; human-authored creation and every disposition keep the Document's own device.
- **Sealing is decided by counters and the Document's actor, never by a scan.** `sealChain(docId:)` seals what this store appended since the last seal (`linesSinceSeal`); the open sweep uses `sealChain(docId:actor:)` for the author alone. The cadence is a set of call sites: every `OpLogStore.chainSealInterval` (100) appends, after every burst that appended, at `close()`, and at project open. `__project__` appends through `ProjectStore._projectOpLogStore`, the one store for its lifetime. The inbox and phone call `appendSeal()` after every append. Every seal is best-effort and logged, never a reason to lose a landed burst.
- **At close and open the chain seal runs BEFORE `sealTailIfNeeded`**, so a rotated segment ends on a seal (`SegmentSealTriggerTests.test_close_sealsTheChainBeforeRotatingTheTail`).
- **Rotation is the Document's own actor at close, and every local actor at open.** `close()` rotates only the actor it was loaded as (rotation deletes the tail, and MCP Documents load as the assistant); the open sweep rotates every local actor's oversized tail before the first load, and `__project__` last. Never the legacy unsuffixed file, never another device's (tripwire 17, `OpLogStoreSegmentTests.test_legacyFile_neverSealed`). The segment's signer follows the slug..
- **A torn last line is `tornTail`**, excluded, never quarantined, and reported in `diagnostics.skipped`; an incomplete line with something after it breaks the chain.
- **Quarantine is a `.lines` record that never returns**: `OpLogQuarantine.setAsideLines`, content-deduped, `attemptReturn` answers `.setAsideByProvenance`. The reason is derived (`JSONLAppendStore.quarantineReason`), never chosen by a caller.
- **Every reader classifies before it applies** through `OpLogClassifier.classify`. Only the coordinated reader writes (set-aside record, adopted head, segment digest), each best-effort. **A check reports; the load records**: `ProjectIntegrity.check` classifies keylessly and writes nothing, and a clean check is never a statement about what the load applies.
- **`Bootstrap.run` takes the load's store**, and `Document.makeLoadOpStore` is the one construction, with `localIdentitiesForTesting` (all four writers) and `deviceStateForTesting` as its seam. CI's runner is genuinely unsigned, so a seal assertion injects a signer.
- **An `async` function in the `OpLogStore` split's six files says `@MainActor`**: isolation does not move with the text (tripwire 56, `OpLogClassifierIsolationTests`).
- **No `static let|var <name>IsAvailable = true|false` gate left in production**: a constant-true gate feeding `.disabled(!…)` is dead code dressed as live (`TripwireGrepTests.test_noAvailabilityFlagIsLeftStandingInProduction`).

### What the writer is told about history
- **`HistoryPane` says only what the writer can act on knowing**: `unsignedHistoryNotice` (one sentence for both legacy and foreign-signed history) and `setAsideChangesNotice`, neither with a Retry. **"Another device" never means this Mac's assistant, translator or Maugham.** `unsealed` lines are never mentioned.
- **Set-aside counts are CHANGES, through `OpLogQuarantine.setAsideChanges` for both panes**: op lines only (a seal is counted nowhere), deduped by the line's identity, minus what the stream already applies. Both group by reason (`HistoryPane.setAsideChangesByReason`, one enumeration; `InboxPane.setAsideNotice(byReason:)`) in `JSONLAppendStore.quarantineReason`'s words, composed by the one `SetAsideDoor.notice`, so the two panes cannot describe one event differently.
- **The sentence is acknowledged per device per record**: both panes ask `SetAsideAcknowledgement.unacknowledged` and neither restates the filter (census in `SetAsideAcknowledgementTests`). Nothing under `.maugham/conflicts/` is touched; `SetAsideRecordsDisclosure` lists every record, declares its own ideal width and truncates rows in the middle.
- **History's held line has the pane's one control**: `HistoryPane.pendingNotice`'s **Admit…** posts a forced `.maughamAdmissionRequested` (the sheet is the window's, not the column's); `joinedChainNotice` states the chain this Mac is on, absent when it is its own root.
- **Held counts that carry a noun read `OpLogProvenance.pendingOpLines`** (`pendingByDevice`'s total), so History and the admission sheet show one number; line tallies (`pendingLines`) count seals and are not for sentences. A held span that is only a seal draws nothing.
- **The production load door names an actor**: `Document.load(url:actor:session:presenter:)` takes a `DeviceActor` — `.author` for the editor and the writer's automations, `.assistant` for MCP, `.translator` for the pipeline and `write_translation`, `.maugham` for the task rebalance (`TaskDeriver.rebalanceSentinel` survives only as a session marker). If a sentinel returns, the list is a grep and never a sentence. The `device: String` overloads are internal and test-only (tripwire 38, `TripwireGrepTests.test_noDeviceStringAtAProductionDocumentLoad`).

### The register and trust
- **Nothing here refuses to open a manuscript, and the writer's own words are never what is held.** A device record names its own author actor (`actors["author"] == device`); under labels-only a person is a device's author key.
- **`RegistryWriter` is the one door that signs and writes records, and the one place their directories are spelled** (tripwire 40). It refuses a wrong signer and an unsigned device before creating anything. `writeUnchecked` is internal and exists for tests; `RegistryWriter+Restore.swift` writes already-signed bytes and forms no opinion. Census: `TripwireGrepTests.test_registryRecordsAreWrittenThroughRegistryWriterOnly`.
- **The registry's writers are three files**: `RegistryPresence.swift`, `RegistryAdmission.swift`, `RegistryCache.swift` (restore alone); the phone writes none (tripwire 41). The authority rules live in those files, not in `write`. Census: `TripwireGrepTests.test_theRegistrysWritersAreThreeFiles`; phone: `TripwirePhoneGrepTest.test_thePhoneWritesNoRegistryRecord`. `RegistryAdmission.changePermit` is the only writer of permit events.
- **`RegistryCanonical` alone decides what a signature covers, and it takes the FILE's bytes** (tripwire 42): parse, remove `"sig"`, re-serialise `.sortedKeys` + `.withoutEscapingSlashes`, never a re-encode of a decoded record (`JSONDecoder` drops unknown keys). A re-sign edits the file's object (`RegistryCanonical.resigned`) and refuses to move `fingerprint` or the signer. The escaping is frozen (`RegistryCanonicalCensusTests`).
- **`RegistryReader.load` verifies filename, signature, signer and author actor; read `MalformedRecord.Reason`.** People are read in two passes (roots first). Malformed is listed, never read; a present-but-unreadable record throws (`ReadError.unreadableFile(kind: .registry)`, RULING-54).
- **The cache restores only refs with no file, and the folder wins under the same key only**: a record signed by another key is `malformed(.signerChanged)` and the remembered one stands. A registry deleted wholesale is restored record by record, loudly. The dated restore list is bounded at `RegistryCache.restoreLimit` (50). `RegistryCache.shared` resolves no identity for a project with no registry and no cache.
- **Every trust closure is built from a `TrustTable` and takes a `TrustVerdict`, never a Bool** (tripwire 39). The keyless spellings and `OpLogClassifier.walk`'s callers are named arrays (`TripwireGrepTests.trustClosureAllowedSpellings`, `walkCallSites`); a new caller is an unreviewed keyless decision. `TrustResolution.keyless(mine:)` is the signed-but-registerless behaviour exactly.
- **`myRoot`'s arms are numbered names, in a load-bearing order**: (1) the joined root, write-once; (2) this device's own root record; (3) a foreign root whose chain names my key; (4) nil. **A device with its own root record never joins another** (`TrustTable.ownRootRecord`); other roots are claimants and read `.otherRoot`. Adoption (`TrustTable.adoptedRoots`) unions an adopted root's chain into `myChain` without moving `myRoot` or the claimant list.
- **A span answers to its file's verdict, sealed or not.** The file's key comes from the last chain-verified seal; where that seal is unattributable (`TrustVerdict.isUnattributable`) it falls through to the filename's slug (`PermitMark.keyNaming` → `TrustTable.key(forDeviceSlug:)`); else unchanged. The fall-through can only hold or leave alone, never widen. Read `TrustVerdict.settlingAnUnsealedSpan`'s arms: **this device's own unsealed tail is never held or refused**, and `.retired` keeps. `OpLogChain.readmitting` restores a line to the state it would have had (`Line.coveredByASeal`). `PermitPartition`'s `attributableKeys` takes the same filename fallback for a file with no seal at all, so never sealing is no bypass. A refused span does not break the chain: a later admitted span still applies, so held lines are not necessarily a suffix.
- **Verdict → line state is one switch, `TrustVerdict.settling(sealKey:sealedAt:)`**: `.mine`/`.admitted` verify; `.stranger` is pending with no `.lines` record; `.revoked`/`.otherRoot` quarantine; `.retired` by the seal's date. `.mine` and revocation outrank retirement. Count the verdict cases in the enum, never in prose.
- **A revocation keeps what this Mac had already applied**: `RevocationSplit.partition` cuts per line against `TrustTable.highestOpIdSeen(forPerson:)`, before the parse, in both `classifyTail` and the segment fallback walk through `OpLogClassifier.readmittingWhatWasAlreadyApplied`. It asks each line's own `OpLogChain.Line.refusal`, never `Verification.quarantineCause` (forged text would come back). A seal travels with the op before it; `Verification.head` does not move.
- **A revocation's scope is the writer's** (`RevocationScope`; *Revoke and Set Aside Everything* records no mark, keeping nothing, told apart by `TrustEvent.Kind.revokedEntirely`); `DocumentStore.revoke` computes the mark over every op-log file, never just the open documents. **`handleExternalLogChange` re-reads when ops LEFT as well as arrived** (after first flushing the writer's un-bursted words into real ops), so a revocation, retirement or registry Restore takes words out of an open chapter.
- **The chained write judges by `.mine` alone**: a stranger's line in my file is a quarantine, never a hold.
- **Every device declares itself**: `ensureDeviceRecord` names `.author` and only enumerates other actors; `ensureRootIfEmpty` refuses if anyone is named, if this device has no record, or on a non-Mac; a malformed-only registry is not empty. On the Mac both run in `DocumentStore.open`; the phone runs `PhoneDeviceRecord.ensure` at first write.
- **A key minted after the open reaches the record before its first line**: `OpLogStore.append` and `TranslationStore.appendBatch` call `declareActorOnce` (re-signing through `RegistryWriter.resign`, `actors` only) when `declarationIsDue`. It never declares an unknown device, never names the author, never mints, leaves a retired record alone and never costs a line. One attempt per registry state; `invalidateTrust()` makes a store ask again.
- **A record arriving after its line re-judges it**: `DocumentStore.registryChanged` (debounced) forgets tables, re-reads open documents and posts admission-settled; this Mac's own writes are an echo (`DocumentStore.registryChangeIsAnEcho`, `RegistryArrivalTests`). Stated limit: the open's own `ensureDeviceRecord` writes a fresh record and drops a later build's fields.
- **`RegistryAdmission`'s refusals of authority are decided against the reconciled registry (`TrustResolution.verifiedRegistry`), never a raw folder read.** `admit` refuses `.notARoot`, `.alreadyAdmittedElsewhere(root:)` and `.recordUnreadable(fingerprint:)`; `revoke` and `retire` refuse `notAdmitted`, `cannotRevokeARoot`, `notThatDevice`. `admit` is idempotent to the byte, keeps `admittedAt`, and clears a revocation on re-admission; `claim` writes the root record before the `ClaimRecord`.
- **`AdmissionMemory` is only ever a sheet decision**: a recognised admission writes nothing to it (`RecognitionAdmissionTests.test_aRecognisedAdmissionInOneBookIsNotRememberedIntoAnother`), and a rename only updates an existing entry. `RegistryPresence.admitRemembered` silently admits remembered devices where this device is a root.
- **A stranger's rotated segment is held like its tail**: the segment fallback walk passes the same `TrustVerdict` closure (`PendingLoadTests.test_aStrangersRotatedSegmentIsHeldJustAsItsTailIs`).
- **Retirement is one-way.**

### The permit
- **No narrowing, no behaviour change**: with no narrowing event every admitted person is a book author from the start.
- **`Permit.allows` is the one table, its `OpKind` switch (`Permit.group(of:)`) has no `default:`, and manuscript text is asked of `Deriver.appliesToManuscript`, never restated** (tripwire 44). `.cannotJudge` holds lines pending and never sets them aside. Censuses: `TripwireGrepTests.test_thePermissionTableIsSpelledInThePermitLayerOnly`, `test_theManuscriptClassifierHasOneNamedSetOfCallers`.
- **A mark is chain positions per STREAM** — whole-segment digests plus the last `lineHash` — never an opId and never this device's memory. `PermitMark.stream(of:)` is the one URL → stream parse.
- **A mark records what was SEEN, not applied; a revocation's mark alone means APPLIED** (`OpLogStore.seenPositions` vs `appliedPositions`, chosen by `DocumentStore.permitMark(forPerson:seen:)`).
- **The opening before a person's first event turns on its kind** (`PermitTimeline.opening(before:)`): a demotion never reaches back, so a re-admission mints `.readmitted`, never `.admitted`.
- **The check runs after `RevocationSplit` and before the parse, line by line.** A refusal is `QuarantineCause.notPermitted`; an unjudgeable line is pending with no record. The call sites are `TripwireGrepTests.partitionCallSites` (tripwire 45); a missing site applies unjudged text. Census: `TripwireGrepTests.test_thePartitionsCallSitesAreExactlyTheNamedList`.
- **Annotation amendments are judged as of the line** (`AmendmentPermits`, `AnnotationOwnership`), never by the signer's current permit.
- **The cost exits turn on NARROWING, never on events** (`TrustTable.hasNarrowingPermits`): admissions write events too. The actor rows bind in every book. The exits, for anyone editing the partition: a registerless book judges nothing (`judgesAnything`); a book author's author key skips the per-line decode (`Permit.allowsEverything`); a one-kind stream an allowed actor wrote is answered whole (`PermitPartition.answersWholeFile`); the document class travels as a closure in the `PermitJudge`, so no manifest is read where nothing is judged.
- **Nothing proves possession of a listed non-author key**: `Registry.actorKeyOwners` is the one resolution; a non-author key two records claim is nobody's, forever, and standing plays no part.
- **Which writer a key is has two sources, and the second only narrows**: a device record decides (`TrustTable.actor(forSealKey:)`); without one, `DeviceIdentity.actor(ofDeviceId:signingWith:)` believes the slug's actor word only where its hex is a prefix of the key. Unreadable actor word, no slug, or a mismatched run stay nil (pending) (`PermitLoadTests`).
- **The role check reads `PermitTimeline`, never `PersonRecord.role`/`.scope`/`.pieces`** (tripwire 43). Census: `TripwireGrepTests.test_theRoleCheckReadsTheTimelineAndNotTheRecordsField`.
- **A marking verb refuses and writes nothing when its sweep cannot read** — unlistable directory, unreadable file, an `.icloud` placeholder (`OpLogStore.nameBehindICloudPlaceholder`), or a stream it remembers missing (`ReadError.streamMissingFromSweep`). The silent admission at open skips instead. The refusal names its act (`RegistryAdmissionError.Act`). `changePermit(everyRecordOf:to:)` pre-flights every record sharing a label before writing, skips revoked siblings, and reports a mid-run failure as `PermitChangePartlyApplied`.
- **`OpLogStore.localWritePermit(as:documentClass:)` is the one write-side question; only `LocalWritePermitBuilder` builds a `LocalWritePermit`** (tripwire 46). It never throws (fallback: the remembered register via `TrustResolution.remembered`, then keyless — never straight to keyless), never suspends (`trustOnThisActor`), and costs a registerless book nothing (`TrustResolution.hasAnythingToResolve`). Census: `TripwireGrepTests.test_theWriteSidePermitQuestionHasOneFunction`.
- **A permit rung is compared only inside the permit layer** (tripwire 47); a surface asks `Posture` through one door (tripwire 51, `Maugham/Views/AREA.md`). Censuses: `TripwireGrepTests.test_aPermitRungIsComparedOnlyInThePermitLayer`; for the posture, `test_postureIsAskedOfThePermitInOnePlace`.
- **Which lines the load emitted is decided once** (tripwire 48): `Permit.isALoadEmission` (`bootstrap`, the anchor `taskCreate`) and `Permit.actorJudging`, asked by the partition. It widens the ACTOR, never the permit, and is not gated on narrowing. The three `typingBurst` emissions are not covered; their `synthesisSource` (`.pendingRecovery`, `.anchorSplice`) is provenance (`LoadBurstCensus`) and reaches no table. Census: `TripwireGrepTests.test_theLoadEmissionRuleIsSpelledInThePermitLayerOnly`.

### The load seam
- **What the load emits on its own account is the author's, whoever opened the file**: the bootstrap, both pending-recovery folds, the spliced task anchors and their `taskCreate` sign through `Document.authorEmissionDevice(loadedAs:)`. `sealChain(docId:)` seals them at the same Document's close; rotation stays the Document's own actor.
- **Where this device may not write the piece, the load emits nothing.** `LocalWritePermit` is resolved once per load and stamped on the `Document`:
  - **bootstrap** — asked of `LocalWritePermit.mayMintOpening`. In a narrowed book a piece with a recorded starter (`StructureItem.startedBy`) is minted on that Mac alone, the root's included; a piece with no starter, a `.gone` starter (`TrustTable.starterStanding`: revoked or retired only), or any un-narrowed book keeps the older rule. An `.unknown` starter waits. Otherwise `DocumentLoadError.waitingForPiece(docId:from:)`, naming the starter (`Document.starterLabelForWaiting`) or the root, never this Mac's own root label. `EditorHost` draws it as a calm state on the one load-outcome `@State` (tripwire 6) and retries when the piece's ops change.
  - **the pending file** — not folded and not read (`PendingBuffer.fileNameIfOnDisk`). `Document.mayWriteThePendingFile` is ONE expression at four sites (autosave mirror, burst clear, failed-flush re-persist, clean clear); the burst uses `PendingBuffer.clearInMemoryOnly`. The writer hears through `PendingRecoveryFailure`.
  - **task anchors** — no mint, no `taskCreate`; the rebalance is guarded on the `.maugham` key's own row.
- **The writer's-hand automations** — `sweepOrphanedAnnotations`, `repairRejectedButSplicedAnnotations` — sign as the author through `appendLifecycleOp(automation:)`, skipped where the permit disallows the write (`AutomationNotPermitted`); the repair also waits while `unsettledStarter` is set, and a later merge repairs (#84).
- **Every disposition mutator asks the stamp first** (`requireDispositionPermitted`) and throws `Document.PostureRefusal` before writing; a refused undo or redo says so (`refusingLoudly` → `UndoDecline.notPermitted`). **A suggestion's accept and revert also ask the host's `mayWrite` closure**, forwarded into every text-writing re-entry; refusal is `UndoDecline.suggestionNotPermitted`. A textless accept never asks it; a windowless caller passes nil. A refused press is said through the notice channel, never swallowed by `try?`.
- **A reopen is judged by what it undoes**: against the withdrawal it undoes by ownership (`AnnotationOwnership.mayAmend`), otherwise as a disposition (`mayDispose`), through `AnnotationAmendments`; the Mac door uses `requireRestoreHonoured` or `requireDispositionPermitted` with `dispositionProbe`. Restore follows who deleted the note, by key (`Document.restoreStanding`), never by the display name (`WithdrawnAnnotation.withdrawnBy`).
- **A Restore beaten only by order refuses with `PostureRefusal.Cause.deletedAgainElsewhere`**, decided by re-deriving over the whole mirror plus a probe reopen sorting last. Do NOT go back to dropping later-sorting withdrawals. The probe is never appended. `restoreStandingMemo` is cleared by `invalidateRestoreStandingMemo()` at every site that assigns or appends `_opLogMirror` or assigns `annotationAmendments` (census in `DocumentAmendmentOwnershipTests`).
- **Every reader of the raw mirror asks the deriver's judgement** (`isWithdrawn`, `AnnotationDeriver.isHonouredLifecycleOp`), including the reject/splice repair, the rewind's return journey and `RewindImpact.preview`. A closed piece's rewind preview is judged as a load would (`Document.closedPieceHistory`, `Document.judgedAmendments`).
- **Don't add a suspension point to `Document.load`**: its awaits are part of its contract (a pane can bind mid-load, `ProjectStore.withStatementDocument`). Resolve on the store's actor (`trustOnThisActor`).
- **The stamp is live**: `Document.localWritePermit`'s one setter is `stamp(localWritePermit:)`, called by the load and by the posture refresh in `DocumentStore+Posture.swift` for every open document, statement editors included, in the same main-actor turn as the drawing publication. **A re-stamp keeps the author actor** (tripwire 38).
- **Task ops have a door**: `appendTaskOpInternal` refuses a refused kind; `archiveTask` refuses up front if its op or its text splice is refused; undo declines with `UndoDecline.taskNotPermitted`. The project stream's verbs go through `ProjectStore.appendProjectTaskOp` (`projectTaskRefusal`), which registers no ⌘Z for a refused act.
- **Every manuscript writer outside the editor asks first** (tripwire 52). A burst's emission is deliberately unguarded (the editor's membrane is in front of the keystroke). A restore refuses in `requireRestorePermitted` before its undo-stack clear, flush or op (`UndoDecline.restoreNotPermitted`). Project Replace, the rename's wiki-link sweep and statement writes ask `Document.mayWriteItsText` beside the store's settled posture (`Maugham/Stores/AREA.md`). The paragraph primitives also refuse inside (`Document.rejectTextWriteIfNotPermitted`). The population is `TripwireGrepTests.guardedDocumentMutators` and `manuscriptWriterCallSites`. Censuses: `TripwireGrepTests.test_everyGuardedDocumentMutatorIsClassified`, `test_everyManuscriptWriterOutsideTheEditorIsANamedSite`.
- **`author_collaborator_id` is decoded and never written**: only `Op.swift` names `authorCollaboratorId:`; attribution is the signing device through the registry (`TripwireGrepTests.test_theCollaboratorIdIsDecodedAndNeverWritten`).

### A foreign stream that got shorter
- **`ForeignStreamWatch` remembers other devices' streams by STREAM, never by filename**, together with the digest of every segment taken in whole (`ForeignHeadTests`). Both this memory and a mark's `segments` are built from one value, `FileClassification.wholeSegmentDigest`.
- **A stream is remembered only once it has answered**: an entry means "this device applied something of theirs". Once present it is kept and only grows; it leaves with its project (`OpLogDeviceState.prune`, `rootIsGone`).
- **A remembered digest no segment carries any more is a lost segment** (`StreamTruncation.Loss.segment`); while a present `.mzseg` cannot be settled, no digest is reported missing.
- **It is a report: nothing is refused or set aside.** `OpLogStore.truncatedStreams` names the device the usual way; `IntegrityReport.truncatedStreams` makes a report unhealthy and does not block a backup. A finding holds now and is dated once (`settleForeign`), and clears when the bytes return.
- **The strict load fills it** (one watch per load, settled once); `TranslationStore.loadMerged` carries its own; `JSONLAppendStore.loadVerifiedStrict` uses `ForeignStreamWatch.note`. `loadSyncMerged`, `loadDiagnosedPartial` and `ProjectIntegrity.check` deliberately do not. The phone fills it too and asks it nothing.
- **A marking verb's sweep is asked about CONTENTS**: `DocumentStore.expectedStreams(ofDeviceIds:in:state:)` is the one builder, and `positions` calls `ForeignStreamWatch.loss` — the load's own predicate, never restated. `writeEvent` unions segment digests per key. A stream never read is not expected; `retire` expects nothing.

### The unsigned door, scope and a piece of her own
- **`UnsignedSnapshot` is taken at the first NARROWING event** over every unattributable stream: at or before it, applied; after it, pending, never pardonable by admission, with *Send to Inbox* as its way in. Narrowing is sticky; the earliest narrowing by signed date governs. **A later narrowing carries the governor's own mark** (`DocumentStore.sweptUnsignedSnapshot`), never an empty map.
- **`HeldLines` tells the three held reasons apart once** — a stranger's key, a permit-pending line, an unsigned stream (`unsigned:<stream>`). `HeldLines.Waiting` counts prose by paragraph, notes as notes, the rest as changes, asking `Permit.group(of:)`.
- **`OpLogStore.provenance(forDocId:in:trust:state:)` is what a load would report about a closed document**, read-only and not a second classifier (`ClosedProvenanceTests`).
- **`OpLogDeviceState.acknowledgeLoss` is the escape** for a stream legitimately gone; every sweep takes it through `expectedStreams`.
- **The schema gate**: the first narrowing raises `ProjectManifest.schemaVersion` to 9 before the event is written (gate → event → record), raise-only against disk, healed at open. The call-site lists are `TripwireGrepTests.countedLists` (tripwire 50). Census: `TripwireGrepTests.test_theP3bCountedListsAreExactlyTheNamedArrays`.

Earlier entries are judged by `Entry.judging`, while `Entry.permit` stays what was installed; the partition asks `entry.judging` and nothing else. Only lines refused for that piece's scope come in. A piece taken from her is recorded (`PermitTimeline.wasTakenFromThem` → `Document.keptWritingInATakenPiece`).

The answer takes the ordinary loss check: a segment this Mac applied that is now missing refuses it (`streamMissingFromSweep`).
- **Unsigned-stream words cover a Mac whose first seal has not synced** (`HeldLines.unsignedWriter`); none says there is no device to admit.
- **`StructureItem.startedBy` is written at creation through `ProjectStore.thisMacAsAStarter` and never rewritten** (`TripwireGrepTests.test_everyStructureItemAProductionFileConstructsRecordsItsStarter`). A permit ask needing class and starter reads one `ManifestPlacement`, never the class from the live manifest and the starter from disk. The census cannot see a `StructureItem` copied from a source; Duplicate's re-stamp is pinned by its own test.

A starter must name an owned author key; her other Mac counts only while still admitted.

### Figures
- **A figure follows its piece's posture, both starter arms included**: `Permit.startersPiece(of:)` names the piece whose starter a class asks, so §4.5's shape, `writesAsItsStarter`, `unsettledStarter` and the partition's starter and `unowned` questions reach a figure of a piece, never one of the whole book. A figure has no opening (`startedHere` nil); a figure edit claims the piece as its text does; a piece's re-stamp forgets its figures' cached postures.
- **Parked folds nothing**: content ops ordered between `figureParked` and `figureResumed` are dropped with a diagnostic and kept in history; a second park is ignored. Mutators refuse while parked (`FigureParkedRefused`), bar `resumeFromResearch`.
- **A figure op is minted after the newest op its host folded** (`commit`'s `after:`).
- **The return is three-way**: a park records each device's position in its own stream (`parkedFrontier`); `FigureReturnDiff.base(of:streams:frontier:)` folds that base, the copy's changes land on the parked state, and a late edit the copy overwrote is reported. Returning ops follow and name their `figureResumed`, which names its park (`returnOf`, so a duplicate or stale return folds nothing), carry `SynthesisSource.broughtBackFromResearch`, signed by whoever brings them back.
- **A figure restore is ordinary figure ops** (`FigureDocument.restoreToCheckpoint` over `FigureRestoreDiff`), stamped `provenance.sourceCheckpoint`, behind `editFigure`: a parked figure is skipped; pins are judged by the book's park cycles from one assembly (`FigureWorkbook.parkCycles`), so a live pin is never replaced by an inert one; a picture returns only when its bytes are in `figures/` or the undo folder, by content under its current name; a reload or failed append part way answers `.partlyRestored(opCount:why:)` (a retry is safe).
- **Figure undo is compensating ops** (`FigureInverse`): a delete carries its `removed` slice and undoes as a revive; an undone insert redoes as a revive; `refreshPins` carries each `priorPin` and is one ⌘Z per visit; park and resume have none.

### The person key
- **Recognition decides only who is admitted**; permits, partition, timeline and load are untouched. Only a Release build reaches the keychain (`scripts/verify-mac-signing.sh`); Debug, ad-hoc and test builds read it as unavailable.
- **`PersonKey.findOrCreate` never mints over an item it cannot read**, fills an empty name and never overwrites a set one. The key signs a claim and nothing else. The Mac's one store construction is `Maugham/Stores/PersonKeyAccess.swift`; the phone finds and never makes.
- **The claim's device comes from the containing record, never the claim**; read `Registry.verifiedPersonClaims`, never `.personClaim` raw. A misshapen claim decodes nil. `DeviceRecord` has a hand-written `init(from:)`: a new field goes in `CodingKeys` and that init. `ensureDeviceRecord` takes a `PersonClaimIntent` (`.keep`, `.set`, `.remove`) and compares claim facts (ECDSA is randomised).
- **Link and Forget are root-only** (`RegistryAdmission.linkPersonKey`, `forgetPersonKey`, through `RegistryWriter.resign`). A person is a label: the same key may sit on every record sharing it, a label change drops it, and it is refused for any other label (`otherPersonHolding`, revoked holders included). Forget is durable (`hasForgotten`; there is no re-trust verb) and label-wide over this root's holders (`RegistryAdmission.forgetHolders(of:by:in:)`); a same-label holder another root admitted never blocks it. A present-but-unreadable person record refuses a link (RULING-54). **Every person-key fact is read from `TrustTable.chain(ofRoot:in:)` only.**
- **`Recognition.recognise` turns every doubt into an ask**; read the file's table. The silent admission (`RegistryPresence.admitRecognised` → `RegistryAdmission.admitRecognised`) runs before `admitRemembered`, which leaves to the sheet any device whose remembered label names a narrowed person (`labelNamesANarrowedPerson`) and any device recognition declined; both are serialised (`DocumentStore.serialisingSilentAdmission`). The doors are counted (tripwire 53, `PersonKeyCensusTests`).

### Sealed segments and cost
- **A device's own tail over `OpLogStore.segmentSealThreshold` (512 KB) rotates into an immutable `.mzseg`** (`OpLogSegment`, ADR 0016). Recognition lives only in the single-source helpers (`opLogFileURLs`, `docId(fromOpLogFilename:)`, `loadFileDiagnosed`, `loadSyncMerged`). A checksum failure quarantines and marks the document unhealthy (backups pause). Never the inbox or pending files, never mid-typing, Mac-only.
- **Each segment is signed beside itself** (`.mzseg.sig`, named only by `segmentSignatureURL(for:)`), best-effort. A segment reaches one of three outcomes, in order: cached digest; trusted sidecar (`TrustVerdict.isOurWord(sealedAt:)`); fallback walk through the table. Only a container that itself verified may be keyed on. The `.sig` stays out of history only because `opLogFileURLs` matches `.jsonl`/`.mzseg` endings; a new sidecar must end in neither.
- **What keeps the cost where it is, and must not be undone** (`docs/superpowers/notes/2026-09-09-perf-step-measurements.md`):
  1. `Hex` is table-driven; never `String(format: "%02x")`.
  2. The settled-segment branch COUNTS lines rather than splitting them.
  3. `prev(ofLine:)` reads the fixed `{"prev":"<64 hex>"` prefix by bytes; never per-byte `Data` accumulation into a `String`.
  4. No date decode allocates a formatter: `ISO8601Fast` takes exactly the two shapes this app writes and nothing else; `JSONLAppendStore.dateEncoding` is byte-frozen (heads hash encoded bytes).
  5. The head is persisted before the batch, once per batch, never coalesced.
- **The registry costs one folder read and verify per store, and again only when `TrustResolution.signature(of:)` changes**; `OpLogStore.trust()` and `InboxStore.trust()` compare it before reusing the table.

### RenderFilter's three matching tiers
- **An unanchored paragraph is reattached in three tiers**: exact text; word-shingle overlap ≥ 0.6 (`ShingleMatcher.bestMatch`, k = 4); character bigram ≥ 0.6 with a margin over the second-best (`RenderFilter.bigramReuseThreshold` 0.6, `bigramReuseMargin` 0.1). The bigram tier lives in `RenderFilter`, not `ShingleMatcher`.
- **On a tier-2-vs-tier-3 disagreement, tier 2 wins whenever it clears 0.6**: the bigram tier is a fallback, and a tier-3 score never steals an id from a tier-2 pairing (`RenderFilterTests.test_restoreComments_tier2WordShingleWins_overTier3BigramFalsePositive`).
- **An ambiguous bigram tie mints fresh**; a single high-overlap candidate keeps its id (`CrossDeviceIntegrationTests.test_case3a_singleCandidateMinorEdit_keepsItsId`, `test_case3b_nearDuplicateTie_reusesIdWithNoMargin`).
- Failure modes: all tiers miss → orphan paragraph (logged); tier 2 matching the wrong near-duplicate → silent corruption.
- **The task-anchor round trip `restoreTaskAnchors(prior, stripComments(prior)) == prior` holds** (`RenderFilterTaskAnchorTests`).

### Behavioural claims
- **`Document+Rewind`, `Document+RewindUndo` and `Deriver+Rewind` are claim-covered** (`register/reconciliation/Rewind.claims.json`, `register/reconciliation/Rewind.filings.json`). Read the filings before changing rewind behaviour; changing pinned behaviour updates the claim and filing in the same commit.

### Add an `OpKind`

### Add a permit-checked writer (tripwire 52)
1. In the `Document` extension that owns the verb, open with `rejectMutationIfNotWritable("…")`/`requireWritable("…")`, and for a disposition `requireDispositionPermitted` (or `requireRestorePermitted` for a restore), throwing `Document.PostureRefusal` before any undo clear, flush or op.
