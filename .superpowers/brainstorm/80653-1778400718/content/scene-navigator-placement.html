A — Three segments: Manuscript / Scenes / Research

Add Scenes alongside Manuscript. Manuscript shows the single .fountain file (forward-compatible with multi-file in 3d). Scenes shows extracted sluglines.

Pros: matches handoff. Forward-compatible. Cons: Manuscript is redundant for single-file (one item).

B — Scenes replaces Manuscript for screenplay (recommended)

For Screenplay projects: binder is "Scenes / Research" — no redundant Manuscript segment for the single .fountain. For Novel/Story/Collection: binder stays "Manuscript / Research" as today.

Pros: cleaner UI, no redundancy. Cons: per-project-type segment shape; 3d (multi-file) will need to revisit.

C — Floating scene navigator window

Separate window/sheet showing scenes. Toggle via ⌘ shortcut. Binder stays unchanged.

Pros: doesn't perturb binder UX. Cons: adds a new window scene; users have to remember a shortcut.

scene row format (same across all options)

  • Slug: INT. KITCHEN - DAY (full text from FountainLine.content)
  • Page number: p.5 (computed by accumulating page-count up to that line)
  • Click row → editor scrolls to that line, cursor lands at start of slug
  • Optional: synopsis/section context surfaced inline (deferred)
