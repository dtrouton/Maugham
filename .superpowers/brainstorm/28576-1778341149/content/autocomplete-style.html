Character autocomplete — UX style

When the writer types on a character cue line, suggestions appear from FountainScript.characterNames. How should they appear?

A — Popup menu (NSPopover-style)

Discrete dropdown anchored at the cursor. Up/Down arrows select. Tab or Enter accepts. Escape dismisses. Visible.

Pros: Familiar pattern (Xcode, IDEs). Multi-match visible. No commitment until accept. Cons: Adds a floating surface to manage.

B — Inline ghost text

The most-likely completion appears in dim grey directly after the cursor. Tab accepts. Any other key dismisses (and the next character typed continues the input).

Pros: Quiet. No popup chrome. iA-Writer / GitHub Copilot vibe. Cons: Only shows ONE suggestion (the best match). Multi-character ambiguity (BAR → BARRY or BARTENDER?) loses one option.

C — Both: ghost + popup

Ghost text shows the top match inline; popup shows the full list of candidates below. Tab accepts the ghost; arrows + Enter select from the popup.

Pros: Best of both (quiet AND complete). Cons: Most code. Two surfaces to manage. Risk of feeling busy.

Trigger conditions (same across all 3 options)

  • Active only on a Character cue line (forced @ or detected ALL-CAPS)
  • Activates after typing 1+ character in the cue
  • Suggestions are uppercased character names from FountainScript.characterNames (already populated by 3a's parser)
  • Ranking: prefix-match first, sub-string match second, alphabetical within each
  • Dismisses on: blank line, cursor leaving the cue line, Escape
