# The Atlas & Change Cards — Owner-Facing Codebase Visualization

**Date:** 2026-06-09
**Status:** Draft — pending owner review
**Extends:** [mental-maps note](../notes/2026-06-09-mental-maps-for-a-non-coding-owner.md) (parts 1 & 2 are the brainstorm this spec hardens)

## Problem

The owner of this codebase does not read code — Claude writes all of it. The owner's two
standing questions have no artifact today:

1. **"What is the current state of the project?"** The answer is scattered across
   CLAUDE.md, MEMORY.md, AREA.md files, ADRs, release notes, and the repo itself. None of
   it is visual, none of it carries live numbers, and the numbers that do appear in prose
   (file counts, tool counts) silently rot.
2. **"What just changed, and what does it mean?"** Today's options are commit messages
   (too low-altitude, plural, code-speak) or release notes (too coarse, writer-speak
   only). There is no per-milestone artifact that says *what changed for the writer*,
   *what changed for the system*, *how risky it was*, and *where it landed on the map* —
   with the ability to drill from a one-sentence summary down to the diff.

Both artifacts must be **drillable** (each altitude links to the next) and **trustworthy**
(computed numbers, never hand-typed ones). The repo already proves the pattern works:
`EMISSION.md` is generated from `EmissionContract.swift` and test-enforced. This spec
applies that principle to the whole project.

## Goals

- A generated, GitHub-rendered **Atlas**: one L0 page (zoning map + health numbers +
  curated state paragraph), one L1 page per district (vitals + scars + recent activity).
- A per-milestone **Change Card**: computed fields (districts touched, risk class,
  source/test/docs line split, commit story) filled by a tool; two short prose fields
  (writer-visible summary, system meaning) written by Claude at milestone time.
- **The base map never changes shape** — change renders as highlighting on a constant
  background, so the owner's eye learns the geography once.
- **Every number is computed.** The only hand-written content is prose that changes
  rarely (district meanings, the state paragraph) or is authored once per milestone
  (the two card prose fields).
- The whole system runs in **both** session environments: the Mac (Xcode CLT) and
  Claude's cloud Linux containers. No third-party dependencies.
- A test fails when the district registry stops covering the source tree.

## Non-goals

- **No HTML dashboard, no app UI surface.** The rendering target is GitHub-flavored
  markdown + mermaid; GitHub *is* the UI. (The "every data type needs a UI surface" rule
  is about writer-facing app data; this is repo tooling about the codebase, and its
  inspection surface is the rendered repo.)
- **No screenshot automation.** Views-district changes are best shown as before/after
  screenshots; v1 allows manually attaching images to a card (`images:` field), and
  automation is future work.
- **No git-history backfill** beyond two seed cards. Cloud clones are shallow; the
  convention accrues forward.
- **No CI freshness gate on Atlas numbers.** Numbers change every commit; instead the
  Atlas is stamped with the commit it was generated from and regenerated at defined
  moments (below).
- **No churn-from-git analytics.** Heat comes from change cards, not `git log`, so it
  works identically in shallow clones and measures *milestones*, not commits.

## Design

### Artifact layout

```
docs/atlas/
  registry.json          # hand-curated district registry (single source of truth)
  state.md               # hand-curated "where the project is" paragraph(s)
  ATLAS.md               # GENERATED — L0: map, heat, health table, state, open concerns
  districts/
    <district>.md        # GENERATED — L1 vitals per district
  cards/
    001-cross-surface-contracts.md     # one card per milestone, NNN ordered like ADRs
    002-inline-emphasis-contract.md
scripts/
  atlas.py               # the tool (python3, stdlib only)
```

`ATLAS.md` and `districts/*.md` carry a generated-file header (`<!-- GENERATED by
scripts/atlas.py from <short-sha> on <date> — do not hand-edit -->`). Cards are
half-generated: the tool emits the skeleton, Claude fills two prose fields, then the file
is owned like any doc.

### The district registry (`registry.json`)

The path→district mapping is data, not code. One entry per district:

```json
{
  "districts": [
    {
      "id": "editor",
      "name": "Editor",
      "paths": ["Maugham/Editor/"],
      "testPaths": ["MaughamTests/Editor/"],
      "scars": [2, 3, 5, 6, 7],
      "risk": "expensive",
      "meaning": "Typing, cursor, tokenization, focus — the fragile AppKit↔SwiftUI seam.",
      "area": "Maugham/Editor/AREA.md"
    }
  ]
}
```

Initial districts (one per existing zone): `core` (Packages/MaughamCore), `editor`,
`oplog`, `stores`, `mcp`, `publish`, `views`, `models`, `updates`, `backup`,
`preferences`, `app` (Maugham root files + maugham-mcp), `phone` (MaughamPhone/*),
`docs` (docs/, *.md). `risk` ∈ {`cheap`, `medium`, `expensive`} seeded from the cost map
in the mental-maps note. Scar IDs are CLAUDE.md tripwire numbers.

**Coverage rule:** every `.swift` file in the repo must match exactly one district's
`paths`/`testPaths` prefix list. Enforced two ways:

- `python3 scripts/atlas.py check` — local/CLI validation (also validates card front
  matter and generated-header stamps).
- A new Mac test `AtlasRegistryTests` (lives beside `TripwireGrepTests`, same pattern):
  reads `registry.json` natively in Swift, walks the source tree, fails on any unclaimed
  or doubly-claimed file. This is what makes "we added `Maugham/NewThing/` and forgot the
  map" impossible to ship silently.

### The tool (`scripts/atlas.py`)

Python 3, stdlib only (present in cloud containers and via Xcode CLT on the Mac).
Subcommands:

| Command | Does |
|---|---|
| `atlas.py gen` | Regenerate `ATLAS.md` + `districts/*.md` from registry + repo measurement + cards |
| `atlas.py card <range> --slug <slug>` | Emit `cards/NNN-<slug>.md` skeleton with all computed fields filled |
| `atlas.py check` | Registry coverage, card front-matter validity, generated-header stamps |

Measurement per district (computed by `gen`): source file count, source LOC, test LOC,
test:source ratio, scar count, top-3 largest source files. Repo-level: latest tag,
generating commit + date. **Heat:** number of the last 8 cards touching each district.

Card computation (`card <range>`): `git diff --numstat` over the range, classified
through the registry → districts touched (with per-district line counts),
source/test/docs insertion split, computed risk = max risk class over touched code
districts, scars-in-scope = union of touched districts' scar lists, spec/plan links
(paths under `docs/superpowers/` in the diff), and the L2 story = the commit list for the
range, each line linked to its commit on GitHub.

### Change card format

Front matter is a constrained YAML subset (`key: value`, JSON arrays for lists — parsed
by ~30 lines of stdlib code, no YAML dependency):

```markdown
---
card: 2
title: Inline emphasis contract
date: 2026-06-09
range: 4dd6cb4^..a405b0b
districts: ["core", "editor", "phone"]        # computed
lines: {"source": 261, "tests": 316, "docs": 932}   # computed
risk: expensive                                # computed default
risk-note: "Editor district in scope; mitigated by parser-pinning tests before wiring"
scars-in-scope: [2, 3, 5, 6, 7]                # computed
invariants-touched: []                         # author-confirmed
contracts: ["InlineEmphasisScanner (asterisk-emphasis grammar)"]
spec: docs/superpowers/specs/2026-06-03-inline-emphasis-contract-design.md
images: []
---

## For the writer            ← AUTHOR (1–3 sentences, no code-speak)
## For the system            ← AUTHOR (kind of change, why this shape, risk reasoning)
## The story                 ← GENERATED (linked commit list)
## Map                       ← GENERATED (zoning map, touched districts highlighted)
```

The two author sections are the part a diff cannot reconstruct: intent. Everything else
is computed. `risk` may be overridden by the author only with a `risk-note` explaining
why.

**The card unit is the milestone** — a merged branch / tagged arc — not the commit.
Commits are the card's L2.

### ATLAS.md composition (L0)

In order: generated header → **state paragraph** (inlined verbatim from `state.md`) →
**zoning map** (mermaid; fixed node layout from the registry; node label carries live
LOC/scar numbers; node *color* = heat class: hot ≥3 recent cards, warm 1–2, cold 0) →
**health table** (district | source LOC | test LOC | ratio | scars | risk | hotspot
file) → **recent cards** (last 8, newest first: title, date, one-line L0 pulled from the
card's "For the writer" first sentence, districts) → **drill-down footer**: links to
district pages, the promise–enforcement matrix in the mental-maps note, ADR index — and
the standing line *"For anything deeper: ask Claude. The bottom of this ladder is a
conversation, not a document."*

District pages (L1): generated vitals block + the registry `meaning` line + a link to the
district's AREA.md (the curated prose stays where it lives today; the Atlas points, it
does not duplicate) + the cards that touched this district (full list, newest first) +
scar list with tripwire text excerpted from CLAUDE.md by number.

### Workflow integration

1. **Finishing a milestone includes its card.** Added to CLAUDE.md's "Default workflow":
   after merge, run `atlas.py card <range>`, write the two prose sections, commit the
   card together with (or immediately after) the merge. The merge commit message
   references the card path.
2. **`cut-release.sh` runs `atlas.py gen`** and includes the regenerated Atlas in the
   release commit. Claude refreshes `state.md` while writing release notes — same moment,
   same mindset.
3. **`atlas.py gen` may be run any time** ("show me the current map") — it's
   deterministic for a given repo state.
4. Trivial merges (typo fixes, doc nits) don't need cards — judgment call, same as
   "skip dual review for trivial tasks."

### Seed content (ships with v1)

- `registry.json` covering the current tree (the `AtlasRegistryTests` coverage test pins
  it).
- Backfilled **card 001**: cross-surface contracts baseline (v0.6.1 arc) and **card 002**:
  inline emphasis contract — both ranges are in reachable history and serve as the worked
  examples for the format.
- First generated `ATLAS.md` + district pages.
- `state.md` first draft (Claude writes, owner adjusts wording taste once).

## Acceptance criteria

1. `python3 scripts/atlas.py gen` runs on macOS and in the cloud container, touches only
   `docs/atlas/ATLAS.md` and `docs/atlas/districts/`, and is deterministic for a given
   commit.
2. `ATLAS.md` renders on GitHub: mermaid zoning map with heat colors, health table with
   live numbers, recent-cards list, drill-down links that resolve.
3. `python3 scripts/atlas.py card 4dd6cb4^..a405b0b --slug inline-emphasis-contract`
   reproduces card 002's computed fields exactly (261/316/932 split, districts
   core+editor+phone, risk `expensive`, 12-commit story).
4. `AtlasRegistryTests` passes on the seeded registry and **fails** when a new top-level
   Swift directory is added without a registry entry (verified by a temp-dir negative
   test, not by dirtying the tree).
5. `atlas.py check` catches: unparseable card front matter, a hand-edit to a generated
   file (stamp mismatch is fine — stamp *removal* is the violation), uncovered source
   files.
6. `cut-release.sh` regenerates the Atlas as part of cutting a release.
7. CLAUDE.md gains the card-per-milestone workflow line and an `docs/atlas/` pointer in
   the per-area table.
