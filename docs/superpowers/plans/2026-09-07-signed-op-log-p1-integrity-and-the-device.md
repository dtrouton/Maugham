# Signed op log P1 — integrity and the device

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every line a device writes to an op log or an inbox manifest is chained to the one before it, every span the device wrote is sealed by a Secure Enclave key that never leaves the device, a sealed segment carries a signature over its digest, and a load classifies each line as *verified*, *unsigned history* or *quarantined* — never refusing to open, never applying what broke the chain, never losing a byte. The device's identity becomes its key's fingerprint (so two Macs named alike can never collide on a file), `MacDeviceID` and `PhoneDeviceID` are replaced by one MaughamCore `DeviceIdentity`, and the phone's palette aim is removed. Closes the maintainability audit's item 10 (the live tail's unframed appends).

**Architecture:** three new MaughamCore units and one widened one. `DeviceIdentity` (new) mints and persists the enclave key's opaque `dataRepresentation` under Application Support — never a keychain item — and answers the device id string every existing `device:` parameter already takes. `OpLogChain` (new, pure) is the wire format and the verifier: an op line gains one additive key `prev` (the SHA-256 of the previous line's bytes), a **seal line** is a line of its own kind carrying a signature over the chain head, and `verify` walks bytes to a per-line classification with no I/O. `OpLogDeviceState` (new) is the device's own memory — the remembered chain head per file and the content-hash cache of verified segments — in the same Application Support folder, shared in-process behind a lock so the synchronous readers see what the writers remembered. `JSONLAppendStore` (widened) grows a chained append that reads the tail, checks its last line against the remembered head, sets aside anything after it that this device did not write, then writes; `OpLogStore` and `InboxStore` on the Mac and the phone's two writers all go through it, so the phone cannot drift (tripwire 19). Sealed segments gain a `.sig` **sidecar** beside the `.mzseg` — additive, so no reader of the MZS1 container changes — and `loadFileDiagnosed` consults the verify cache before walking a segment's lines. Foreign devices' lines are applied as unsigned history in P1 (there is no registry yet); a chain break or a line after the remembered head is quarantined through `OpLogQuarantine`'s existing home as a `.lines` record that never returns. Legacy files carry neither `prev` nor seals and load as unsigned history; no migration.

**Tech Stack:** Swift 6 / CryptoKit (`SecureEnclave.P256.Signing`, `P256.Signing`, `SHA256`) in MaughamCore (Apple frameworks only); XCTest on all three targets: `swift test --parallel --package-path Packages/MaughamCore`, `./scripts/test.sh` (Mac), `./scripts/test.sh phone` (iOS simulator — the Apple Silicon simulator has a working enclave, measured in the spike).

**Spec:** `docs/superpowers/specs/2026-09-05-signed-op-log-design.md` — §3 (the 2026-09-07 ruling), §4.1 (keys; no software fallback in production), §4.3 (chained lines, seal lines, the chain-head check, segment signatures, the verify cache), §4.4 (three states; legacy is unsigned history), §4.8 (the slug is the key), §4.10 (the inbox; the palette aim goes), §8's **first bullet** (this plan's scope, exactly). **Spike:** `docs/superpowers/notes/2026-09-07-signed-op-log-spike.md` and the two full reports beside it — the numbers this plan budgets against are theirs.

**Branch:** `claude/signed-op-log-p1-2026-09-07` off local `main` at `901b5598` (the spec's ruling commit; baseline `./scripts/test.sh` green 2026-09-07).

## Global constraints

1. **Scope is §8's first bullet and nothing from P2 or P3.** No registry, no device certificate, no person key, no admission sheet, no roles, no `pending` state, no People & Devices pane. **No entitlement, no keychain item, no provisioning profile, no change to `Maugham.entitlements` or `project.yml`'s signing settings.** The enclave key blob is a plain file the app owns.
2. **No software device key in production** (spec §4.1, spike item 2). A Mac or simulator reporting `SecureEnclave.isAvailable == false` mints no key and writes **unsigned** chained lines; its identity is still stable (a persisted random token stands in for the public key when deriving the fingerprint). The ONLY software P256 private key in the tree is the test-only signer, and a census keeps `P256.Signing.PrivateKey(` out of every production source under `Maugham/`, `MaughamPhone/`, `Packages/MaughamCore/Sources/` (Task 1). Every test that asserts *verified* injects that signer; exactly ONE test per target touches the real enclave, skipping by **measurement** (`SecureEnclave.isAvailable`), never by platform guess — the GitHub macOS VM runner almost certainly has no enclave, and the phone job runs on an Intel-era image.
3. **Budget (spike item 3):** 50k ops must add under 100 ms to a cold open. The design meets it by construction — the tail walk is ≤ 512 KB (~700 lines, ~0.5 ms), a sealed segment's inner walk is skipped when its digest is in the verify cache, and an UNCACHED segment costs one walk of ~700 lines plus ≤ 8 signature verifies (~1 ms) once. Task 5 pins the structural fact (a cached segment's lines are never walked) without a clock, and its env-gated fixture prints the measured number for the handoff. Enclave signing is 4.5 ms per call and **never runs in a loop**: one seal per burst flush, per K appends, per close.
4. **Wire format, verbatim.** An op line is the existing `.sortedKeys` JSON object with `"prev":"<64 hex>"` inserted as the first key (`{"prev":"…",` then the rest of the object) — the position is fixed so the bytes are deterministic and the hash is over the bytes as written. A legacy line has no `prev`. A seal line is `{"seal":{"at":"<ISO8601 fractional>","head":"<64 hex>","key":"<fingerprint>","pub":"<base64 of P256 x963 public key>","sig":"<base64 of the 64-byte raw signature over the head's 32 bytes>"}}` — sorted keys, one top-level key, recognised by the prefix `{"seal":`. The line hash is SHA-256 over the line's bytes **without** its trailing newline. `Op` and `InboxEntry` gain NO field: `prev` is a wire key the chain layer adds and every `Codable` decoder already ignores, so an older reader decodes a chained op line unchanged and skips a seal line as an undecodable line (forensics, not loss — no schema bump: the manifest schema contract scopes bumps to `OpKind` cases, and nothing here rewrites an op).
5. **Identity.** `DeviceIdentity.deviceId` is the 16-hex-character prefix of SHA-256 over the public key's x963 representation (or over the persisted token when unsigned); `fingerprint` is the full 64 hex; `slug` is `DeviceSlug.make(from: deviceId)`. `DeviceSlug` keeps its private init and its filename-only life (tripwire 24) — only what `make` is handed changes. This Mac's and this phone's EXISTING files (hostname slug, `phone:<uuid>` slug) become another device's files: read as unsigned history, never appended to, never sealed. **Say so in the handoff**, including the one edge: a crash-recovery `pending` file partitioned under the OLD slug is not read after the upgrade (an updater relaunch follows a clean quit, which clears it).
6. **The device's own state** lives at `~/Library/Application Support/<BuildVariant.current.supportFolderName>/device/` on both platforms (tripwire 13 — the folder name comes from `BuildVariant`, never a literal), with a per-process leaf under XCTest exactly as `TestWorkspace.root` does (`Packages/MaughamCore/Sources/MaughamCore/TestWorkspace.swift:27-37`), so seven parallel workers never share a key or a remembered head. Three files: `device-key.blob`, `device-token`, `op-log-state.json`. A test that needs a specific identity or state injects it; nothing in a test reads the developer's real state.
7. **Verification never refuses to open a book** (spec §3). Quarantine is a classification plus a record; the ops that verify or are unsigned history are applied exactly as today, so `OpLogStorePartitioningParityTests`, `CrossMacMergeTests`, the claims suites and every derive test stay green untouched. A quarantined line is never applied and never deleted: it lives in `.maugham/conflicts/quarantined-ops/` beside the file quarantines, and the ONE new refusal in the tree is that a `.lines` record never returns.
8. **Every negative assertion runs the disable experiment** (remove the guard, watch the test fail, restore it, report the output in the task's summary): the chain-break quarantine, the after-remembered-head quarantine, the forged-seal rejection, the segment-signature mismatch, the two censuses' planted offenders. A test that passes with its subject deleted is not a test.
9. **Tripwire 33 on every new Mac/phone test**: no press-then-wait; History-pane copy is pinned as a pure static, like `HistoryPane.quarantineNotice(heldCount:)` (`Maugham/Views/HistoryPane.swift:232-235`).
10. **Every task touching MaughamCore runs all three gates** — the package's `swift test`, `./scripts/test.sh`, `./scripts/test.sh phone` — before its commit. `./gen.sh` after adding any file (a stale project runs 0 tests for a new file with no error).
11. **Nothing under `Maugham.xcodeproj/`, `.agents/`, `.codex/`, `AGENTS.md` is committed.**

**Contract — `DeviceIdentity`** (`public struct DeviceIdentity: Sendable`):

- `public static let current: DeviceIdentity` — `load(from: DeviceState.directory)`, with a fatal-free fallback: if even the token cannot be written, an in-memory random token (the process still writes; the id is not stable; log it).
- `public static func fingerprint(of publicKey: P256.Signing.PublicKey) -> String` — SHA-256 hex over `x963Representation`. Also the one place the token→fingerprint derivation lives (`SHA256(token)`), so a P2 certificate can name a device by the same string.

## Task 3 — `OpLogChain`: the wire format and the verifier, pure

**Files:** new `Packages/MaughamCore/Sources/MaughamCore/OpLogChain.swift`; tests new `Packages/MaughamCore/Tests/MaughamCoreTests/OpLogChainTests.swift`.

**Contract** (`public enum OpLogChain`, every member `nonisolated static`, no I/O, no clock — `at` is a parameter):
- `lineHash(_ line: Data) -> String` — SHA-256 hex; strips ONE trailing `0x0A` if present.
- `chainedLine(elementJSON: Data, prev: String?) -> Data` — inserts `"prev":"<prev>",` after the leading `{` when `prev != nil`; `elementJSON` must begin with `{` (precondition, tested). No trailing newline.
- `isSealLine(_ line: Data) -> Bool` — prefix `{"seal":`.
- `struct Seal: Codable, Equatable, Sendable { at: Date; head: String; key: String; pub: String; sig: String }` with `static func line(head: String, identity: DeviceIdentity, at: Date) throws -> Data` (signs the head's 32 bytes via `identity.sign`; throws `.unsigned` when it cannot) and `static func parse(_ line: Data) -> Seal?`; `func verifies() -> Bool` — the `pub` decodes as x963, `DeviceIdentity.fingerprint(of:) == key`, and `sig` verifies over the head bytes. Self-contained: a seal carries what verifies it, so P2 adds trust without a format change.
- `prev(ofLine line: Data) -> String??` — outer nil when the line is not a JSON object / unparseable, inner nil when the object has no `prev`. Read by inspecting the first key textually (the format fixes its position) — not a full JSON decode; a legacy line whose FIRST key is not `prev` has no prev.
- **`verify(bytes: Data, trusted: (String) -> Bool, rememberedHead: String?) -> Verification`** where `Verification` is `struct { lines: [Line]; head: String? (the hash of the last applied line); legacyCount: Int; verifiedCount: Int; unsealedCount: Int; foreignSealCount: Int; quarantined: [Data]; breakReason: BreakReason? }`, `Line = (bytes: Data, kind: .op | .seal, state: .legacy | .verified | .unsealed | .unsignedHistory | .quarantined)`, `BreakReason = .prevMismatch(lineIndex:) | .unchainedAfterChain(lineIndex:) | .sealHeadMismatch(lineIndex:) | .sealSignatureInvalid(lineIndex:) | .afterRememberedHead(lineIndex:)`. The walk: running head `h` starts nil; an op line with `prev`: `prev == h` else break; an op line without `prev`: legacy only while no chained line or seal has been seen yet in these bytes, else break; a seal line: `head == h` else break, `verifies()` else break, and its span (every `.unsealed` line since the last seal) becomes `.verified` when `trusted(seal.key)` and `.unsignedHistory` when not; then `h = lineHash(line)`. **The remembered head**: when `rememberedHead != nil` and some line's hash equals it, every line after that one is `.quarantined` with `.afterRememberedHead` **even though it chains** — that is the case an agent that computes `prev` correctly is caught by; when `rememberedHead != nil` and NO line hashes to it, the walk proceeds as if it were nil (the crash-window case; the caller adopts the file's head — Task 4 says when). From the first break on, every line is `.quarantined`. `quarantined` carries the raw bytes in file order. Blank lines are skipped, never counted, never break.

**Requirements — the tests are the spec of the walk**, each with its disable experiment: a legacy-only file is all `.legacy` with a head; legacy then chained then a trusted seal → the chained span `.verified`; an untrusted seal → `.unsignedHistory`; lines after the last seal `.unsealed`; a line with a wrong `prev` and everything after it quarantined; an unchained line after the chain began quarantined; a seal whose `head` is off by one line quarantined; a seal with a flipped signature byte quarantined; a seal whose `key` does not match `pub` quarantined; a line whose bytes were altered after the fact breaks the NEXT line's `prev` (the tamper case); `rememberedHead` mid-file quarantines the correctly-chained tail after it; `rememberedHead` absent from the file changes nothing; round trip `chainedLine` → `prev(ofLine:)`; `lineHash` ignores exactly one trailing newline. Property test (200 trials, seeded): a randomly generated chain of N lines with seals every K verifies whole, and flipping any one byte in any line quarantines from that line (or the next) on. Package gate; Mac and phone gates untouched but run (constraint 10).

Commit: `feat(core): OpLogChain — chained lines, seal lines, and the pure verifier that classifies every line`.
