# P3 follow-ups (#74, #75, #76) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the yield gaps in the editor's checkbox click and in the doors behind it (#74), make the every-100-lines seal best-effort (#75), and fix the doc drift P3's release left behind (#76).

**Architecture:** Each fix sits where its decision already lives. The editor's checkbox click asks the same membrane as a keystroke. `InlineToggleUndo` and Recovered History's Append get a yield-aware posture check from their hosts, because only `DocumentStore` knows about *Edit Anyway*, and the posture has to keep honouring it. The interval seal follows the rule every other seal site already follows: sealing never costs the writer an op that has already landed. The docs are corrected in place, and the hard-coded counts become "count the cases".

**Tech Stack:** Swift, AppKit/SwiftUI, XCTest; MaughamCore SPM package.

**Spec:** issues #74, #75 and #76 (filed from audit PRs #64, #68, #69 and #71), as corrected by this plan's research (below).

## Research corrections (read before Task 1)

- **#74 F1 was overstated.** `HistoryPane` builds `RecoveredHistorySheet` with `mayAppend: offersRewind(documentStore?.posture(forDocId:))` (`HistoryPane.swift:1166`), and a yielding posture refuses `.writeText` (`Posture.swift:207`). So the sheet already hides Append under a yield. Only the press-time door, `static mayAppend(to:)` (stamp only), lags. It is reachable during the frame after a trust change, before the view redraws. Low.
- **New and reachable: the editor's checkbox click ignores the membrane.** `EditorSurface.mouseDown` (`Maugham/Editor/EditorSurface.swift:586-597`) calls `checkboxToggleHandler` with no `lockEditing`/`isTranslationReview` check, and `InlineToggleUndo.perform` guards only `doc.mayWriteItsText` (the stamp). On a book author's Mac over a piece someone else started and nobody has claimed (the stamp allows it; the posture yields, Ruling U), clicking a checkbox in the visibly locked editor writes a paragraph. Under Option A that claims the piece and sets the starter's held words aside on every Mac. The root's owner-yield, a read-only iCloud share (`lockEditing` is posture OR share) and the translation view (`isTranslationReview`) are bypassed the same way.
- **The other permit-only callers are already posture-gated:** Find/Replace (`ProjectStore+Search.swift:226`, `settledPosture` before the stamp), the rename sweep (`ProjectStore+Structure.swift:610`, `mayWrite`), and statements (`mutateStatementText`; statements are not starter-yielded pieces). Out of scope.
- **The Tasks pane's toggle is hidden by posture** (`TaskRowVerbs.decide`, `textIfNeeded = posture.allows(.writeText)`). Its door is still `InlineToggleUndo`, so Task 2 covers it.
- **`TrustVerdict` carries associated values**, so it can't be `CaseIterable`. #71's "CaseIterable + DocSync grep" promotion is dropped; Task 4 removes the hard-coded numbers.

## Review Focus

1. **Edit Anyway must still work.** After the writer presses *Edit Anyway* on a yielding piece, the checkbox click, its ⌘Z and Recovered History's Append must all write again. The posture is the one input that knows about the override; a fix that reads `permit.unsettledStarter` directly breaks this. (Task 2 tests it.)
2. **A locked click must still be an ordinary click.** It falls through to `super.mouseDown`, so it places the caret, selects, and allows copying. It is not swallowed. (Task 1.)
3. **Review mode is unchanged.** `isReviewMode` is the writer's own render toggle; the Tasks pane allows toggling in the same posture, so the editor checkbox stays live in review mode. Do not gate on `isReviewMode`. (Task 1 pins it.)
4. **Undo crossing a yield:** flip, then the posture starts yielding, then ⌘Z. The undo is refused and said (`declineUndo`), and the paragraph keeps its flipped text. (Task 2.)
5. **A failed interval seal retries:** the counter is not reset on failure, so the next append asks for the seal again. (Task 3.)
