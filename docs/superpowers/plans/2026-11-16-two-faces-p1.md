# Two faces, plan 1: To resolve and Brief take Author's and Review's right column — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In Author and Review, the right column offers two panes, **To resolve** and **Brief**, built from the existing notes, check, to-do and intent views; every other pane stays reachable by its ⌘⌥ key.

**Architecture:** Two new `DetailSegment` cases through the existing "add a persona pane" extension point. `ToResolvePane` is a head (the pass ladder and a single-choice source filter with counts) over the three existing panes, unchanged, as its bodies. `BriefPane` is an optional one-line field over the existing intent `StatementPane`. The personas, `ProjectWindow`, the centre column and all storage are untouched.

**Tech Stack:** Swift, SwiftUI, XCTest. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-16-subject-resolve-brief-shell-design.md`. Read "To resolve", "Brief", "Constraints" and "Anti-goals" before starting.

**What this plan deliberately does not do** (later plans, re-derived against this one once built): one interleaved list grouped by paragraph that follows the cursor; the letter at the head of the list; marks on the intent and the margin setting; the pulled-up thing; Decided folding to the newest few; scope at Book level beyond counts; any tree, centre, persona-removal or shortcut-remap work. In this plan To resolve shows **one source at a time**.

## Global Constraints

- Read `Maugham/Views/AREA.md` before editing anything under `Maugham/Views/` or `Maugham/Models/`. Its recipe "Add a persona pane (a `DetailSegment`)" is the procedure Tasks 3 and 4 follow.
- Line numbers below were verified at commit `0c575a88`. Re-locate every symbol by name before editing.
- Run `./gen.sh` after adding any source or test file. Test with `./scripts/test.sh`; before the final commit of Task 6, `./scripts/test.sh full`. Never a raw `xcodebuild test` or `swift test`.
- No new code compares a `Persona` by name or asks a new persona predicate (`TripwireGrepTests.test_noViewComparesAPersonaByName`). Nothing in the two new panes takes a `Persona`.
- No store, disk or walk work in a `body` (tripwire 4): counts and statement text are read in `.task`.
- A pane that can show a `ContentUnavailableView` chains `.frame(maxWidth: .infinity, maxHeight: .infinity)` on it and its outer `VStack` takes `.frame(maxWidth: .infinity, maxHeight: .infinity, alignment: .top)` (tripwire 15).
- Ask `Posture`; never compare a permit rung (tripwires 47, 51). Hide a refused verb, don't disable it.
- No new file writes pass state. The ladder in To resolve calls the `onSetPassState` closure `DetailPaneToggle` already holds, so `PersonaPaneRegistryTests.passStateWritingFiles` keeps its four members.
- Every pane fits a 240pt column less `RightColumn.resizeHandleWidth` with no `minWidth` (`RightColumnPaneWidthTests`). Toolbar labels that can grow are icons or truncate.
- Nothing AI-produced is drawn in the editor or its chrome (constitution must-not #2, ADR 0027). This plan draws nothing there at all.
- Writer-facing copy is the writer's register: "To resolve", "Brief", "Notes", "Check", "To-do". Never "segment", "diagnostic" or "annotation" in new copy.
- Commit after each task. Messages follow the repo's style (a plain sentence saying what is now true) and end with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Review Focus

1. **No document is open** (the project row, a group, a collection's reference piece, an empty project): To resolve shows whole-book counts and no pass ladder; Brief shows the book's intent and no line field; neither crashes or shows another piece's data. → Tasks 2, 3, 4.
2. **A piece the writer may not change** (reviewer permit, view-only share, someone else's piece): the line field is read-only text, the ladder offers no rulings. → Tasks 3, 4.
3. **A window restored with a pane that has left the registry** (`UIState` remembering `.diagnostics` for Author): it opens on To resolve, and ⌘⌥D still opens the old pane. → Task 5.
4. **Fast switching between pieces:** counts shown always belong to the piece on screen; a late read for the previous piece is dropped. → Task 3.
5. **Large counts in a narrow column** (hundreds of notes at 240pt): the filter row still fits and nothing widens the column. → Task 3.
