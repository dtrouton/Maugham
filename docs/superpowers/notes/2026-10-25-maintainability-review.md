## 2. Emergent / cross-cutting findings (the synthesis payoff)

The four historical emergent-bug classes were checked across every map boundary. Four collisions survived to verified findings; the rest were run to ground as actively-guaranteed-correct (§6).

### E1 [Medium] The phone reader *mangles* report-element syntax — ADR 0033 §5 "never mangles them" is only partly true — **VERIFIED against source**

Three maps collide: **(A2)** no test feeds a footnote/figure/citation/section-label form through the phone's `MarkdownBlocks.parse`; **(T-B)** the phone uses the shared `MarkdownBlockParser`, **not** `ManuscriptBlocks`, so it never runs `ManuscriptAttributes.split` that strips `{#…}`; **(T-A)** the actual render therefore leaks internal syntax. Verified: `MaughamPhone/Read/DocumentReaderView.swift:116` renders a heading as `Text(text)` verbatim, so `# Heading {#sec:x}` shows literally as "Heading {#sec:x}"; `:120-121` sends a figure line `![Cap](../research/x.png){#fig:label}` through `inlineEmphasis` → `AttributedString(markdown:)`, which eats the image and leaves a stray `{#fig:label}`; a table caption line shows raw `{#tbl:x}`. This is **live today** for any manuscript that already contains these forms (ADR 0033: existing manuscripts "read as the same text … now also mean something"). It is consistent with the ADR's staged status (editor styling = plan 3, publishing = plan 2), but the §5 promise "shows the other forms as plain text and **never mangles them**" is stronger than the code. This is the cross-surface-contract-drift + output-read-back class (the derived `.md`'s Pandoc attributes read back by a surface that can't interpret them). — `MaughamPhone/Read/DocumentReaderView.swift:116,120`, `MaughamPhone/Read/MarkdownBlocks.swift:34` — fix-shape: in the shared parser/adapter strip a trailing `{#…}` attribute block for display, and treat a figure line as its own non-image block that shows the caption; reconcile ADR §5 to say the phone strips labels (not "never mangles") — effort: **M**.

### E2 [Medium] A whole pipe table is one op-log paragraph, so concurrent cross-device cell edits resolve by whole-table last-writer-wins — **VERIFIED against source**

ADR 0033 §4 ("every element is one ordinary paragraph") is correct and load-bearing for the op log — but it collides with the op-log merge granularity (T-A map × the op-write data flow). `Document.setFullText` records a per-paragraph `ParagraphChange` whose `next` is the **whole** paragraph text (`Maugham/OpLog/Document.swift:1138`); for a 30-row pipe table that is the entire table on every cell keystroke, and cross-device resolution is whole-table LWW. Two devices editing different cells of the same table lose one side's edits. For prose the merge atom is a sentence-sized paragraph; for a table it is the whole table, and the ADR does not call this out. Guarded today only by the single-editor ethos (the same guard that makes all op-log LWW acceptable), which is why it reads as correct — the blast radius is the surprise. This is the two-correct-features-interacting class (one-paragraph-per-element × per-paragraph merge). — `Maugham/OpLog/Document.swift:1138` + ADR 0033 §4 — fix-shape: document the table merge-unit limit explicitly in ADR 0033 / `OpLog/AREA.md` (sub-paragraph table merge is a genuine L and almost certainly not worth it under single-editor ethos) — effort: **S** (document) / **L** (sub-paragraph merge).

### E3 [Medium] `ManuscriptIndex` (Core) is dead, and label/citation/footnote diagnostic logic now lives in three parallel implementations — the dead one with a weaker figure-path rule — **VERIFIED dead against source**

T-B traced the report-element diagnostic path and found `ManuscriptIndex` — the Core type `Maugham/Packages/.../AREA` and ADR 0033 §5 read as the intended single "project-wide index + diagnostics" home — has **zero production callers**: `grep ManuscriptIndex` outside its own file hits only `ManuscriptIndexTests` and the `DocBudgetTests` census (coordinator-verified). The editor diagnoses via `ReferenceIndex` + `ManuscriptChecks`, publish via `PublishResolution`; the same duplicate-label / unknown-key / unresolved-crossref / footnote-fixed-point logic is implemented **three** times. Worse, the dead copy's figure-path check (`ManuscriptIndex.isNotLocal`, `ManuscriptIndex.swift:198`) flags only absolute paths and `scheme://` URLs — **not** `..` escapes or non-research folders — strictly weaker than the live publish-side `FigureImageResolver`. Harmless while dead; a trap the moment anything adopts it as "the canonical index." This is the silently-unwired-after-refactor + duplication class. (A1's "no dead code" conclusion was scoped to the newest parser/scanner/canvas API it enumerated and did not reach `ManuscriptIndex`; T-B's verified finding stands.) — `Packages/MaughamCore/Sources/MaughamCore/ManuscriptIndex.swift:42,198` — fix-shape: delete `ManuscriptIndex`, or make the editor and publish consume it as the one home ADR §5 implies (routing its figure check through `FigureImageResolver`'s rules if kept) — effort: **M**.

### E4 [Medium] Seven MCP tools read manifest doc paths without the `SafeRelativePath` clamp the sibling `DocumentTools` applies — **VERIFIED against source**

A5 found, and the coordinator verified, that `AnnotationToolHelpers.swift:63` resolves a manifest-supplied `path` with raw `projectURL.appendingPathComponent(path)` and feeds it straight to `Document.load` — while `DocumentTools.swift:144` resolves the *same kind* of manifest path through `SafeRelativePath.resolve(path, under: projectURL)`, with an explicit in-code comment: "a corrupted/hostile manifest must not be able to read a file outside the project root (A5)." The clamp is applied at the door someone remembered and absent at seven others: `AnnotationToolHelpers.swift:63`, `AddNoteTool.swift:59`, `TaskReadTools.swift:147` (all three → `Document.load`), plus `PaletteTools.swift:126`, `ReferenceTools.swift:215`, `ListAllLinksTool.swift:145`, `ProjectTools.swift:367` (reads). A `..`-bearing path in a hostile/corrupt synced manifest (a collaborator project) opened via MCP therefore escapes the project root. This is the classic shape — a gap hiding behind a neighbour's reputation for rigor — and the one net-new issue this surfaced. — `Maugham/MCP/Tools/AnnotationToolHelpers.swift:63` (+ the six siblings above) — fix-shape: a single shared `resolveManifestDocURL(path, projectURL)` helper routing every manifest path through `SafeRelativePath`, as `DocumentTools` already does — effort: **M**.
