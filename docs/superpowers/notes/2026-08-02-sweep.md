## 2. Findings (each triaged in §3; every finding coordinator-verified against source)

### S1 [Medium] Line-promotion has no writable-kind filter → a statement-marked card either throws a misleading error at commit or silently writes an unresolvable link (M1A × 1C collision, output-read-back-as-input)
`Promotion.resolvedArtifact` (Promotion.swift:1189-1194) accepts **any** mark whose title resolves in `ArtifactIndex` — which M1A widened to include statements (`stmt-` ids) — so `plan(.line)` (Promotion.swift:1010-1019) offers a line whose endpoint is a scrap promoted to Craft Intent (or a mark repointed by adoption). Two failure modes from the one missing filter:
- **(a) FROM endpoint is statement-marked** → `intoItemID = fromItem` (a `stmt-` id), and `performWikiLink` (PromotionPerformer.swift:559-562) resolves `intoItemID` only in `manifest.research`, where a statement id never lives → throws `PromotionFailure.artifactMissing(stmt-…)` at Commit with the message "the artifact this card produced is no longer in the project" — for an artifact that is a **live statement**. `blockedReason(.line)` does not catch it (the mark is not dangling), so preview offers it as valid.
- **(b) TO endpoint is statement-marked** (from is a real note) → `linkText = [[<statement title>]]` gets **written into the from-note** (Promotion.swift:1018-1019 → PromotionPerformer.swift:568), a link that no `titleIndex`/`resolveDocumentId` set contains, so it lands as permanent `wiki_unresolved` junk **silently**.

fix-shape: in `resolvedArtifact` (and/or the line-plan guard) require the mark's `ArtifactIndex.kind` be a writable research note / palette card, excluding statement-kind endpoints on both sides; teach `blockedReason` to explain the refusal. — Promotion.swift:1192 + PromotionPerformer.swift:559 — effort M. **Verified against source** (both files read; the ArtifactIndex-includes-statements widening confirmed by the tracer at Promotion.swift:344-373). *Calibrated from the tracer's High to Medium:* fails loudly on path (a), is niche on both (requires promoting a scrap to Craft Intent, then drawing + promoting a line off it), and loses no existing data — the rubric reserves High for data-loss/crash/broad breakage. Path (b)'s silent junk-link is the sharper half.

### S2 [Medium] `propagateWikiLinkRename` doesn't rewrite `[[…]]` inside statements → M1A widened the link READ but not the link MAINTENANCE (corroborated ×2)
`propagateWikiLinkRename` iterates only `Self.collectDocuments(in: manifest.structure)` (ProjectStore+Structure.swift:399); it never walks `manifest.statements`. Yet M1A's adoption carries legacy craft-intent bodies (which may contain `[[…]]`) verbatim into statements, and S1(b)/promotion can add more — and `list_all_links`/`find_references` were widened this window to **read** those statement links (the M1A whole-branch review's own "a migration may not silently cost a shipped capability"). So renaming a document silently flips a statement's `[[chapter]]` to `wiki_unresolved` while the graph tools keep listing it. The **research-note half** of this gap is pre-existing (since 1C-c2) and ADR 0026's Consequences records it as "recorded, not fixed"; the **statement half is new this window and undocumented** — ADR 0026 predates M1A and never names statements. — ProjectStore+Structure.swift:396-464 — fix-shape: extend rename propagation to statement `Document`s (via the `appendToStatement` open/transient seam, op-log never the `.md`) and research-note bodies, or explicitly document the statement half in ADR 0026 — effort M. **Verified against source** (the loop reads structure only) and **independently surfaced by both the spine-hunter and the tracer** — classic synthesis-over-maps: both maps carried "read tools scan statements; rename walks structure only," which only becomes a finding when the two facts are collided.

### S5 [Low] Scope-switch mid-mint loses the in-flight keystroke and leaves a spurious empty statement
Typing the first character into a never-before-used **project** intent fires `mintAndBind` → async `createStatement` + `Document.load`; clicking another binder row before the mint completes runs `reconcile` for the new scope, whose `target.release()` clears the draft (`draft = ""`), and the superseded mint's load returns `loadMayBind == false` and closes without binding — so the character is gone **and** `createStatement` has already committed an empty `intent.md` + manifest entry (`read_craft_intent` then reports exists:true / markdown:"" for project scope). Single-character loss in a narrow interleaving; the design otherwise prioritizes never losing words, so this is the one exception. — StatementEditorHost.swift:546-560 (mintAndBind) + :520 (reconcile `target.release()`) — fix-shape: have the superseded mint re-queue its `draft` instead of `release()` clearing it, or refuse the empty `createStatement` when the load is superseded — effort M.

### S6 [Low] NSImage image ingest mints the statement before the save can fail
`addImage(toStatement:kind:scope:image:)` calls `createStatement` before `ImagePasteHandler.save*`; on a `saveAndReference` throw the just-created empty visual-language statement is left behind. The `fileURL` arm (ProjectStore+StatementAssets.swift:83-95) validates **before** `createStatement` precisely to avoid this; the NSImage arm has no equivalent cleanup, so it violates the "a refused promotion/ingest leaves nothing behind" contract the rest of the seam honors. — ProjectStore+StatementAssets.swift:48-54 — fix-shape: delete the freshly-minted statement on a save failure in the NSImage arm — effort S.

### S7 [Low] Inbox→canvas image capture has no idempotency guard, unlike its palette sibling
A `.promoted` status-flip failure surfaces the error but leaves the inbox entry `.new`; a manual retry then re-runs `ingestCanvasAsset` (a **second** copy in `canvas_assets/`) and `CanvasCapture.send` (a **second** card). The palette sibling gained a dedup guard (`appendSensoryNote`, InboxStore.swift:435); the canvas send did not. — InboxStore.swift:390-397 — fix-shape: make the canvas send idempotent on retry (record the minted node id and reveal-not-recreate, or flip-then-send with rollback) — effort M.

### S8 [Low] CLAUDE.md's "count the arms in the wiring census" pointer counts the wrong thing
The Canvas cell tells the reader to "count the arms in `PromotionCommandTests`' wiring census" for how many subject kinds `Promote…` supports (prose lists 4: a scrap, a region, a line, an owned item node).
