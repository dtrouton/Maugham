## 2. Synthesis over the three maps (the sweep payoff)

**The collision: duplicated stranded-accept logic.**
- The tracer's map lists "stranded-accept logic exists twice with different rules": the manuscript's `RewindImpact.travelStatusChanges / strandedAccepts / returningAccepts`, and the figure's `FigureDocument.answeringStrandedAccepts`.
- The git pre-pass shows the RULING-57 hardening (34504b1..242625b) and the #128 work (18fb58c..e81c3c0) touched only the first copy.
- RULING-57 says the rule holds "for a full rewind and for a checkpoint revert alike". The checkpoint revert (`PartialRestorePicker`) drives both copies.
- The result is classic **two-correct-features-interacting / silently-unwired-after-refactor**. Each copy is internally consistent, but the parity fix landed in one. This is **W1**, and the same gap shows up as **W3** (the BEFORE count is manuscript-only) and **W4** (the two copies differ on which accepts to reopen, and on archiving).

**The second collision: the update schedule's new triggers.**
- The delta hunter's map ("wake fires before Wi-Fi is back") combined with the doc checker's ("`checkInBackgroundIfDue` guards only in-flight states") gives **U1**.
- The old 24 h loop had the same unguarded path, but it ran roughly once a day. Wake and activation make it routine.

**The third collision: two 9d changes on the Research-table host.**
- 9d made "keep the prior version" a precondition of every save.
- `close()` was written when the CSV write was the only gate, and it discards on failure.
- Together they give **R1**.

**Ran to ground negative:** see §5.

## 3. Findings (file:line + fix-shape + effort)

### Figure cell notes vs the manuscript's travel rules — #136

**W1 [High] A checkpoint revert puts an accepted figure suggestion's value back but leaves its note OPEN (RULING-57 not applied to figures). VERIFIED.**
- `answeringStrandedAccepts` only considers notes that are `.accepted` now (`Maugham/OpLog/FigureDocument.swift:1734`). It has no returning class.
- Scenario: accept before the checkpoint, ⌘Z after it, then a restore writes `next` back with a plain `figureCellSet` and the note stays open.
- Reject is then allowed: the guard covers `.accepted` only (`FigureDocument+Annotations.swift:105`).
- A re-Accept passes the changed-since check (`:171`) with `prior` = the suggested value, so its ⌘Z cannot reach the original.
- fix-shape: add a returning class (a restore cell-set writing the newest cell-carrying accept's `next` for an open, reverted suggestion becomes a `claudeAccept` with `sourceAnnotationId`), add `reaccepted` to `FigureRestoreNotes`, and add a figure twin of `RewindReturningAcceptTests`.
- effort: **M**

**W2 [Medium] Stet or archive, then Reopen, leaves an accepted figure suggestion OPEN over its written cell. VERIFIED.**
- `FigureAnnotationOps.reopen(for:)` emits a plain reopen for `.stetted`/`.archived` (`Packages/MaughamCore/Sources/MaughamCore/Table/FigureAnnotationOps.swift:167-169`).
- Stet and archive take any status (`FigureDocument+Annotations.swift:282,294`).
- The phone reaches the same state through `PhonePosture.reopenVerb` → `AnnotationWriter.makeReopen`.
- fix-shape: such a note returns to accepted (status-only) or is refused as `acceptedInTheTable`; add a truth-table test covering the Mac and the phone.
- effort: **S**

**W3 [Medium] The checkpoint revert's confirm sentence (RULING-28 BEFORE half) never counts figure notes. VERIFIED.**

**Merit-drops (recorded so the next sweep doesn't re-litigate them):**
- **`ResearchVersionStore.sweepLeftovers` deletes any device's `.staging-*` file older than 10 minutes** (`ResearchVersionStore.swift:279-280,460-465`). A staging file lives for under a second. One that is 10 minutes old is a crash's debris whichever device made it, and deleting it loses nothing that a version listing would show. That makes this a tripwire-17 wording tension, not a defect.
- **The #131 fix refills figure cards twice for this Mac's own CSV saves** (presenter plus host, `DocumentStore.swift:947-952` and `ResearchTableHost.swift:643`). This is a perf nit on a correct path.
- **A version meta's `content_hash` is written but never checked on `read`.** Versions are write-once, staged then moved, so there is no live mismatch path.
- **Promotion moves another device's version files with the item** (`ProjectStore+CollectionPieces.swift:702-718`). That is a move of the item's own history, as intended, not a seal or edit of another device's stream.
- **`liveResearchItemIds` returns nil on one unreadable Trash entry**, which blocks the orphan sweep. It fails safe: nothing is deleted.
- **`create_research_table` with only empty cells yields 1×1 rather than the blank 4×3 shape.** Cosmetic.
- **`FigureTableLayout` assumes `headerRows ∈ {0,1}`.** The UI offers a single header-row toggle and MCP's schema enum enforces 0/1, so there is no producer of 2+.
- **The phone hides a figure whose fold kind differs from its record's** (`PhoneFigureBook.swift:111-114`). This is the deliberate 9b I1 ruling.
- **A failed download after a successful fetch is not retried for 6 h**, because `recordCompleted` is stamped before the download. The old loop waited 24 h, and a manual check still retries.
