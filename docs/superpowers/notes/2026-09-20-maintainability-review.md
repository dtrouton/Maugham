## 2. Emergent / cross-cutting finding (the synthesis payoff)

**The trust gate is a seal-boundary gate, but the manuscript is built from every applied line — sealed or not.** Two facts collide across maps: (a) *P1 fact* — `OpLogChain.verify` classifies an op line with a valid `prev` as `.unsealed`, and `.unsealed.isHeldBack == false`, so `applied()` keeps it and it merges into the derived `.md`; (b) *P2a invariant, assumed* — "a stranger's writes are held pending admission." The gate that enforces (b) lives **only** in `case .seal` of `verify`; nothing maps an *unsealed* line to its file's device verdict. So a foreign device's writes-since-its-last-seal enter the book un-gated. Neither the bug-hunt nor either tracer's *findings list* alone tells the whole story — it is visible only when the seal-only trust consult (one map) is set against the "held pending covers strangers" invariant (another) and the `applied()` keep-rule (a third).

### F1 [High] A foreign (stranger/revoked) signed device's UNSEALED TAIL is applied to the manuscript, bypassing the admission/revocation gate — **VERIFIED against source**

`OpLogChain.verify` consults the `trust` closure **only** in `case .seal` (`Packages/MaughamCore/Sources/MaughamCore/OpLogChain.swift:804`). An op line with a valid `prev` is classified `.unsealed` with no key/device check (`OpLogChain.swift:760`); a seal, when reached, settles the `.unsealed` lines it covers to the verdict-derived state (`:812-816`). `.unsealed.isHeldBack == false` (`OpLogChain.swift:459`), and `JSONLAppendStore.applied` keeps every non-held-back line (`JSONLAppendStore.swift:210-213`) — so it reaches parse → derive → the clean `.md`. `classifyTail` never maps the file's device slug → `TrustVerdict` for the unsealed span (`OpLogStore.swift:626-684`). Consequence: a **signed** foreign device's writes since its last seal — up to `chainSealInterval−1` = **99 ops**, or its whole file before its first seal — merge into this device's manuscript regardless of whether that device is admitted; for a **revoked** device, post-revocation unsealed writes leak the same way (`RevocationSplit`/`readmitting` only re-judge *sealed*, `.quarantined` spans by opId). This is precisely tripwire 39's named SILENT direction ("a stranger applied … instead of HELD"). Held/pending/quarantined text does **not** leak (`applied()` correctly filters those) — the leak is exactly the `.unsealed` class.

**Scope discipline (what this is NOT):** an *unsigned* device (VM/CI) writing `unsignedHistory` that is applied-but-never-claimed is **by design** — P1's B3 world, ADR 0032:166 — so the "unsigned device's entire file" framing is not a defect. The defect is narrower and real: a *signed* foreign device's unsealed tail is applied with none of the holding its *sealed* spans receive. It self-heals once the source device seals that span (close/open-sweep/100-op cadence), so it is transient in steady state — which is exactly why it reads as correct and why the live-sync window (a second Mac writing now, before it seals) is the exposure. The design docs describe the hold model **entirely** in terms of "sealed span" (`Maugham/OpLog/AREA.md:660-689`, ADR 0032 §3/§6); the unsealed-foreign-tail case is addressed nowhere. — `Packages/MaughamCore/Sources/MaughamCore/OpLogChain.swift:743-816` + `JSONLAppendStore.swift:202-213` + `OpLogStore.swift:626-684` — fix-shape: attribute an unsealed op span to its file's device (the filename already partitions per device → device record → `TrustTable.verdict`) and HOLD/refuse it when that device is not `.mine`/`.admitted`, so authorship no longer depends on a seal existing — effort: **L**. **This may intersect P3's declared remit** (the P3 handoff lists "a durable trust event log" and "the per-span Apply exception" as owed) — worth Denver's ruling on whether F1 is a standalone fix or folds into P3, but it is not on P3's *written* list today (that list is about re-admitting a revoked device's *pre*-revocation history, the opposite direction).

### F2 [Medium] The hold/refuse model has ZERO test coverage for an unsealed foreign tail — every fixture seals first

`PendingLoadTests.makeStrangerFile` chains **and seals** the fixture ("chained and sealed under its key") before asserting held/quarantined (`Packages/MaughamCore/Tests/MaughamCoreTests/PendingLoadTests.swift:131-138`; the same at `:162,:208,:283`). Every stranger/revoked/retired test in the suite exercises a *sealed* foreign span; none exercises the `.unsealed` tail F1 is about. This is why F1 shipped green — the seam the tests pin is not the seam that leaks. — fix-shape: pin a case that a signed foreign device's unsealed tail is held/refused, not applied (drives the F1 fix and prevents its recurrence) — effort: **S** (test) once F1's mechanism lands.
