Smoked on one machine with `scripts/second-mac.sh` (the dev build under a substituted home is a second Mac: fresh enclave keys, its own registry cache, admission memory and MCP socket). Mac A = the ordinary dev app (`4fd28305…`), Mac B = the second (`20522482…`). Every find below was observed live and then confirmed on disk or in the source. Branch: `claude/signed-op-log-p2-smoke-wave-2026-09-17`.

**Passed:** root + device record at open, silently; cache rebuilt clean; author file chained and sealed per burst; MCP comments land in the assistant's own file under the assistant key, sealed at the next burst; checkpoint chained; a DELETED record restored byte-identical with a dated entry (History says so); stranger held as pending, no `.lines`; *Not now* re-asks; Admit applies held ops in-session and writes the admission memory; silent admission AT OPEN; revoke writes `revokedAt`/`revokedBy`/`highestOpIdSeen`; Re-admit clears them and everything applies; Claim on B writes its root + a claim adopting A.

## Finds

1. **An unverifiable registry record has no surface.** Tampered A's own root record (`label` edited): it is correctly left as found and contributes nothing, but People & Devices then shows this Mac as *not yet admitted* and NOTHING in the app lists the record. P2 spec §6 promised malformed records a surface; no production view reads `Registry.malformed`. **Fix:** a *Records that don't verify* section in People & Devices (whose record, the reason in the writer's words); when the record names THIS Mac the row says so instead of *not yet admitted*; a **Restore** verb when `RegistryCache.rawBytes(of:for:)` still holds the last verified bytes — a deliberate press, through the cache's existing restore door (tripwire 41 holds); listed only when nothing is remembered.
2. **One Mac reads as three rows.** Header, person and device all say *Denver's MacBook Air*, because `RegistryPresence` labels the root PERSON with the machine name. **Fix:** the root's label defaults to the account's full name (`NSFullUserName()`, falling back to the machine name when empty — a LABEL, not an identity; tripwire 35 is about device ids); the header names no device when the root is this Mac (*You are the root of this book's chain. This Mac's code is 4FD2.*); the *this Mac* badge on the device row only, the person row says *you*; no disabled Revoke on a root's row (a root is never revoked) — remove it.
3. **No way to change a label after admission.** **Fix:** *Rename…* on any person row the root admitted, and on the root's own — `RegistryAdmission` gains the verb, re-signing through `RegistryWriter.resign` so unknown fields survive; `AdmissionMemory` follows the new label; through `PeopleAndDevicesConfirmation` like every other verb; a dated trust event if `TrustEvents` can derive one without a new record kind (say so if it cannot — do not invent a field).
4. **A remembered device arriving MID-SESSION is asked about again.** Decision B2 is once per device. `RegistryPresence.admitRemembered` runs only in `DocumentStore.open`; `AdmissionModifier`'s refresh uses the memory to pre-fill a label and puts the sheet up anyway. Mid-session arrival is the ORDINARY case (a window open for days, the phone syncing in). **Fix:** the refresh admits remembered devices first (the same verb, then `invalidateTrust`), and only a device this Mac has never labelled reaches the sheet. Pin: a remembered device's span arriving after open raises no request and is applied.
5. **Revoking strips everything the device EVER wrote, including what was applied.** B's first op IS the revocation's `highestOpIdSeen`; after the revoke it is filed *may be late sync, or may be backdated* and refused with the rest. The spec says only spans *arriving later* are held; the smoke script says earlier work stays. **AWAITING DENVER'S RULING** — recommended: opId ≤ mark stays applied, opId > mark is refused as *after revocation*; the late-sync/backdated distinction returns in P3 with a real Apply. Do not build until ruled.
6. **The set-aside count is wrong.** *6 changes set aside* for 2 ops: seal lines are counted as changes; B's first op is in TWO records (the span split differently on two loads — `[op1, seal1]`, then `[op1]` + `[seal1, op2, seal2]`); `seal1` is filed in the *after revocation* half although it seals the earlier op. **Fix:** count OP lines only, deduplicated by `op_id` across records (the pending counts already count ops only — `OpLogChain.pendingByDevice`); the seal travels with the op it seals.
7. **The set-aside banner survives a re-admission.** The `.lines` records are permanent evidence (correct), so the sentence counts them forever — but after Re-admit those ops are APPLIED, and *set aside* is no longer true of them. **Fix:** the sentence counts only records holding an op that is not currently applied; the disclosure still lists every record.
8. **History's *Set-aside records* chevron blanks the whole window.** Main thread idle (sampled) — not a hang. The rows are ~130-character unbreakable filenames in a `Text` with no line limit inside the right column; the pane's ideal width runs to thousands of points and `NavigationSplitView` resolves every column to nothing (the failure class CLAUDE.md's Canvas cell records for `hiddenDetailColumn`). **Fix:** `.lineLimit(1)` + `.truncationMode(.middle)` and no ideal-width growth from the list. Pin WINDOWLESSLY: the pane's fitting width with a 130-character record name is bounded. `InboxPane` has the same sentence — check it has no such list.
9. **A root that ADOPTED mine is not listed, so the two-root merge cannot be completed.** After B's Claim (its root + a claim adopting A's), A's People & Devices shows nothing of B and offers no Merge; A's cache `claimants` is empty. A claimant is recorded only when a foreign root ADMITS one of my keys or a `signerChanged` fault names me (`TrustResolution.resolveVerified` / `recordRefusedClaimants`); a claim record whose `adopted` names my root is neither. The smoke script's step 19 (two self-rooted Macs, no claim at all) would show nothing either. **Fix:** any verified self-signed root in the registry that is not mine and that I have not adopted is a claimant — by a claim record adopting my root, or simply by being a second root in my book — listed with Merge, under the same `canMerge`/`whyNotMergeable` rule. Decide in ONE place (Core, beside the existing two claimant rules), not in the view.
