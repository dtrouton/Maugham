## 3. Findings this window (all source-verified)

### 3.1 The `metadata.language` seam — two Medium siblings (both new this window)

Both findings share one root: **`config.metadata.language` is validated nowhere** (`PublishConfigValidator` guards `languageOverrides.keys`, imprint names, template basenames, `outputs.directory`, and `filename_template` for traversal — but has no rule on `metadata.language`; grep of `PublishConfigValidator.swift` returns no match). It is writer/Claude-settable through the `set_publish_config` MCP tool (`MCPTool.swift:62`). Before this window it never reached a filename or an identity decision (a plain source compile had no language token; a single translated body draws its tag from the *validated* `language`/`languages` params). The P2 `LanguageSet.identity` concept — `bodies.map { $0 ?? sourceTag }.joined("+")`, `sourceTag = config.metadata.language` — promoted it into both roles at once.

- **F1 [Medium] `config.metadata.language` flows UNSANITIZED into the multi-body output filename, enabling a path escape out of `Exports/` on any bilingual/source-inclusive compile.** `LanguageSet.identity` joins `sourceTag` (=`config.metadata.language`) raw (`LanguageSet.swift:84`; `sourceTag` set at `CompileOrchestrator.swift:227`). That identity is passed as `language:` to `OutputFilenameBuilder.make` (`PDFCompiler.swift:340`, EPUB mirror), where `sanitizeForFilesystem` is applied ONLY to `title` and `label` (`OutputFilenameBuilder.swift:44,48`) — the `{language}` token replacement and `insertBeforeExtension` insert the value raw (`:79,92-108`). The file is then written via `exports.appendingPathComponent(filename)` + `moveItem` (`PDFCompiler.swift:239,249`). **Tension the code itself flagged:** the *anchor/build-file* path defended against exactly this unsafe tag (`fileTag` ordinal fallback, `PDFCompiler.swift:305-314`, whose own comment names `metadata.language` as "free-form config text") — the defense was applied one layer too shallow, missing the output filename. Repro: `set_publish_config {"metadata":{"language":"../../evil"}}` (passes validation) then `compile(languages:["source","sr"])` → identity `"../../evil+sr"` → PDF written outside `Exports/` (and recorded as the catalog `Publication.language`, which republish then reproduces). — `Maugham/Publish/OutputFilenameBuilder.swift:44-108` / `LanguageSet.swift:83-84` — fix-shape: validate `metadata.language` with `TranslationRecord.isValidLanguageTag` in `PublishConfigValidator` (mirroring `language_overrides`), AND/OR run `sanitizeForFilesystem` over the `language`/`imprint` tokens inside `OutputFilenameBuilder.make` so filename safety stops depending on every upstream field being pre-validated — effort: S.

- **F2 [Medium] `Republisher` derives `sourceTag` from the UNFOLDED staged config, not the imprint-resolved one, so an imprint that respells `metadata.language` mis-reconstructs its bodies on republish.** `Republisher.swift:170` reads `let sourceTag = stagedConfig.metadata.language`, but imprint `metadata` is an RFC 7396 merge-patch fragment (`PublishConfig+Imprints.swift:93,119` — `result.metadata = merging(metadata, with: layer.metadata)`), so an imprint can respell the source language. The compile door reads the *resolved* config's tag (`CompileOrchestrator.swift:227`) and the snapshot records `languages` with that resolved tag (`CompileOrchestrator.swift:711`); at republish, `imprint = prior?.imprint` is already known (`Republisher.swift:183`) and `foldingBase` *does* resolve staged config against it (`:545`), but the `sourceTag` at `:170` does not. Result for an imprint with e.g. `metadata.language:"es"` over an `en` book: the source body (recorded as `"es"`) fails the `substitute(tag)==sourceTag` test against `sourceTag=="en"`, is treated as a *translated* edition, and the republish either refuses at the coverage gate or mints the wrong identity. **Narrow trigger** (imprint respelling the source language + a multi-body republish; imprints shipped only this window, likely no real usage yet); no data loss. — `Maugham/Publish/Republisher.swift:170` — fix-shape: derive `sourceTag` from `stagedConfig.resolved(imprint: prior?.imprint, pieceIDs:)` (reorder imprint resolution above the `LanguageSet` build), mirroring the door; add a republish test with a language-respelling imprint — effort: M.

**Merit-drops (recorded so the next sweep doesn't re-litigate):**
- **`LanguageSet.identity` is order-sensitive** (`["en","sr"]`→`"en+sr"` ≠ `["sr","en"]`→`"sr+en"`, `LanguageSet.swift:82-85`) — **by design, not a defect.** Per spec §2 the bodies render *sequential and unrotated*, first body's title page and metadata lead the document, so English-then-Serbian and Serbian-then-English are genuinely *different artifacts*. The collision guard correctly not firing across a reorder is the identity system telling the truth. (Reported Low by the bug-hunt; dropped on this reasoning. Worth one clause in `LanguageSet` doc that body order is part of edition identity — folded into F2's test rather than tracked separately.)
- **`relativePath(_:from:)` triplicated** across `CompileOrchestrator` (866-870), `Republisher` (639-643), `OutputFilenameBuilder` (483-485) — in sync, trivial; a private free function would remove three copies, but consolidating three 4-line path helpers is negative-value churn against a stable snippet.

Negative-value.
- **Desk in-flight line joins request tags with `" + "`, settled line shows identity `"EN+SR"`** — cosmetic; running line describes what was *asked* (pre-reconciliation), settled line the *identity*. Intended, not drift.

## 5. Refuted / clean suspicions (so the next sweep doesn't re-chase)

- **The "one door" imprint seam leaks** — **REFUTED**: `PublishConfig.resolved(imprint:pieceIDs:)` (`PublishConfig+Imprints.swift:68-113`) is the sole imprint-aware transform; every downstream consumer (`OutputFilenameBuilder`, PDF/EPUB compilers, `TranslationCoverage.gateEveryTongue`, `snapshotStore.capture`) takes NO imprint arg and reads the plain resolved config (signature-verified by the tracer; grep-enforced by `TripwireGrepTests`' census). `placeOf`/`notPlaceOf` take an imprint *string* but only to format a refusal sentence — not resolution. The orchestrator threading the imprint *name* as an identity/scoping key is not a second resolution path.
- **Display surfaces can disagree about a compiled book's identity** — **REFUTED**: the preview header, Exports footer, and desk completed-line all read the ONE `PublishPreviewCentre.parts(for:)` (`:257`) off `publication.language`. Literally one function, not three spellings.
- **The `{language}` filename token can collide between a single-tag and a joined `en+sr` compile** — **REFUTED**: both draw from the same `set.identity`; the four identity components agree at catalog/mint/collision/filename by construction.
- **The version counter bumps wrongly across source-vs-edition or imprint-vs-book** — **REFUTED**: source takes `config.nextVersion` (resolved: imprint's own or inherited); an edition pins an existing source version scoped by `isSourceEdition(sourceTag:)` AND `imprint==imprint` (`CompileOrchestrator.swift:366-441`); the bump lands in `imprints[name].nextVersion` for an imprint, top-level otherwise, and saves the raw `loaded` config so shared config isn't flattened (`:823-836`).
- **The coverage gate blocks on the first tongue only / drops a blocked tongue** — **REFUTED**: `gateEveryTongue` loops `translatedTags` (source body never gated), tags every diagnostic `[tag]`, accumulates ALL blocked tongues and fails whole (`TranslationCoverage.swift:194-221`).
- **Republish reproduces the wrong body set** — **REFUTED for the common case**: `recordedTags = snap.languages ?? prior.language.split("+")`, the staged `config.json` is the writer's *unfolded* config read off disk with an explicit refusal when unreadable, `foldingBase` folds each body from the resolved staged config with the minted republish version. The one gap is F2 (imprint respelling the source tag) — narrow, filed.
