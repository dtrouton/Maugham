## 2. Emergent / cross-cutting finding (synthesis over maps)

**Theme: the round-ring depth is a load-bearing number with no single owner, and it just proved it.** The doc-truth agent found two unfixed copies of a "five vs six checks" off-by-one; the compiler tracer, independently, recorded as an *invariant observation* that `roundHistoryDepth = 5` (`DiagnosticsStore.swift:388`) is "a bare Swift constant with NO test extracting it and cross-checking prose against it, unlike the tool-count / DetailSegment / shortcut patterns." Colliding those two maps is the finding: **the same arithmetic is independently restated in prose across five files** (`CLAUDE.md`, `docs/guide/compiler.md`, `docs/guide/review-passes.md`, `docs/roadmap.md`, `Maugham/Compiler/AREA.md`) plus the code constant, and `33af6f3` fixed only three of the five. Neither agent's *findings list* alone surfaces the general shape — the tracer flagged no defect (the code is right), the doc agent flagged two instances; the synthesis is "this number has no guard and therefore will keep drifting," which is the enforcement finding E1 below.

### E1 [Medium — enforcement gap] The round-ring depth / "six checks" prose has no `DocSync`-style guard, and drifted into two docs in one milestone — VERIFIED
The `DocSyncTests` firewall parses source directly and cross-checks docs for the tool count, keyboard shortcuts, `DetailSegment` cases, and canvas calibration figures (each with a planted-offender self-check) — but it was never extended to numeric constants embedded in narrative prose. The round-ring number is exactly such a constant, and `33af6f3` ("the document remembers six checks, not five") proves it can drift: it corrected three files and missed two. — fix-shape: add a `DocSyncTests` case that extracts `roundHistoryDepth` from `DiagnosticsStore.swift` and asserts the doc set's "five/six finished checks" phrasing agrees (mirroring the tool-count pattern + a planted-offender), which closes D1/D2 permanently rather than by hand — effort: S–M.

### D1 [Medium — doc-truth] `Maugham/Compiler/AREA.md:224` still asserts the round-ring off-by-one `33af6f3` fixed — VERIFIED
The cell reads: *"capped at `roundHistoryDepth` (5) — every pass files into the same ring, so **five finished checks in Line push a Structural round out of it** exactly as five more Structural checks would."* This is false: the code keeps **6** finished checks (the 5-deep `rounds` ring **plus** the standing run, which `latestRound` reads *before* the ring — `DiagnosticsStore.swift:388,411,427`; `replace` files only the *superseded* run into the ring, `:197,213-214`), so a round survives five later checks and ages out on the sixth. This is the more serious of the two because (a) CLAUDE.md's Compiler row explicitly directs readers here ("**Read `Maugham/Compiler/AREA.md`**"), and (b) it states the *true* constant (`5`) adjacent to a *false* conclusion in one sentence — a skimmer confirming "still 5?" sees it confirmed and misses the wrong arithmetic. It is precisely the `•→✓` sibling-doc-sweep miss that CLAUDE.md Default-Workflow rule 10 exists to prevent, applied faithfully to three files and missing the one next door. — fix-shape: apply `33af6f3`'s wording ("the document's memory of its last SIX finished checks — the 5-deep ring PLUS the standing run") — effort: S.

### D2 [Low — doc-truth] `docs/roadmap.md:240` (the M3 entry) carries the same off-by-one — VERIFIED
*"…computed against the document's **5-deep ring** of finished checks, shared across every pass rather than one ring per pass, so a pass pushed out of it by other passes' rounds reopens at round 1."* The "5-deep ring" undercounts the six-check memory and names the ring as the comparison basis. Lower than D1: it's a historical milestone entry, not a consulted reference, and the sentence's "reopens at round 1" claim is itself correct. — fix-shape: same wording fix as D1 — effort: S.
