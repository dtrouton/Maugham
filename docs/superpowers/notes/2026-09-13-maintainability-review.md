## 2. Emergent / cross-cutting finding (synthesis payoff)

**Theme: the signed op log is bulletproof on the trust/forge axis and has a cluster of minor crash-window / write-path robustness gaps.** Five agents (A1, A5, A6, T-A, T-C) read this subsystem end-to-end and converged on the same shape — the *authentication and tamper-evidence* machinery is exceptionally careful (no Critical/High from any of them; every forgery path closed), but the *durability-around-a-crash-or-cancel* edges have five independent small holes, all writer's-own-data, none a normal-operation data-loss bug. The Medium leads the cluster; the four Lows (M2/M3/M4 below plus the torn-tail append) share its seam. No single agent's findings list showed the cluster — it is visible only when A6's Medium, T-A's remembered-head coupling, and A5's torn-tail gap are laid over one another on the write/rotation/crash-window seam.

### F1 [Medium] The 100-line interval seal in `OpLogStore.append` throws *after* the op has durably landed, desyncing the live annotation mirror — VERIFIED against source
`OpLogStore.append` writes the op durably (`OpLogStore.swift:605-607`), then increments `linesSinceSeal[url]`, and on the 100th line calls `if try await sealChain(docId:by:) { … }` (`:629`) — whose throw (an `NSFileCoordinator`/write error inside `appendSeal`→`chainedAppend`) **escapes `append` even though the op is already on disk**. This is the one seal site in the codebase not wrapped in best-effort do/catch: `Document.flushBurstNow` (`Document.swift:1198-1203`, with the invariant stated verbatim: *"sealing is maintenance, and it must never cost the writer the burst that has already landed"*), `TranslationStore.appendBatch` (`TranslationStore.swift:164-172`), and `Document+Tasks.swift:229` all wrap theirs. The manuscript **burst path is immune** — `flushBurstNow` calls `sealChain(docId:)` every burst, resetting the counter to 0 before it can reach 100 — but the **non-burst callers that use a bare `try await opStore.append(op)` and don't follow with a seal** do let the interval seal fire on their own 100th op: annotations (`Document+Annotations.swift:214,562,772,1241,1295`), rewind markers (`Document+Rewind.swift:131,237,468`), the checkpoint breadcrumb (`CheckpointCapture.swift:73`). Verified concretely at `Document+Annotations.swift:214-218`: on the 100th annotation op with a transient seal failure, the op is durable on disk but `appendToMirror(op)`, `_hasAnyAnnotationOps = true` and the cache invalidations (`:215-218`) never run — the annotation is **invisible in the live mirror until reload**, and a caller-level retry mints a **fresh-opId duplicate** the opId dedupe cannot collapse. — fix-shape: wrap the interval seal at `:629` in do/catch + `os.Logger`, mirroring the three sibling sites (the invariant is already written down at `Document.swift:1189-1191`) — effort: S.

## 3. Per-dimension findings

### 3.1 Signed op log — the crash-window cluster (T-A, A5, A1)
- **F2 [Low] `OpLogDeviceState.shared` is keyed to the AUTHOR's fingerprint alone but holds remembered heads for all four actors' files, so an author-key re-mint discards the other three actors' heads too.** `init(fileURL:identity:)` discards the whole state file on an identity mismatch (`OpLogDeviceState.swift:104,109-121,124-126`); the `heads` dict keys carry no actor. A partial restore where only `device-key.blob` is unloadable (`DeviceIdentity.swift:160-175`) sends assistant/translator/maugham files all to the "adopt" path at once. Low because the **seal layer backstops it** — `resolveAbsentHead` falls back to `lastTrustedSealIndex` for any actor whose key still exists (`OpLogChain.swift:682-691`), so a forge is still caught and adopt is the documented safe direction. — fix-shape: a per-actor state file, or make the state file identity-agnostic (heads already carry no device) and drop the whole-file discard — effort: M.
- **F3 [Low] An append after a crash-torn tail concatenates onto it with no newline guard.** A crash mid-write can leave the last line without a trailing `0x0A`; the read path recognises it (`OpLogChain.tornTail`), but the next append does `seekToEnd()` + write with no guard that the file ends in a newline (`JSONLAppendStore.swift:381-383` chained, `:416-419` plain), and `applied()` only rewrites when `!quarantined.isEmpty` (`:161`), so a **torn-only** tail is never normalized. The torn fragment and the new line merge into one line that fails element-decode (silently → `diagnostics.skipped`) or breaks the chain and quarantines the writer's post-crash ops. Crash-conditional, writer's-own-data, likely masked by `PendingBuffer` recovery — but it touches the subsystem's own "the words are safe" goal. — fix-shape: before appending, if the coordinated bytes are non-empty and don't end in `0x0A`, write a separating newline (or rewrite-normalize a `tornTail` on open); add a crash-truncate→append→reload regression test — effort: S.
- **F4 [Low] Constructing an `OpLogStore` eagerly mints the author enclave key, undercutting the "constructing `LocalIdentities.current` mints nothing" laziness contract.** Every store defaults `state: .shared` (`OpLogStore.swift:123`), and `OpLogDeviceState.shared`'s initializer evaluates `DeviceIdentity.author.fingerprint` (`OpLogDeviceState.swift:124-126`), forcing the author key mint the first time any store is built — including on a device that only ever reads (`LocalIdentities.swift:63-67` advertises the laziness). Harmless in practice (the author key is nearly always needed) but the store-level laziness the doc-comment advertises is not achieved. — fix-shape: make `shared`'s identity itself lazy, or document that the store's default state mints author — effort: S.
- **F5 [Low] `LocalIdentities.fingerprints`/`all` are rebuilt (array map + `Set`) on every op-log file classification** — once per globbed file per load (`OpLogStore.swift:420` in `classifyTail`, called per-URL from `loadDiagnosed`; rebuild at `LocalIdentities.swift:129-135`) rather than hoisted once per load. — fix-shape: compute `trusted` once in `loadDiagnosed` and thread it, or memoize on the value — effort: S.

### 3.2 Two loops, two readers (T-B)
- **F6 [Low] A round can run PASSLESS if its stage is retired during the async burst-flush hop.** `runRequested` refuses a no-editor round only at press time (`CompilerOrchestrator.swift:692`), but `beginRun` re-resolves `roundEditor` after the `prepareForRun` hop (`:796`) with no nil-guard. If the writer retires/unassigns the piece's pass during the sub-second flush, the round proceeds with `passId=nil`, `round=nil`, `editorName="Claude"`, `passSection(nil)` emitting no editor role frame, notes minted unstamped, a `RoundRecord(passId:nil)` filed into the round slot. Not corruption — the delta marker is untouched and `standingRound`/`latestRound`/`previousRound` filter by exact `passId`, so it can't poison a later real round — but it silently breaks `runRequested`'s stated invariant and puts a frameless "Claude" round on the cockpit until superseded. — fix-shape: re-check `roundPass != nil` in `beginRun` and abandon with `.noEditor` — effort: S.
- **F7 [Low] `RunState` is kind-less; both loop surfaces match it on `docId` alone.** `.running(docId:checking:)`/`.nothingNew(docId:at:)` carry no `RunKind` (`CompilerOrchestrator.swift:36-41`); the Author pane (`DiagnosticsPane.swift:529,534`) and Review cockpit (`ReviewRoundCockpit.swift:201`) both switch `where runDocId == docId`. Start a check in Author, switch to Review mid-run (same doc), and the cockpit shows the round as "running" (Run disabled, borrowed counts) over a check it never started — symmetrically for `.nothingNew`. Transient UI only; **all standing state is correctly split per-kind**. It is the one place the milestone's two-loop separation leaks. — fix-shape: carry `RunKind` in `.running`/`.nothingNew` and have each surface match its own loop's kind — effort: M.

### 3.3 Translation pipeline (T-C)
- **F8 [Low] A cancel/shutdown landing inside `mintDeclinedQueries` orphans annotations already minted.** The mint has side-effects (real `.query`/`.craftNote` annotations created), then the generation check fires and the leg is recorded `.cancelled` with `applyFixOutcomes` skipped (`TranslationPipeline.swift:358-369`) — the minted queries sit in the queue but the round record never links them. — fix-shape: apply outcomes for whatever the mint returned before honouring the cancel, or mint after the generation check — effort: M.
- **F9 [Low] An empty-string translation is accepted as a real (non-tombstone) record.** `text: ... (e.text ?? "")` (`TranslationWritePipeline.swift:138`) writes an empty translated paragraph, marks it FRESH (a record with the current `sourceHash`), and emits at most an advisory `ConstructSkeleton` construct-parity warning — never a rejection — so a blank paragraph can be published as "translated." In a subsystem obsessive about the words being safe, this is the softest treatment of a bad model output on the path. — fix-shape: treat an empty non-verbatim `text` as a rejection or a hard warning — effort: S.
- **F10 [Low] `Ruling.directiveText` degrades a malformed paragraph id silently instead of loudly.** It composes `"¶<id>: <instruction>"` sanitizing only the instruction, never validating `paragraphId` (`RulingShapes.swift:43-45`); if the id is ever not a clean 4-char `ParagraphID`-alphabet id, `directivePattern` fails to match on read-back and the ruling degrades to a plain edition-brief ruling — the writer's paragraph-scoped decision goes dormant with nothing red. Not exploitable today (directive ids flow from records parsed against `briefedParagraphIds`), but it is the one place this loud-refusal subsystem quietly reclassifies. — fix-shape: assert the 4-char alphabet in `directiveText`, or reject a malformed id loudly — effort: S.
- **F11 [Low] `TranslationRoundStore` forms `rounds/<lang>.json` paths from the language tag with no validation of its own**, at the top of `runRound` before any `TranslationWritePipeline.validate` runs (`TranslationRoundStore.swift:37-38`, `TranslationPipeline.swift:268`). Not exploitable — both desk entries validate first (`DepartmentRunState.preflight:354`, `runBook:542`) — but it is the only stage that trusts the tag rather than checking it, and a future refactor of `preflight` that drops its internal validate would silently un-guard the single-doc path. — fix-shape: call `TranslationWritePipeline.validate(language:)` inside the round store's write/read entry points as defense-in-depth — effort: S.

## 6. Refuted / resolved suspicions (so the next audit doesn't re-chase)

- **Signature bypass / seal-line confusion / chain-head spoof / wrong-actor signing in the signed op log** — **REFUTED** (A5 + T-A, verified in code): `verified` is unreachable without this device's enclave private key; `isSealLine` is the sole `{"seal":` recogniser and its one parser caller filters seals before element-decode (no healthy-file-as-damaged DoS); the signer is resolved by the *whole* `op.device` id so no actor's op is signed by another's key; rotation is correctly scoped (`Document.close` rotates only its own actor; the open sweep is the one all-four/`__project__` boundary).
- **A future perf pass batching head-persists would silently convert crashes into set-asides** (A1 surprise) — **REFUTED as a live risk**: the ordering is **test-pinned** at `OpLogDeviceStateTests.swift:248-250` ("the head the whole batch leaves, once, before the bytes go down… nothing here may defer or coalesce it"), so a coalescing change fails a test rather than shipping silently.
- **Cross-surface contract drift from the new subsystems** (phone-v0.1.1 class) — **REFUTED**: the signed op log lives in shared MaughamCore, the phone only ever mints the `.author` key (lazily), TW35/37 have phone twins, and the one phone census that couldn't catch its own defect was retired for a behavioral test — the seam is actively guarded, no registry row owed.
- **CI action SHA fabrication** (recurrence of the PR-#1 class) — **REFUTED**: all 6 pins verified live against tags.
