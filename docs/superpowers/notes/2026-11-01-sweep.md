The three maps agree on the real shape of the new seam: **one grid UI (`FigureGridController`) over two backends with sharply different storage semantics** — `FigureDocument` (per-cell op-logged, drift-guarded merge) and `ResearchTableHost` (whole-CSV file, no op log, whole-file LWW with a conflict backup). ## 3. Findings (file:line + fix-shape + effort)

### S1 [Medium] A Research source table changed by sync or outside Maugham does not refresh figures that pin it — stale values + stale "source-changed" badge until an unrelated fill — **VERIFIED against source**

Silently-unwired-after-refactor. The external-change dispatch arm `.otherProjectFile` (`Maugham/Stores/DocumentStore.swift:2191`) calls `researchFileMayHaveChanged(at:)` but never `invalidateFigureCards()`. `researchFileMayHaveChanged` (`DocumentStore.swift:917`) is guarded `!researchTables.isEmpty` and only pokes **open** grids' `host.fileMayHaveChanged()`; it does not invalidate figure cards. All six `invalidateFigureCards()` call sites are on the figure-stream / local-write / birth paths (`DocumentStore+Figures.swift:199,277,317`, `ResearchTableHost.swift:383`, `FigureBirthUndo.swift:129`) — **none** on the external/synced Research-content edge. The three card owners watch `manifest.research` by array identity, and a content-only CSV change leaves that array untouched, so no watch fires. Net: a figure pinning a Research table shows stale computed/pinned values and a stale source-changed badge after another device (or MCP writing into `research/`) updates the source, until some unrelated fill — while the *local*-edit path invalidates correctly, so the behaviour is also inconsistent with itself. — `Maugham/Stores/DocumentStore.swift:2191` + `:917`; `Maugham/Editor/ResearchTableHost.swift:383` — fix-shape: have `researchFileMayHaveChanged(at:)` (and/or `reloadUnlessEdited`) call `invalidateFigureCards()` on any external Research-asset change; add a test that a synced CSV change re-fills a pinning figure's card — effort: **S**.

### S2 [Low] An open Research-table grid reloaded from an outside change repaints itself but never invalidates figure cards — same root cause, distinct symptom — **VERIFIED**

Even when a grid *is* open on the changed table, `fileMayHaveChanged()` → `reloadUnlessEdited()` repaints the host's own grid but calls no `invalidateFigureCards()`, so a figure pinning that table shows stale values while both table and figure are on screen. — `Maugham/Editor/ResearchTableHost.swift:215-257` — fix-shape: invalidate figure cards at the end of a successful reload (covered by S1's fix) — effort: **S**.

### S3 [Low] `TableCSV.detectSeparator` toggles quote-state on every `"`, while `rows()` only opens a quoted field at a field boundary — a stray quote in line 1 mis-detects the separator and silently corrupts the import — **VERIFIED**

`rows()` opens quoting only when a `"` is the first scalar of a field (`field.isEmpty`, `TableCSV.swift:125`), but `detectSeparator` flips `inQuotes` on *every* `"` (`TableCSV.swift:157`). A first line whose leading field carries a stray/mid-field `"` (e.g. a `;`-delimited European file with an inches mark like `5"` in row 1) desynchronises the two scanners: the separator is mis-detected, the whole file parses as one column, and the wrong decimal locale is applied — silent import corruption with no error. — `Packages/MaughamCore/Sources/MaughamCore/Table/TableCSV.swift:157` (vs `:125`) — fix-shape: make `detectSeparator` track field-start the same way `rows()` does (a `"` opens quoting only at a field boundary), or share one scanner for both — effort: **S**.

### S4 [Low] `ResearchTableHost.write` commits the new `diskHash` before the sidecar write; on sidecar-write failure (logged only) the next reload drops all formats/widths/header — **VERIFIED**

After `performFileSave` succeeds, `diskHash` is set to the new content (`ResearchTableHost.swift:371`), then the sidecar is written in a separate `do/catch` whose failure only logs (`:378-384`). On failure the CSV is on disk with new bytes while the on-disk sidecar still carries the **old** `contentHash`, so the next open's `sidecar.applied` guard (`contentHash == hash(file)`) mismatches and silently drops every format, column width and header-row flag for that table. Reachable only on a sidecar write error (disk / path), hence Low. — `Maugham/Editor/ResearchTableHost.swift:360-384` — fix-shape: on sidecar-write failure surface a notice (as the save-failure path does) or roll `diskHash` back so the mismatch is retried next save — effort: **S**.

### S5 [Medium] `docs/roadmap.md` never recorded the plans-6–8 writer-facing table/figure milestone, and the plan-5 line is now false — **VERIFIED against source**

The Report-foundations roadmap entry (`docs/roadmap.md:299`) still ends "Plan 5 built the table model and formula engine in MaughamCore, **with no writer-facing surface of its own yet**", and there is no entry for plans 6a–8b (2026-10-24 → 2026-10-29), which shipped the **Format ▸ Table** menu, the in-place table grid, Research tables opened in the grid, **Use in Document**, the **Figures** binder section, and **Insert ▸ Existing Figure**. The plan-5 sentence is now false and a whole writer-facing milestone is unrecorded — the recurring `•→✓`/sibling-doc drift (CLAUDE.md rule 10), one milestone behind again. — `docs/roadmap.md:299` — fix-shape: reword the plan-5 sentence and add a "Report figures & tables (plans 6–8)" ✓ entry flagged *merged, unreleased* (same schema-10 release freeze) — effort: **S**.

### S6 [Low] `docs/product.md` Reports paragraph describes tables only as Pandoc Markdown — no mention of the table grid, figures, Research tables or Use in Document — `docs/product.md:35` — fix-shape: add one sentence on the writer-facing table grid and figures — effort: **S**.
