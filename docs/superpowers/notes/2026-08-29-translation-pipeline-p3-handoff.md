## Carried forward (decisions for later plans, not defects)

- **The declined "reply" lives in the query BODY** under the translator's name. The annotation layer has no reply primitive and a new `OpKind` is a wire change the phone would have to decode; the structured form (reason + annotationId) is on the round record. If a reply primitive ever exists, `declinedBody` is the one site to change.
- **Leg 4 skips when leg 3 wrote nothing** (`nothingChangedReason`) — "nothing fresh to read" read as "nothing new since leg 2". A constant to revisit if the author wants the second cold read regardless.
- **A failed round stops a book queue** (as a cancel does). The next chapter would meet the same session; the author should see this one first.
- `languageQueries` (the translator gather's open/answered-query read) still reads the OPEN document only; in a book queue a closed chapter's prior queries are not briefed. `mint` and `mintDeclined` DO reach closed documents.
- A cancel landing inside `mintDeclinedQueries` records the leg cancelled and skips `applyFixOutcomes` — queries that were minted are absent from the record (narrow; the annotations exist).
- Round-number collision is possible only if a run starts the instant after a `shutdown()` while the old round is still resolving a cold leg (`nextNumber` is taken at start, advanced at `append`). Unreachable until Plan 4 surfaces Run; derived data.
- `translation_status` decodes the per-language ledger once per row (docs × languages); hoist a per-language cache if a book ever makes it slow.
- `authorLanguage` re-reads `config.json` per gather (2 per round); fold into a cold-gather `RoundContext` peer when the file is next touched.
- Cross-object cancel (`pipeline.cancel()` → `TranslatorOrchestrator.cancel()` → `.cancelled` summary → `translatorRunEnded`) is pinned in each object's own suite and by the census token, not by one test spanning both — a Plan 4 candidate once Run is surfaced.

## Rulings made during execution (for Denver to rework if wrong)

1. **`applyFixOutcomes` scopes to the leg's briefed notes** (the plan's code had the parameter unused) — strictly narrower; costs nothing if wrong.
2. **`live` is run-scoped via `runToken`** (review finding, not in the plan) — closes a stuck desk after shutdown+restart; if wrong, Cancel during a cold leg after a restart would be the symptom.
3. **`runToken` beside `generation`** for the status/queue reset — both alternatives falsified by tests; if wrong, a status stuck `.running` after a cancel.
4. **`shutdown()` resumes `pending` as `.abandoned`**, not a fabricated summary — unobservable today (the generation guard precedes the switch).
5. **The `.fix` gather answers an empty work-list, not nil**, when no noted paragraph is briefable — so the leg is a recorded skip rather than an abandon.
6. **A verbatim paragraph reaches the blind reader as its own text** — it is the edition's text, not a gap; pinned by `test_aVerbatimParagraphReachesTheReaderAsTheEditionsOwnText`.
7. **`ReloadKey` carries the pipeline's language only**, never the leg — a leg-keyed re-derive re-walked the whole book seven times a round.

## Process lessons from this run

- **Plan defects the executors caught** (all fixture/test-level; no production code diverged from the plan except by ruling): `try XCTUnwrap(await …)` again (P2's lesson, repeated in the plan); a `calls.count == 5` that forgot the three fix legs (7 per chapter); a `HeldWorld` that short-circuited the base closures; a 30 ms sleep where a predicate wait belonged; census tokens that could not match a `[weak pipeline]` capture; a `harness.doc.replaceParagraph` verb that does not exist (the stale-record route through `TranslationStore.append` was right).

- **Reviewer reports truncate around ~4–5 KB in the notification channel** — three of nine needed a follow-up message for their verdict. Ask reviewers for reports under ~60–80 lines, Issues before Strengths.
- **The gate ran concurrently with the whole-branch review** (both read-only) and its result stood because the fix wave was docs+small edits that a second gate re-verified; running gate 1 early saved a full gate's wall time.
