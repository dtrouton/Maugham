## Your first task is a spike, not a plan

**Do not write the implementation plan yet.** §7A.7 calls for a timeboxed spike first, and planning eight tasks of Canvas-drawing before running it would be planning past the decision.

The spec recommends: one SwiftUI `Canvas` renders every node, with exactly one real `NSTextView` mounted on the scrap being edited. The runner-up — `NSScrollView` with a document view and real subviews — gets crisp text, real editing and correct zoom-to-cursor (`setMagnification(_:centeredAt:)`) *for free*, and is held second only by three unresolved risks. **If those turn out to be fixed, the runner-up may beat the recommendation on effort outright.**

The spike must answer, in a throwaway branch:

1. **Does `NSScrollView` magnification still fail to translate coordinates to hosted SwiftUI content?** Reported in 2021 (`dmytro-anokhin/advanced-scrollview`), **never verified on macOS 15**. This is the single cheapest experiment available and it decides the architecture.
2. **Do `_NSTiledLayer` seams appear at ~1.5× zoom?** Apple Forums 663536, open since 2020, unresolved. A hazard for *any* magnification route, so test it whichever way you lean.
3. **Does the TextKit-shared-layout approach actually hold?** Draw a text scrap through the same `NSTextStorage`/`NSTextLayoutManager` used for editing, mount the editor on focus, and check the glyph origins are identical. §7A.2 names this as the biggest risk in the whole design: if drawn and edited layout differ at all, text visibly jumps on *every* focus and blur.

Timebox it. Report which architecture wins and why, then write the plan.

## Constraints that will otherwise be rediscovered the hard way

- **`ProjectWindow.body`'s expression budget is zero.** 28 chained expressions, eleven `ViewModifier` structs that exist solely to buy expressions back, and the ceiling has been hit twice — once building locally and failing Release CI. The canvas should need **no** new top-level modifier: add `case canvas` to `BinderSegment`, add it to `Persona.binderSegments(for:)` for `.plan`, and the compiler lists every switch that needs an arm. This mirrors `.palette`, which is already a centre-column surface reached only through the binder segment. **Do not thread `persona` into the centre column** — it doesn't go there today, and doing so breaks the "coercion happens once, centrally, in `PersonaModifier`; the views only render" contract.
- **`BinderSegmentPicker` requires uniform `Image` children.** A mixed `Image`/`Text` `ForEach` puts a `_ConditionalContent` in the picker whose branch is cached per position while `NSSegmentedControl` updates in place — that shipped a palette icon glued to the Research segment and made the palette wall unreachable (2026-07-25 smoke, defect C). A fourth Plan icon must also fit the width budget: the icon set measures 87–145pt against a 240pt column.
- **There is no spatial view anywhere in this codebase.** No `GeometryReader` in `Maugham/`, no `Canvas`, no `scaleEffect`, no magnification, exactly one `DragGesture` (a horizontal scrubber). You are establishing the pattern. Establish a boring one.
- **There is no image cache and no real downsampling.** The palette wall's `downscaled` helper decodes the full image then redraws it, so memory peaks at original size. The canvas is the first surface with an unbounded image count: it needs a `CGImageSource` thumbnail path and a bounded cache, keyed by **path, not id** (tripwire 22).
- **`DropClassification` is the shared external-drop entry point.** Browser image drags carry rendered bitmaps rather than file URLs, so `.dropDestination(for: URL.self)` silently rejects them. Don't hand-roll it.
- **MaughamCore tests do not run in the `Maugham` scheme.** If you touch `Packages/MaughamCore/`, you must also run `swift test --package-path Packages/MaughamCore` — nothing else will, including CI.
- **Run `xcodebuild` in the foreground** with a long timeout. Backgrounding it and polling burned two turns last session, and two concurrent invocations contend for one DerivedData.
- **Release build after anything touching views.** The Release type-checker budget is stricter than Debug; that distinction is what caught the last failure.
