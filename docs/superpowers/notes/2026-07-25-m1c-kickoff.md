## Build 1C-a before touching the others

This is the most important instruction in this note.

1C-b, 1C-c and 1C-d were all written against 1C-a's API **before it existed**. Nearly every defect found across four review rounds and five fix rounds was drift against imaginary Swift — a renamed parameter, a wrong arity, a duplicated type, a method split three ways that its owner says not to split. Three separate times, one plan would have deleted a day's work from another.

Once 1C-a is built, `grep` over real code is authoritative and the compiler rejects a wrong symbol on sight. **So: execute 1C-a, then re-derive b, c and d against the built code.** Expect them to shrink — a lot of their bulk restates an API that will then be greppable. Do not "just fix" them on paper first.

Use `superpowers:subagent-driven-development`. On the last slice its whole-branch review caught a Critical that eight per-task reviews missed, and the writer's own smoke caught three more that a green 2,646-test suite could not see. Budget for both.

## Constraints that will otherwise be rediscovered the hard way

- **`ProjectWindow.body`'s expression budget is zero.** 28 chained expressions on the outer `Group`, 6 more on the inner `NavigationSplitView` branch, and eleven extracted `ViewModifier`s that exist solely to buy expressions back. The ceiling has been hit twice, once passing Debug and failing Release CI. **Count per type-check unit** — a buy-back inside the `if let store` branch does not pay for an addition to the outer chain.
- **`mountedEditorNodeID` and `visibleEditorNodeID` are different things** — the editor *existing* versus the editor *being the visible text*. This distinction has been merged **four times**, in both directions, producing jumping text and lost keystrokes. Both names are real; do not globally substitute. A census test guards it.
- **There is no spatial view anywhere in this codebase** — no `GeometryReader` in `Maugham/`, no `Canvas`, no `scaleEffect`, one `DragGesture` (a horizontal scrubber). You are establishing the pattern.
- **There is no image cache and no real downsampling.** The palette wall decodes at full size then redraws. 1C-d builds the real thing; 1C-a renders items as placeholders.
- **MaughamCore tests do not run in the `Maugham` scheme.** If you touch `Packages/MaughamCore/`, run `swift test --package-path Packages/MaughamCore` — nothing else will, including CI. A doc-only `CLAUDE.md` edit broke `DocSyncTests` today for exactly this reason: docs claims are code claims here.
- **Run `xcodebuild` in the foreground** with a long timeout; backgrounding and polling burns turns, and two concurrent invocations contend for one DerivedData.
- **Release build after anything touching views.** Debug passing is not evidence.
- `./gen.sh` after adding files; `-only-testing` takes `MaughamTests/<ClassName>`, never a folder path (a folder path runs zero tests and reports success); never commit `Maugham.xcodeproj/`.
