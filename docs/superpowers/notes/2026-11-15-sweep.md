## 2. Synthesis over the maps (the sweep payoff)

**The collision: two definitions of "palette card".**
- The tracer's duplication entry listed the palette-card predicate twice: by path prefix in `ResearchTextRole.of`, and role-first in `PaletteLookup.paletteCards`.
- Set against the prior audits' knowledge that the palette group is role-first precisely so it survives a rename (`test_paletteGroup_survivesRename_andStampsLegacy`), that gives **N1**.
- The new `update_note` (ADR 0034: notes yes, cards never) inherits the path-prefix definition. So the rename that the wall tolerates turns cards into notes for the assistant.
- This is a **cross-surface contract drift**: each definition is right on its own surface.

**The second collision: the door versus the mover's in-between state.**
- Both opus agents found, from opposite directions, that the door re-reads the manifest path at write time and treats a missing file as "write afresh".
- Both found that the move, rename and trash paths change the manifest only after an awaited file move.
- So a debounced timer save that lands in the gap recreates a file at the old path (**T2**). Independent rediscovery raised confidence.

**The third collision: the off-main autosave versus the fire-and-forget quit.**
- The delta hunter's surprise ("⌘Q never awaits `DocumentStore.close`") was combined with e166f6b's new suspension points between the pending-mirror flush and the `.md` write, and probed.
- The probe found no lost text: the op log and pending mirror are unchanged. It did find a regression in step-lock: a false "diverged" backup (**Q1**).

**The fourth collision: two versions of one rule (again).**
- The note door re-implements the table door's check-then-write. #138's R3 gap (an outside change is overwritten between the read and the write) now has a twin. It is recorded on #138, and one shared fix is suggested.
- This is the 11-08 note's recurring lesson: a parity issue across two implementations of one rule.

**Merit-drops (recorded so the next sweep doesn't re-litigate them):**
- **`ResearchNoteRecord` is one file per note that every device rewrites** (tripwire-17 spirit). It is a label, not a signature, and every reader checks `contentHash`, so a stale or conflicting record only shows as unmarked. This is the same precedent as the table sidecar.
- **The v0.45.0 release notes say keystrokes take "about a third less time"; the measured gain is 21–29%.** The release is tagged, and the claim is approximate but in the right direction.
- **The CI gate accepts a green run on any ref for the tagged SHA.** The same SHA means the same code, which is the gate's intent.
- **`Promotion.filings.json:448` cites a removed test.** It sits inside a dated historical amendment that `:455` supersedes.
- **`settle(itemId)` flushes every note and can loop under continuous typing.** It terminates on any pause. This is liveness only, with no data effect.
- **A BOM'd note loses its BOM on the next keystroke and keeps one extra version.** Cosmetic, and recoverable.
- **The Versions list doesn't refresh when another device's versions arrive** until a local bump. A stale listing, nothing lost.
- **`update_note` re-checks only `takes` after the awaited keep**, so an item that becomes a card mid-save is still written. It needs a concurrent manifest re-role during one save. N1's fix (a role-first check) covers the practical case.
- **⌘Q never awaits `DocumentStore.close()`.** This is pre-existing and deliberate (ruling N1, `ProjectWindow.swift:426-440`), and the probe refuted any loss of op-log text or word count. Only Q1's step-lock regression is scheduled.
