# Maugham 0.3.2

_Released 2026-05-25_

Lifecycle + layout stabilization across project types.

## Fixes

- **Collection piece rename now reliably updates the file on disk.** Same close-before-move pattern as v0.3.1 for Novel docs, extended to the `renamePiece` path that moves the enclosing piece folder.
- **Research note rename + delete no longer leave phantom files.** The 750ms autosave on a research note would otherwise re-create the file at its old path after the move. Now flushes pending saves before the FS operation.
- **Collection piece reorder is autosave-safe.** Moving a piece up/down in the list renumbers folders on disk; if a document inside was open, its autosave used to race the move. Now closes the doc first.
- **Binder reorder is autosave-safe across affected siblings.** When inserting a doc at position N shifts later siblings down (renumbering), every affected open doc's autosave used to race. `DocumentStore.executeRenamePlan` now closes all of them in one pass.
- **Inline rename TextField reliably focuses on new Research notes and Collection pieces.** Same fix that landed for Novel docs in v0.3.1, now extended to `ResearchRow` and `PieceRow`. Adds a brief deferral plus `.onChange` so both "add new" and "context-menu Rename" paths land the focus claim.
- **Empty Collection no longer floats its toolbars to the middle of the window.** The Pieces/Research segmented picker and the right-pane segment picker now stay pinned to the top regardless of whether the project has content.
- **Empty Novel binder can now create the first document.** Previously the context menu was attached to each row, so an empty binder had no right-click affordance. Added a binder-level context menu plus a button-driven empty state with "New Document" and "New Group" actions.
- **Other empty-state panes (research preview, trash, image-unavailable, inspectors) now fill their containers** rather than collapsing and floating their parent's toolbar.
- **"Check for Updates" fetches fresh from GitHub** — was already in v0.3.1 but worth restating since the prior cycle (v0.3.0) had this URLCache staleness bug. From v0.3.1 onward, mid-session checks see new releases as soon as CI publishes them.

## Internal

Three recurring bug patterns are now documented as CLAUDE.md tripwires (#14 close-before-FS-surgery, #15 empty-state fill-frame, #16 inline-rename focus claim) with matching guidance in `Maugham/Views/AREA.md`. Future view + store work should hit these as canonical patterns rather than rediscovering them.

## Known issues

- First open of each downloaded `.dmg` still requires right-click → Open in Privacy & Security. Will go away when we flip to signed + notarized builds.
