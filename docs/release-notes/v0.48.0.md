# Maugham 0.48.0

_Released 2026-11-17_

A hardening release: Replace works across documents again, the assistant stops leaving empty notes behind, and Research notes keep their place when you reorder or rename the pieces of a collection. Mac only.

## Fixes

- **Find & Replace**
  - Clicking Replace on a match in another document, after an earlier Replace refreshed the results, now works. It no longer says "That match has changed" when it hasn't. A document that an earlier Replace did change still refuses, as before.
  - Replace in a Research note changes nothing if the note's file changed while Replace was running. Replace All lists such a note: "Left as it was — “X” changed while Replace was running. Search again."
- **Research notes and groups**
  - A new note lands in its group's own folder, even after the group was renamed. It used to follow the group's new title.
  - After a note is renamed or moved, if Maugham could not update the links to its pictures, it now says so.
  - Reordering or renaming a piece of a collection no longer loses track of the notes inside a Research group under that piece. They no longer go missing or fail to save. A note being saved at that moment is kept as a copy in the project's `.maugham/conflicts` folder, not as a stray file in the old folder.
- **The assistant**
  - If `add_note`, an Inbox promotion or a kept letter cannot save the new note's text, the empty note is removed again. If its file got text from outside Maugham in the meantime, the note is kept, in Research or in the Trash, and the message says where.
  - A malformed `set_publish_config` change is refused with a message. It used to crash Maugham's connection to the assistant.
  - `list_publish_files` says so when it cannot read the publish folder. It used to show the folder as empty.
- **Opening and closing**
  - Leaving a chapter and coming straight back can no longer delete the newer copy's crash-recovery file.

## Known issues

- A recovery file that cannot be read at all is reported again the next time you open the chapter.
- In a collection, **Tidy All Filenames** asks you to confirm, then does nothing and says nothing. Your files are left as they were.
- After a quit there is no window to show a "couldn't save" notice for a Research table. Look in the project's `.maugham/conflicts` folder for a file ending `-unsaved-` and a date.
- Restoring a version of a note or card from before it was renamed brings back links to its old picture folder, so those pictures don't show.
