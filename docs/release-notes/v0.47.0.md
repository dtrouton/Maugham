# Maugham 0.47.0

_Released 2026-11-16_

Research notes, palette cards and the Trash stop losing or overwriting work without saying so, and Replace changes the match you clicked or nothing. Pairs with MaughamPhone 0.17.0, which carries the phone's half of 0.46.0's suggestion fix.

## What's new

- **An open note or card notices a change made outside Maugham.** If the file changes on another device or in another app, the note reloads and a notice says so. If you had typed something unsaved, your edit is saved, the outside text is kept in the note's Versions, and the notice tells you.
- **The assistant never writes a palette card.** `update_note` refuses a card even after you rename the Palette group, and `add_note` can't add to the Palette. Cards are yours.
- **What the assistant writes is marked as the assistant's.** A note made by `add_note`, an Inbox entry the assistant promotes, and a kept letter each show "Written by assistant" in Versions once you edit them.

## Fixes

- **Find & Replace**
  - Replace changes the match you clicked. If the text changed after the search (you typed, or the file changed), it changes nothing and says "That match has changed. Search again."
  - Clicking Replace twice quickly, or Replace straight after Replace All, can no longer change the next occurrence along.
  - Replace All skips a note that no longer contains what you searched for.
- **Deleting in Research**
  - Deleting several items at once is one gesture: ⌘⌥Z brings them all back, or none.
  - A note whose file has already gone from disk can now be deleted.
  - If a delete stops partway, what was moved to the Trash is saved and can be undone, and the message says what was deleted and what wasn't.
- **Moving and renaming notes**
  - A save that arrives while a note is being moved, renamed or deleted no longer leaves a stray copy at the old place. Your text is kept as a copy in the project's `.maugham/conflicts` folder, and a notice names the file.
  - A renamed note's pictures keep showing even when the project's index couldn't be saved at that moment.
- **Versions**
  - Restoring the oldest version of a note or table no longer removes that version.
  - A new palette card no longer keeps its blank template as a version.
  - Permanently deleting a note or table also removes its leftover bookkeeping files.
- **Opening and closing**
  - Maugham no longer files a "diverged" copy of a chapter when the only difference is its own unfinished save.
  - Closing a document cleanly leaves no recovery file behind.

## Known issues

- After Replace, clicking a match in a different document can say "That match has changed" when it hasn't. Search again and click it.
- If the assistant's `add_note` fails to save its text, an empty note is left in Research. Delete it.
- Reordering, renaming or deleting a piece of a collection while the assistant is writing a note inside that piece can leave a stray copy of the note in the old folder.
- After a quit there is no window to show a "couldn't save" notice for a Research table. Look in the project's `.maugham/conflicts` folder for a file ending `-unsaved-` and a date.
- Restoring a version of a note or card from before it was renamed brings back links to its old picture folder, so those pictures don't show.
