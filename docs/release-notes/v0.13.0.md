# Maugham 0.13.0

_Released 2026-07-02_

A multi-window correctness release. If you work with more than one project
window open — a novel here, a screenplay there — this release makes every
command and every update land on exactly the window it belongs to, and
nowhere else.

## Fixes

- **⌘⌥I toggles the inspector in one window, not all of them.** With two
  project windows open, Toggle Inspector flipped both. Now only the window
  you're working in responds — and the same is true for Focus Mode (⌘\),
  Research Preview (⌘⇧P), Find in Project (⌘⌥F), the right-pane segment
  shortcuts (⌘⌥1/2/3/A), Project Settings, and the rest of the menu commands.
- **Background windows no longer react to another project's clicks.** Clicking
  a scene, a search result, or a History/Annotations/Tasks jump in one window
  could move the cursor or flip the selection in every other open window.
  Each of those now reaches only the window it was meant for.
- **The History pane refreshes only for its own project.** A checkpoint in one
  project no longer causes every open window's History pane to reload.
- **Clicking a chapter in Project Statistics now works.** Selecting a row in
  the statistics window's "Words by chapter" list now brings its project
  window forward and navigates to that chapter — previously the click did
  nothing. For screenplays it lands on the Scenes navigator (screenplays have
  no chapter list), with all your sluglines intact.
- **Closed windows do no ghost work.** After closing a large project's window,
  editing in another window could still trigger invisible work attributed to
  the closed one (an occasional pause on big screenplays). Closed windows now
  receive nothing.

## Under the hood

- Every internal window event now declares who it's for at the moment it's
  sent — key window, a specific project, or genuinely everyone — instead of
  broadcasting to all windows and hoping each receiver filters correctly.
  This class of bug has shipped three times before; it is now structurally
  prevented, and a CI guard keeps it that way.
- The full manuscript record-keeping, editing, and publishing test suites
  (1,900+ tests) pass on Mac and iPhone.

## Known issues

- macOS keeps a closed window's view structures in memory until the app
  quits (a SwiftUI framework behavior — bounded memory, no ongoing work; we
  investigated and documented it this release). Quitting the app releases
  everything, as always.
- Project Statistics still shows screenplays as a single "chapter" row;
  scene-shaped statistics (per-scene page lengths, page-count progress) are
  on the roadmap.
