# Maugham 0.3.0

_Released 2026-05-25_

The Tasks milestone — your todos finally have a home in Maugham.

## What's new

- **Tasks pane (⌘⌥5).** A unified surface for todos across your manuscript, combining three capture paths: inline `- [ ]` markdown checkboxes in any `.md`, Fountain `[[todo: …]]` / `[[done: …]]` boneyards in any `.fountain` (or in prose), and pane-created tasks via the `+` button. Document / Project scope filter, status filter (Open / Done / Archived), drag-to-reorder, single-level parent/child nesting.
- **Mid-paragraph inline todos.** `Anna walked [[todo: tighten this]] and saw the cat.` is one paragraph with one inline task. The brackets terminate the body; you don't have to break the prose.
- **Per-task inline anchors.** Each task gets a stable identifier (`<!--t-XXXXXX-->`) persisted to the `.md`, invisible in the editor. Identity survives every operation: merge / split / rename / reorder / cross-paragraph cut-paste. Drag-ordering, parent nesting, and history all stay with the task wherever you move it.
- **Distinct todo styling in the editor.** Task body text gets a subtle color shift so you can see at a glance where you're inside a task versus regular prose. Done tasks (`- [x]`, `[[done: …]]`) get strikethrough, matching the pane's visual treatment.
- **Archive lifecycle.** Mark a task done with a checkbox click (in pane or editor). Archive via the kebab menu — Maugham tidies the manuscript by removing the line (or splicing the bracketed segment), and the task moves to the Archived filter. Manual line deletion auto-archives so you keep an audit trail. Bulk "Archive all done" in the pane kebab for one-shot cleanup.
- **MCP read-only access.** `list_tasks` and `get_task` let Claude Desktop see your todos as context. No write tools — your task list is yours.
- **Cleaner pane icons.** Annotations (chat-bubble) and Tasks (checked-list) now read as visually distinct things.

## Architecture

Anchored tasks are the first instance of the cross-area pattern recorded in [ADR 0011](https://github.com/dtrouton/Maugham/blob/main/docs/adr/0011-tasks-first-class-with-inline-anchors.md): for any manuscript-derived data with per-item lifecycle, mint inline anchors persisted in the source rather than deriving identity from position. Paragraphs were the precedent; tasks are the next instance.

## Known issues

- Jumping to a Fountain inline task lands at paragraph start, not exactly on the `[[todo: …]]` position. Acceptable for V1; planned refinement threads an intra-paragraph offset through navigation.
- Cross-paragraph text cut-paste between different paragraph_ids preserves anchors when cursor movement signals the intent (V2 alignment). The "delete here, retype the same body later" pattern reads as a new task.
- First open of each downloaded `.dmg` still requires right-click → Open in Privacy & Security. Will go away when we flip to signed + notarized builds.
