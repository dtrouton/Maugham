# Maugham 0.40.0

_Released 2026-09-19_

**This release needs macOS 27.** It is the first one that does, and if you are
still on macOS 26 nothing will change for you: Maugham will keep running the
version you have, and when it checks for updates it will tell you plainly that
0.40.0 needs macOS 27 rather than downloading something your Mac cannot open.
You will not find a broken app in your Applications folder. Upgrade macOS when
you are ready, and Maugham will pick this up at the next check.

The reason is not a new feature — it is that Maugham is built and tested on one
Mac and one toolchain, and that Mac is on macOS 27. Keeping the floor below the
machine the app is written on means every window, column and control is
measured somewhere nobody ever sees it, which is how a layout change can ship
without anyone noticing. macOS 27 moved several of those under us, which is
what this release is mostly about.

## What's new

- **The chevrons on the Research and Palette sections moved to the left**, in
  front of their titles, the way Finder and Xcode put them. They used to sit on
  the right, hard against the scrollbar and hard to hit.
- **The updater refuses a build this Mac cannot run.** A newer Maugham that
  needs a newer macOS is no longer offered: nothing is downloaded, and the
  update window says in one sentence what it needs. Releases before this one
  carry no such requirement and are offered exactly as before.

## Fixes

- **A side column keeps the width you dragged it to.** On macOS 27 a pane whose
  contents wanted more room could take the right column and hold it at its own
  width, ignoring the width you set. The column now frames what it shows: a
  pane that wants more is fitted or scrolls inside it, and never widens it.

## Known issues

- None specific to this release. If you are on macOS 26, see the top of this
  file — this is not a bug and Maugham will say so when you check for updates.
