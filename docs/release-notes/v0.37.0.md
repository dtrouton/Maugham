# Maugham 0.37.0

_Released 2026-09-08_

The signed op log. Every line Maugham writes to a manuscript's history is
now chained to the line before it and sealed by a key that lives in this
Mac's Secure Enclave and never leaves it. A line written by anything that is
not Maugham — an agent with a shell, a tool that rewrites a file — breaks
the chain, is set aside in a backup, and is never applied; History says so
in one sentence. Nothing is encrypted, nothing is locked, and no book ever
refuses to open: this is provenance, not a lock. (ADR 0032; spec
`2026-09-05-signed-op-log-design.md`, P1 and the actors slice.)

## What's new

- **Every device has a key, and four actors write with it.** The Mac signs
  as the **author** for everything you do (the editor, statements,
  checkpoints, wiki-rename, search-and-replace), as the **assistant** for
  anything that arrives through MCP (Claude's comments, queries and
  suggestions, whether the document is open or not), as the **translator**
  for the translation pipeline and `write_translation`, and as **Maugham**
  itself for its own housekeeping (task-priority rebalance). Each actor is
  its own key and its own file under `.maugham/ops/`, so the role is in the
  signature rather than a label anyone could forge. A key exists from the
  first time its actor writes.
- **History tells you what it knows.** *Part of this document's history was
  written before this book was signed* for a project that predates this
  release; *N changes from another device are applied as unsigned
  history* for a device this Mac does not yet trust; *N changes were
  written to this document by something that is not Maugham; kept in
  backup, not applied* when the chain was broken. The set-aside bytes live
  under `.maugham/conflicts/quarantined-ops/` and are never returned to
  the live history. Nothing goes in the tree, the footer or a badge.
- **Sealed segments carry a signature** beside their digest, and a segment
  once verified is remembered by content and never walked again.
- **The inbox and the phone sign too.** Every inbox row is chained and
  every capture sealed; the phone's annotations and captures are signed by
  its own key. A tail torn by a crash or a half-synced file is read as a
  crash, not as a forgery.
- **The device's identity is its key.** Two Macs with the same name can no
  longer collide on one history file, and a restored Mac is a new device
  to its own past.

## Fixes

- A task-priority rebalance used to write into one shared file that every
  Mac appended to; under the chain that file would have been truncated by
  each Mac in turn. Rebalance ops are now Maugham's own and signed.
- The bootstrap op of a freshly imported document is signed by the same
  keys the document is later read with, so it no longer reads as legacy
  forever.
- A translation batch whose seal fails to write is still a successful
  write; the records were durable.

## Known issues

- Your existing history files (the ones named after this Mac's hostname)
  are read as another device's unsigned history from now on, applied in
  full and never appended to again. Each document gains one new file
  beside them on the first keystroke.
- Verifying a 50,000-line history adds roughly 55–83 ms of chain work on
  a cold open in a debug measurement; the parse itself is seconds at that
  size and dominates. A performance pass follows this release.
- The project's task stream (`__project__`) seals but does not yet rotate
  into segments, so a very long-lived project pays a growing verify cost
  on each task toggle.
- There is no registry of people yet: every device is its own identity,
  and a second Mac's lines are unsigned history until P2 adds admission.
