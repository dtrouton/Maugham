# Maugham 0.32.1

_Released 2026-08-27_

A bug-fix release from the first Serbian preview of a screenplay: a
translated edition's sluglines were being set as character cues, and
`read_preview_page` could not see a preview that was right there on disk.

## Fixes

- **A translation never changes a block's role.** A translated screenplay
  edition re-parsed its translated text as Fountain and trusted the
  result — so every Cyrillic slugline (`ЕКСТ. ТЕРАСА - ДАН`, which matches
  none of INT./EXT.) was emitted as a character cue at the cue indent, with
  Overfull \hbox warnings to match. The source paragraph's element is now
  authoritative: Maugham carries it across with Fountain's own forced
  markers where the re-parse would disagree, and proves each marker took.
  This closes the same hole for an unforced `CUT TO:` in any script, for a
  language whose cue casing differs, and for any language that translates
  INT/EXT. Translators never need to write a marker themselves.
- **The fountain drift warning reports only drift the output carries.** It
  reads the same structure-preserved text the emitter renders, so a warning
  now means a line the fix could not align (a translation with a different
  line count than its source, or an element Fountain has no marker for) —
  and it says how many more lines drift, rather than naming the first and
  stopping.
- **`read_preview_page` sees every preview.** Something outside Maugham
  sets the BSD `hidden` flag on files under `.maugham/` in a synced
  Documents folder, and the preview scan honoured that flag — so the tool
  answered "No preview output — run preview_compile first" over a directory
  holding two previews, in any language. Every directory scan in Maugham
  now skips dotfiles by *name* only; `list_publish_files`, the Exports
  footer, publication snapshots and the designer's template walk had the
  same latent hole and are fixed together.

## Under the hood

- No manifest schema change — Mac-only release; MaughamPhone 0.10.0 stays
  current. The phone's op-log and project scans received the same
  name-only dotfile rule (`DotfileScan`, MaughamCore); it ships with the
  next phone release.
- Two tripwire censuses (Mac and phone) keep `.skipsHiddenFiles` out of
  both source trees.

## Known issues

- A translated line whose count differs from its source paragraph still
  takes the re-parse's element; the drift warning names it. Match the
  source paragraph's line count to get the source's structure.
