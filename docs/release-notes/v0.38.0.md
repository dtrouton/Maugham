# Maugham 0.38.0

_Released 2026-09-09_

The reader's own session. A first reader's check on a 450-paragraph
screenplay used to die at a five-minute budget while Claude was still
thinking, and everything it had read was thrown away. Now a check is
stopped only when Claude goes quiet, the session Claude reads in is the
reader's rather than a coding agent's, the notes you pinned travel with the
piece instead of being fetched one by one, and every run says how long it
took. (Spec `2026-09-09-the-readers-own-session-design.md`.)

## What's new

- **A check is stopped for silence, not for taking long.** The old
  per-turn budget killed a run at five minutes whatever it was doing.
  Every Claude session now runs on a silence budget — three minutes with
  nothing arriving from Claude — behind a twenty-minute ceiling that is the
  same for a check, a round, a translation leg and a design round. A
  whole-piece read that needs eight minutes gets them. When a run is
  stopped, the pane says which happened: *Claude went quiet for 3 minutes
  and was stopped*, or *The read passed 20 minutes and was stopped — 31,000
  tokens of thinking so far.*
- **The session is the reader's own.** Claude used to read your piece with
  Claude Code's own coding-agent instructions in front of Maugham's, plus
  whatever hooks, plugins and effort setting your Claude Code account
  carries. Now none of your settings files reach the session, Maugham's
  preamble is the whole system prompt, and the effort level is stated
  explicitly. Your login is untouched. How hard each kind of reader should
  think is not decided by feel: it waits for the evals milestone, and until
  then every session runs at the effort your runs already had.
- **The wait is legible.** While a check or a round runs, the line under
  it counts the minutes and shows what Claude has thought so far —
  *Checking 457 new paragraphs… 2m 10s · thinking (12k tokens)*. Afterwards
  the *Last checked* line and Review's round line say *read in 4m 12s*, and
  hovering them shows the first-word latency, turns, thinking tokens, model,
  effort and cost. A lane's first round, which had no line of its own,
  gets *Read in 4m 12s.*
- **Pinned notes travel with the piece.** A pinned research note under
  about a page is now included in full in the briefing rather than listed
  by title for Claude to fetch — which it did after a whole thinking pass,
  then thought the piece through again. Up to forty thousand characters of
  notes go in, in the order your References shelf shows them; a longer note
  says how to fetch it, and a very long one is never read at all. A pinned
  web link is listed as a link, not advertised as readable. An unchanged
  shelf is not re-sent on a warm session.
- **The briefing says what is not there.** If no craft intent is declared,
  the briefing says so instead of leaving Claude to discover it with a
  tool call; a first reader is told she is deliberately not briefed on the
  lessons ledger; every briefing ends by saying it is the whole read.

## Fixes

- A pinned research item that is a web link was advertised to Claude as
  readable with `read_document`, which failed on every check that tried.
- A run that Claude's own thinking-progress events kept alive was
  classified as hung because only the answer's text counted as activity.

## Known issues

- The per-kind effort table is deliberately unset: every session runs at
  `high`. The evals milestone (spec `2026-09-09-evals-design.md`) decides
  it with measurements.
- Pinned note bodies are read on the main thread at each check, bounded
  at 64 KB each and forty notes; a memo keyed on the file is a follow-up
  (issue #63).
